## Goal

Implement session-scoped channels, the V1 agent identity surface, parent-child run linkage, and provider-agnostic orchestration semantics — turn policies, budgets, stop conditions, moderation hooks, and scheduler limits as a hard V1 quality gate — for concurrent multi-agent collaboration.

## Scope

This plan covers channel creation and lifecycle, the agent attach/detach/config surface, orchestration run creation with full admission enforcement (depth, active-child, scheduler limits, budget, turn policy), durable run-link projection, internal-helper visibility, budget accounting with warning/interrupt thresholds, idle and turn-limit stop conditions, moderation gates, round-robin arbitration with partition pause, and desktop surfaces for concurrent agent work.

## Non-Goals

- Workflow authoring syntax (Plan-017)
- Provider-native subagent APIs beyond normalized adapters (ADR-005)
- Channel-level permission restrictions **on non-direct channels** (V1-deferred per [Spec-016 §Resolved Questions](../specs/016-multi-agent-channels-and-orchestration.md#resolved-questions-and-v1-scope-decisions), narrowed 2026-08-03) — no per-participant ACLs, no agent-scoped read grants, no membership mutation. The `ChannelConfig.audience` member and the `direct` two-human channel kind are the scoped un-deferral and ARE in scope (D-016-21, T2.13)
- Cross-machine `targetNodeId` dispatch ([Spec-024](../specs/024-cross-node-dispatch-and-approval.md)/Plan-027 — D-016-9)
- Conclusion detection (V2 per `Spec-016 §Stop Conditions`)
- Timeline summary-row rendering (Plan-013, Tier 8 — D-016-14; this plan publishes the durable inputs only)
- Realtime/voice channels — reserved behind the R8 capability gate per [Spec-016 §Resolved Questions and V1 Scope Decisions](../specs/016-multi-agent-channels-and-orchestration.md#resolved-questions-and-v1-scope-decisions) (campaign B6, RA-5): the upstream flag is under development, no channel-model change lands until it stabilizes, and this plan schedules no realtime task (the reservation is a gate, not work)

## Data And Storage Changes

- `channels` (user channels only — main is synthesized per D-016-15), `run_links` (single-parent `child_run_id` PRIMARY KEY, `session_id` provenance, `link_type` CHECK, `internal_helper`, `producing_node_id`), `agents` (4-state domain lifecycle), and `session_budgets` (row-canonical limits) per [Local SQLite Schema §Channel and Orchestration Tables](../architecture/schemas/local-sqlite-schema.md#channel-and-orchestration-tables-plan-016).
- `channels`, `run_links`, and `agents` are events-canonical projections (ADR-017 Option B) rebuilt byte-equal on replay; `session_budgets` is row-canonical daemon configuration (the `queue_items` posture — mutated by wire method, never evented).
- Budget **accounting** has no table: the `BudgetAccountant` is an in-memory projection over `usage_telemetry` + `run.*` events, rebuilt on replay (D-016-5); per-run effective ceilings rebuild from the durable `run.queued` `effectiveRunConfig?` field, not by re-merging session defaults that may have changed mid-run.
- No timeline-projection rows: this plan publishes durable events only; Plan-013 derives summary rows at Tier 8 (D-016-14 — the pre-audit "extend timeline projections" step is struck).
- `channels` gains the audience/direct surface additively (2026-08-03 vision reconciliation, D-016-21): `audience` rides the existing typed `ChannelConfig` JSON value, while the channel kind and a `direct` channel's immutable two-human member pair are additive fields on the channel record — **no new table** (`Spec-016 §State And Data Implications`; the pair is fixed-arity, so it needs no membership relation of its own, and the daemon table census is unchanged). Because `channels` is events-canonical (I-016-4), the kind and the pair must ride the `channel.created` payload and not the row alone — a channel whose kind could not be rebuilt from the log would silently widen audience on replay. The [Local SQLite Schema §Channel and Orchestration Tables](../architecture/schemas/local-sqlite-schema.md#channel-and-orchestration-tables-plan-016) DDL mirror **landed in this bundle** (that file is canonical-when-merged with no status lifecycle to pay, so it is taken here rather than routed): `kind` with its two-value CHECK, the `direct_member_a`/`direct_member_b` pair columns, a CHECK binding the pair's presence to the `direct` kind, and a canonical-ordering CHECK (`direct_member_a < direct_member_b`) so a pair has exactly one representation and the events-canonical rebuild is deterministic. T1.3 builds against it.
- The channel-directory publication (D-016-22, 2026-08-11) adds **no daemon-side storage**: no new table, no column, and no acknowledgment ledger — the T2.14 publisher derives every publication and the startup/reconnect re-publication sweep from the durable channel-lifecycle events alone (`Spec-016 §State And Data Implications`), and the directory's backing store is a Plan-002-owned control-plane surface (its Postgres table, ingest mutation, and read path land with Plan-002's own delta — never authored here). `ChannelConfig.turnsPerAgent` (D-016-23) likewise adds no column: it rides the existing `channels.config` JSON value like every other `ChannelConfig` member. The daemon table census is unchanged at five.

(b) **`direct`-kind create validation**: exactly two human members fixed at creation and immutable thereafter (no add, remove, or widen), the authenticated creator one of the two and both members resolving to active human session participants (a create naming a pair the creator is outside, an unknown participant, or a non-human member is refused), server-forced `audience: 'humans-only'` with any conflicting caller-supplied value refused at create, the agent-turn `ChannelConfig` members (`turnPolicy`, `roundRobinOrder`, `moderation`, and — since 2026-08-11, D-016-23 — `turnsPerAgent`) refused on this kind under the same fail-closed disposition — they configure agent turns on a channel that admits no agents, and `round-robin`'s non-empty-agent-order validation (T2.2) is structurally unsatisfiable here — and the kind plus the member pair carried on the `channel.created` payload so the projection stays events-canonical and replay cannot widen audience (I-016-4). (c) **Roster filtering**: the T2.2 roster read becomes **caller-parameterized** — it takes the authenticated caller principal and omits a `direct` channel for any caller outside its pair, the only per-caller filter in the V1 roster read. This task owns the service-layer predicate; **T3.2 owns threading the authenticated caller from the wire boundary into it** (the plan resolves caller identity at that boundary per T3.1/T3.2, so the filter would otherwise have no caller), and T3.2's roster assertions gain the matching membership dimension. (d) **The addressing gate**: the channel admission path creates an agent run only from an explicit addressing act naming a `targetAgentId`, so an unaddressed message creates none, human- and agent-authored alike (`Spec-016 §Turn Policies` — activation is addressing-gated under every turn policy; turn policy orders admitted turns and never authorizes activation, and an agent-authored message is never an addressing act). (e) **The delivery-fallback carve-out**: an audience-restricted channel is excluded from T2.4's re-homing fallback and fails visibly to its sender instead, since re-homing to main would hand agent-excluded content to every agent in the session. (f) **The pair write gate + artifact refusal** (`Spec-016 §Interfaces And Contracts`, Codex round 2 on the reconciliation PR): every `direct`-channel write — message publication and the `ChannelMute` / `ChannelUnmute` / `ChannelArchive` lifecycle mutations — is admitted only from an authenticated pair member and refused fail-closed for every other caller, the session `owner` included (relay scoping bounds readers; this gate bounds writers, who need no ciphertext to reach the wire surface); and an artifact publication or attachment addressed into a `direct` channel is refused outright as a typed refusal, because Spec-014's content-key wrapping fans to the session-wide attested set with no channel narrowing — the durable artifact-channel binding with member-intersected wrapping is the named V1.1 extension.
