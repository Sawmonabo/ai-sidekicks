## Goal

Implement daemon-backed queue state and authoritative intervention handling for active runs.

## Scope

This plan covers queue persistence, intervention records, run-state transitions, and client control surfaces for queue, steer, pause, resume, and interrupt — the waiting messages' edit, reorder and delivery timeout, a child's own controls, the answer to a restart's mismatch, and the run side of an undo among them.

## Non-Goals

- Workflow scheduling
- Notification routing

## Preconditions

- **Plan-004 epoch-attribution carrier (CP-002-12):** the durable typed epoch-attribution field on the event-append surface — [Spec-003 §Required Behavior](../specs/003-queue-steer-pause-resume.md#required-behavior) mandates the stamp; T3.10 writes it, T3.15's supersede projection consumes it. It is [Plan-004](./004-session-event-taxonomy-and-audit-log.md) T1.8's cross-cutting `sourceEpoch` + `sourcePosition` payload carrier pair: `SourceEpochSchema` / `SourcePositionSchema` plus their payload-key constants and the `withEpochStamp` pairing helper in `packages/contracts/src/event/envelope.ts`, registered in Spec-005 at §Event Type Enumeration (run-scoped-variant admission). The stamp stays on the row for as long as its session exists: no background pass rewrites a row a person can see, and the row goes only when its whole session is deleted, so the supersede projection always reads the stamp from the row itself. T3.10 waits on Plan-004 Phase 1.
- **Snapshot-callee checkout-root parameter:** T3.14's capture call-site supplies the caller-resolved `checkoutRoot` — read from `run_execution_contexts.checkout_root` beside the execution root — as a [Plan-007](./007-worktree-lifecycle-and-execution-modes.md) CP-007-11 input. The parameter joins `captureTurnSnapshot` when Plan-006 Phase 2B extends `git/turn-snapshot/service.ts` (CP-007-13), and the `checkout_root` column lands with Plan-007 Phase 3 / T3.2, its only writer. T3.14 waits on both producers, so it is never written against the signature without the parameter.

Target paths below assume the canonical implementation topology defined in [Container Architecture](../architecture/container-architecture.md).

## Design Decisions

This plan's design decisions. Each is registered in the corpus it touches: Spec-003 / Spec-005 for version derivation and emission, `api-payload-contracts.md §Method-Name Registry` for the wire method names, and `error-contracts.md` for the refusal codes.

- **D-002-1 `version` = any-run-progression counter.** The `expectedRunVersion` stale-request guard (I-002-7 / T2.6) compares against a run `version` derived as an **any-run-progression counter** (reading (b)): it increments on every run progression — applied interventions included — not only on `run.*` state-machine transitions (reading (a)). **Rationale:** reading (a) fails to catch two steers racing on a still-`running` run (zero new `run.*` events → the second stale steer passes undetected); reading (b) closes that window. Plan-002 authors T1.7's accessor _shape_ and T2.6's guard _behavior_; the `version` _derivation_ follows this semantics. Spec-003 / Spec-005 define the `version` field on the `run.*` payload and its increment/emission point.
- **D-002-2 `expectedRunVersion` is mandatory (fail-closed).** The comparand is **required** on every intervention request ([Spec-003 §Interfaces And Contracts](../specs/003-queue-steer-pause-resume.md#interfaces-and-contracts) mandatory reading); the absent-comparand case is **rejected**, not applied. An optional comparand would let a caller bypass the stale-request guard by omitting the field — the mandatory reading fails closed. T2.6 authors the present-comparand guard; the absent case rejects.
- **Scope extension — the mandatory comparand binds `run.pause` / `run.resume`, not only interventions.** The `RunPauseRequest` / `RunResumeRequest` contracts (`docs/architecture/contracts/api-payload-contracts.md §Plan-002 — Queue Steer Pause Resume`) carry the **same mandatory** `expectedRunVersion` guard, with `RunControlAck` echoing the advanced `runVersion` so the caller threads the fresh comparand forward. D-002-2 therefore **covers pause and resume as well as interventions**: a stale `pause` sent again against a run that has since progressed is the identical duplicate-request hazard the guard exists to close, so the comparand fails closed the same way (T3.3 / T3.4 apply the T2.6 guard before composing). `pause` / `resume` remain **orchestration-layer run-control verbs, not interventions** — they hold no `InterventionType` (`steer | interrupt | faster_model_retry`) membership and are not serialized through the intervention queue (ADR-011) — so this is a deliberate cross-cutting extension of the mandatory-comparand obligation, which the `api-payload-contracts.md` run-control comment also states.
- **D-002-3 the `run.*` method strings.** `run.queueList` / `run.queueCreate` / `run.queueCancel` / `run.queueReorder` / `run.intervene` / `run.pause` / `run.resume` / `run.childSteer` / `run.childInterrupt` / `run.childPauseSet` / `run.childrenStop` / `run.subscribeState` / `run.subscribeQueue` (CP-002-4) are the wire contract, registered in `api-payload-contracts.md §Method-Name Registry`. The reciprocal `provides` is on [Plan-005](./005-local-ipc-and-daemon-control.md), the `run.*` namespace owner.
