# Plan-003 Phase 3: Codex + Claude Driver Implementations

Phase 3 of [Plan-003: Provider Driver Contract And Capabilities](./003-provider-driver-contract-and-capabilities.md): the Codex and Claude drivers, built on that plan's Phase 1 contract.

**Goal:** Implement the two initial drivers (Codex, Claude) against the Phase 1 contract. Both drivers execute as local-runtime-node integrations per [Spec-004 §Required Behavior](../specs/004-provider-driver-contract-and-capabilities.md#required-behavior) (no shared hosted driver service).

**Driver capability matrix:** the V1 declared values are those of [Spec-004 §Per-Driver Capability Matrix](../specs/004-provider-driver-contract-and-capabilities.md#per-driver-capability-matrix).

`pause` is intentionally absent from both — orchestration-layer construct per [Spec-004 §Required Behavior](../specs/004-provider-driver-contract-and-capabilities.md#required-behavior). The driver declaration tests of the matrix's rows from `rollback` down land with Plan-003's driver tasks.

**Precondition:** Plan-004 Phase 1 merged — it ships `EVENT_DISPOSITION_BY_KIND` (the normalization-disposition map) in `packages/runtime-daemon/src/provider/`, which the Phase-3 driver normalizers (T3.11) consume as the single disposition source; the map ships before this phase's normalizers are built, so the two plans depend on each other only at plan granularity and the ordering is acyclic at phase granularity. Phases 1 and 2 merged in full, T1.7, T1.8 and T2.6 included: T3.11–T3.15 consume T1.8's contract surfaces and T2.6's store/cache seams.

- **Usage-delta accounting — cumulative in, per-turn delta out.** Both pinned providers report usage as a running total for the provider session, not a figure for the turn just finished, so a leg that forwarded each reading would emit the total on every turn and overstate session spend by the conversation's length — measured **22×** on a long thread, landing on the [Spec-014 §Session Cost Receipt](../specs/014-multi-agent-orchestration.md#session-cost-receipt) committed-spend fold rather than on a display. `provider/usage-delta-accountant.ts` holds **one base register per provider thread and axis, advanced in stream order** as each declared-cumulative reading is consumed — never a base snapshot copied at turn dispatch, which re-counts interleaved turns against copies of one starting value — and attributes each interval to **the turn the metered frame itself names** (the Codex usage notification carries the naming `turnId`; a usage frame for one turn routinely lands after the next has opened, and named-turn attribution over the stream-ordered base meters that late interval to its own turn instead of flooring it). Base establishment is two-armed per [Spec-004 §Required Behavior](../specs/004-provider-driver-contract-and-capabilities.md#required-behavior): **fresh bases at zero and the first reading meters in full** (the provider counter starts at zero, and the first turn's large input is real billed spend), while **provider-native resume bases at the daemon's own prior-emitted cumulative sum for that thread**, rebuilt from the canonical record, never at the first post-resume reading — so pre-resume spend is never re-metered and the first post-resume interval meters exactly the new spend. A context compaction does **not** re-base, because the provider's counter is unaffected by it and re-basing there would forgive every pre-boundary token. Where the wire declares a per-turn figure beside the cumulative one (the Codex breakdown's `last`), the accountant consumes it as a **corroborating cross-check** — interval asserted equal to the declared figure for the naming turn, mismatch recorded as a typed diagnostic — never as a substitute metering path. An observed decrease on a declared-cumulative axis is a falsified declaration: the emission floors at zero and the floor-hit lands on the P0-1 diagnostic module as a typed `DriverDiagnosticRecord`, never as negative spend and never silently. The normalized axes are a **partition** — the input axis is uncached input, with any cached-read component subtracted at this boundary **only where the breakdown's own sum identity confirms containment** (the vendor schema places the cached member beside the input member and proves nothing about nesting); an unconfirmed identity emits the input figure unsubtracted with a failed-identity diagnostic, a conservative overstatement surfaced for repair — and the cache-read / cache-write split is retained on the diagnostic band, since the Spec-005 `usage_telemetry` payload registers no per-cache-axis member and this plan mints none. Cost derivation (P1-6-producer) prices from the provider's **full breakdown**, never by re-multiplying the normalized axes. **Tests:** a recorded cumulative sequence yields per-turn deltas that re-sum to the newest reading minus the establishment base; an interleaved two-turn sequence (0 → 100 naming turn A → 150 naming turn B) attributes exactly 100 and 50 with no interval counted twice; a fresh session's first reading meters **in full** from base zero; a provider-native resume whose first reading carries the full historical total meters only the excess over the prior-emitted sum, and zero when there is none; a compaction between two readings does not reset the delta; a turn-A usage frame delivered after turn B has opened is attributed to turn A rather than floored or credited to B; a synthetic decrease emits zero **and** a floor-hit diagnostic record; a declared per-turn figure disagreeing with the derived interval records a cross-check diagnostic without substituting; a wire reading whose input figure contains its cached figure produces normalized axes that sum to the uncached total exactly once; and a reading whose breakdown satisfies no containment identity emits unsubtracted with the failed-identity diagnostic.
- **Child-thread frame routing — fail-closed, carve-out-before-suppress.** Both pinned providers multiplex child-thread traffic — subagent, review, and compaction threads the provider spawns for itself — over the connection carrying the session's own thread. The normalizer therefore consults `provider/thread-frame-router.ts` **before** any projection decision, and the router's rule is **family-scoped** per [Spec-004 §Required Behavior](../specs/004-provider-driver-contract-and-capabilities.md#required-behavior): a frame is first classified by its family against the pinned stream-surface census — a thread-scoped family routes by explicit thread identity and only the session's own thread projects; a censused connection- or account-scoped family (Claude `system/api_retry` → `usage.api_retry`, `rate_limits` → `usage.rate_limit_update`, the capability/initialization frames) routes to its registered normalization **without** a thread identity; an unrecognized family carrying no thread identity still quarantines. Thread identities enter the recognized set on the **registration path ahead of the refusal rule**: the session's own thread at establishment, and a child identity from the provider's parent-linked announcement — Codex `thread/started` carrying `parentThreadId` with a subagent `ThreadSourceKind`, Claude `SubagentStart` with `parent_tool_use_id` in the parent's own stream. A frame naming a **present-but-unregistered** thread — child traffic racing its own announcement — enters a **bounded pending-registration hold**, released into ordinary routing when the registration lands and shed with a recorded diagnostic on a declared timeout; a frame whose identity is **absent where its family requires one, or unrecognized by any registration path, is quarantined and reported**, never projected and never attributed to the parent by arrival order — the quarantine being a **bounded** diagnostic buffer (a declared cap, oldest-first shedding, each admission and each shed a `DriverDiagnosticRecord`), not a delivery queue, and distinct in semantics from the pending hold. Two carve-outs apply **ahead of** suppression. Usage counters are carved out first, so child content is dropped while child spend is not: provider-attributed subagent spend rides the already-registered (`runId`, `provider`, `subagentId`) triple the Subagent-lifecycle-normalization leg above already populates, and spend on a provider-internal child with no subagent identity (a compaction or memory-consolidation thread) attributes to the **parent run at run scope**, which is what it is. Neither arm invents a subagent and neither drops a token. Second, a child thread's **interactive requests** — tool-approval, permission, and input requests raised from inside a child — are carved out and routed through the same dispatch and approval pipeline as the parent run's, answered on the child's own correlation identity (mandatory per [Spec-014 §Provider-Native Subagents](../specs/014-multi-agent-orchestration.md#provider-native-subagents): a subagent introduces no separate trust surface, and suppressing the request would hang the child mid-tool-call rather than hide it); only the child's **transcript projection** is suppressed. Child **lifecycle** still reaches the transcript only as `subagent.started` / `subagent.completed`; a child thread's own frames are never a second lifecycle channel. **Tests:** a foreign-thread assistant-output frame is suppressed and leaves a diagnostic; a censused connection-scoped frame (`system/api_retry`, `rate_limits`) routes to its normalization with no thread identity and is neither quarantined nor held; an unrecognized-family frame with no thread identity is quarantined rather than presumed connection-scoped; a thread-scoped frame with no thread identity is quarantined rather than projected, and quarantine admissions past the declared cap shed oldest-first; a child frame arriving **before** its parent-linked announcement is held and then released into ordinary routing when the announcement lands, and the hold's timeout sheds with a recorded diagnostic; a child identity announced with no recognized parent linkage does not register; a child-thread usage frame lands on the child's attribution and **never** on the parent's rows; a compaction-child usage frame lands on the parent run at run scope with no `subagentId`; a child-raised interactive request reaches the dispatch/approval pipeline and its answer returns on the child's own correlation while the child's content frames stay suppressed; and the `subagent.started` / `subagent.completed` pair is still emitted for a child whose content frames were suppressed.
