## Goal

Implement the replay-backed session timeline, child-run visibility, policy-aware reasoning surfaces, and composer usage meters used by the primary collaboration experience.

## Scope

This plan covers timeline projections, live subscribe plus replay recovery, child-run summaries and expansion, reasoning-availability surfaces, and the composer usage meters (the context-window meter and the rate-limit indicator, `Spec-013 §Context Window and Usage Meters`).

## Non-Goals

- Notification routing
- Provider-specific reasoning rendering beyond normalized surfaces
- Full timeline design polish

## Invariants

- **I-013-1** — Every run-scoped timeline row carries the complete attribution triple `runId` + `position` + `epoch`, all-or-none; a partial row fails SDK schema parse rather than being delivered. **Run-scopedness is decided by three tests, not by category alone**: the row's category where that category is closed on the run-scoped side (`run_lifecycle`), the row's canonical event type against the census of `Spec-006` types whose registered payload names a run unconditionally, and — for the types whose run identity is registered OPTIONAL, which no type-level test can decide — the row's own payload naming one. A row answering any of the three and carrying the attribution-free `kind` is refused, because such a row is reachable by no run filter and permanently current under rollback projection. Grounds in `Spec-013 §Required Behavior`.
- **I-013-2** — A rolled-back turn is never dropped from the timeline; it is marked superseded and stays renderable. Grounds in `Spec-004 §Required Behavior`.
- **I-013-3** — The `superseded` marker is single-field (`targetPosition`); run identity and source epoch are read from the containing row, so live marking and replay marking cannot disagree. **The same no-second-source rule binds the row's payload**: where a projection echoes the canonical run identity or the `sourceEpoch` / `sourcePosition` origin keys, each must equal the row's own outer `runId` / `epoch` / `position`. Run identity is checked under **both** registered spellings — `runId`, and the intervention family's `targetRunId`, which is the same fact named from the other side of the relationship (`Spec-006 §Queue and Intervention (interactive_request)`) — because a rule reading only the first leaves every intervention row free to be filed under one run while naming another, and the row's own general-arm refusal already treats both spellings as run attribution. The run-identity half binds every arm carrying an outer `runId`, the compacted-stub arm included; the origin-key half binds the arm that carries ordinals. Echoing is optional and absence passes; disagreement is refused, because consumers key filtering and superseded treatment on the outer triple while the row's detail and provenance are read from the payload, so a row stating two attributions is filed under one turn and sourced from another. Grounds in `Spec-013 §Required Behavior`.
- **I-013-4** — Superseding is epoch-scoped: a re-executed reused ordinal in a later epoch renders current while the earlier epoch's same ordinal stays superseded. Grounds in `Spec-004 §Required Behavior`.
- **I-013-5** — Every `run.rolled_back` boundary payload validates into the typed `RunRolledBackEvent` shape at projection; no consumer receives an untyped cutoff or performs a cast. Grounds in `Spec-013 §Required Behavior`.
- **I-013-6** — The rollback boundary is delivered visibility-resolved to every filtered subscription admitting any of the affected run's rows, never keyed on the event's optional `channelId`. Grounds in `Spec-013 §Required Behavior`.
- **I-013-7** — Reasoning unavailability always produces a visible explanation surface; redaction never renders as absence. Grounds in `Spec-013 §Acceptance Criteria`.
- **I-013-8** — Detailed-reasoning expiry or compaction never erases the durable summary or the policy marker. Grounds in `Spec-013 §Fallback Behavior`.
- **I-013-9** — No renderer surface settles a driver ask or a compaction: an input-ask card's resolved / expired / canceled state and the compaction affordance's completed state each render **only** from the corresponding daemon event row (`driver_ask.responded` / `driver_ask.expired` / `driver_ask.canceled`; `usage.context_compacted`), never from a countdown reaching zero, a dispatch being accepted, or a locally predicted value. Grounds in `Spec-013 §Timeline Entry Types` (the `driver_ask` entry) and `Spec-013 §Context Window and Usage Meters`.
- **I-013-10** — A child-run summary whose detail is incomplete stays visible and says so **explicitly**: its completeness marker is required, its incomplete arm names a cause from the closed set (`detail_fetch_failed` / `pending_backfill` / `compacted`) together with the time observed, and the row's event count on that arm is a lower bound rather than a total. Incompleteness is never inferred from a low count and never rendered as absence. Grounds in `Spec-013 §Fallback Behavior`.
- **I-013-11** — Every reply of `TimelineRead`, `ReasoningSurfaceRead`, and `ChildRunExpand` rides **one** transport message body. The bound is stated on the reply's **encoded size** against the substrate's own declared limit (CP-007-16), never on a row count — the row's free-form text fields and its opaque payload are each bounded independently of any count, so no count ceiling bounds the page — and it is a parse-time refusal rather than a transport-time discovery, because an oversized response cannot carry its own error and closes the connection instead. A producer that stops short of the caller's window reports `hasMore` and hands back the cursor that continues it; a terminal page may carry a cursor and is never required to. **The budget bounds aggregation and never bounds a page below one entry.** A continuing reply carries at least one entry — a page that promises more and delivers none re-offers the same cursor forever while reading like progress — so where the first candidate alone exceeds the budget the producer pages that single entry rather than answering with zero, and the reply is refused **for its size** at the response boundary, naming the member and its measured bytes on an error frame the substrate can deliver. The undeliverable row is therefore reported structurally, on every producer, instead of as a bare zero each caller had to remember to special-case; the budget itself is unchanged and nothing oversized reaches the wire. A **terminal** page carries no such floor: an empty final page is the honest answer to a continuation whose cursor already sat at the end and to a filtered read that matched nothing. Grounds in `Spec-013 §Interfaces And Contracts`.
- **I-013-12** — A returned page is internally consistent with the header it carries: its entries never move backwards in sequence, every run-scoped entry of a `ChildRunExpand` reply belongs to the run that reply names, and a child-run summary is never its own parent. Each of the three is a schema-level refusal on the response, not a renderer convention, so a projection bug surfaces at the contract boundary rather than as a mis-ordered or misattributed surface. Grounds in `Spec-013 §Interfaces And Contracts`.
- **I-013-13** — Every timeline reply and every timeline emission is scoped to the request that asked for it: a `TimelineRead` page contains rows of the requested session only, a `ChildRunExpand` reply names the requested run, and a `TimelineSubscribe` stream carries rows of the subscribed session only. No response schema can state this — a schema never sees the request — so it is enforced at the daemon binder, on the caller's own parsed request. A cross-scope reply is refused as an **internal** failure and never delivered, because the caller asked a well-formed question and the daemon assembled a well-formed answer about a different subject, which correlates to the caller's own request id and is therefore indistinguishable from a correct answer. **One further reply is judged against the request rather than against itself**, and by the same mechanism for the same reason: a `ReasoningSurfaceRead` answering `available` with **no entries** is correct on a continuation whose cursor already sat at the end of the surface, and a defect on a **first** read, where it renders as a surface that exists and shows nothing — indistinguishable from the unavailable state while asserting the opposite. The response schema cannot separate the two, because the request is what separates them; it carries the half it can see (the continuing arm's non-empty floor, which is the arm that can loop) and this binder carries the half it cannot. Grounds in `Spec-013 §Interfaces And Contracts`.

- Add `TimelineRead`, `TimelineSubscribe`, `ReasoningSurfaceRead`, and `ChildRunExpand` to shared contracts and the typed client SDK.
- Ensure live subscription payloads and replay windows use the same row schema so reconnect recovery does not require projection translation.
- Give all three reads the same continuation shape: `TimelineReadRequest`, `ReasoningSurfaceReadRequest`, and `ChildRunExpandRequest` each take an optional `afterCursor`, and each response carries `hasMore` with `nextCursor` **required** on the continuing arm and optional on the terminal one — the asymmetry deliberate, so a caller moving from a completed read to `timeline.subscribe` has an after-cursor to hand it wherever the daemon has one. The reasoning surface takes the split inside its `available` state only; `unavailable`, `compacted`, and `policy_redacted` carry no continuation, having no entries to continue.
- Bound every page on its **encoded size** against the substrate's declared message-size limit (CP-007-16), checked once per reply and paired with the existing row ceiling, with the producer's page fill stopping at whichever trips first. The limit is declared once in `packages/contracts/src/jsonrpc.ts` and re-exported unchanged by the gateway that enforces it, so the framer and the page builder can never read different numbers. The reserve the budget subtracts is likewise derived from enforced rules rather than assumed ones: the echoed request `id` is bounded at the request boundary by Plan-007 (CP-007-16), so no id the substrate accepted can displace a page this budget sized. A row-count ceiling alone cannot carry this: `TimelineRow` mirrors the canonical event envelope's unbounded `payload` record, and even excluding it the ceiling's worst case over the row's independently-bounded free-form text fields exceeds the limit outright.
- The timeline row model carries an optional single-field `superseded` marker — `{targetPosition}`, present exactly when the row's turn is superseded, absence meaning current; the marker's run identity and source epoch are the containing row's own `runId` + `epoch`, so no duplicated fields exist to disagree and live marking is identical to replay marking by construction — identical on `TimelineRead` windows and `TimelineSubscribe` replay ([API Payload Contracts](../architecture/contracts/api-payload-contracts.md) mirrors the shape); run-scoped rows are the required-attribution variant `RunScopedTimelineEntry` — `runId` + `position` + `epoch` all required, all-or-none by construction, a partial row failing SDK schema parse (the projection-resolved originating run position and execution epoch — Plan-004 T3.14's uniform row-to-turn assignment and row attribution; the session `sequence` is never a run position, and reused ordinals mean `position` can never recover the epoch) — and every timeline surface returns the `TimelineRow` union, genuinely discriminated on the literal `kind` field (`rollback_boundary` | `run` | `legacy_stub` | `general` — consumers narrow structurally on `row.kind`, never probing the free-form `type`; `legacy_stub` carries a vacuous-attribution-era compacted row: `runId` preserved, position/epoch structurally absent because unknowable), whose boundary arm is the typed `TimelineRollbackBoundary` (payload validated into the `RunRolledBackEvent` shape at projection; the SDK parser hands consumers the narrowed arm, never a cast) carrying the rewind cutoff, the comparands of the live-stream client rule: cached rows of that run with `position` above it mark — each marker just the boundary's cutoff against the row's own identity, identical to replay by construction — and rows delivered after the boundary arrive marker-precomputed — a late straggler pre-marked exactly when its stamped attribution ranks above the run's effective lineage-minimum cutoff for its epoch, current within the surviving history; new-epoch rows unmarked — per `Spec-013 §Required Behavior`.
