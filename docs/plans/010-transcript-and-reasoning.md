## Goal

Implement the session transcript backed by the event log, child-run visibility, reasoning surfaces, and the composer's context ring used by the primary session experience.

## Scope

This plan covers transcript projections, live subscribe plus catch-up recovery, child-run summaries and expansion, reasoning-availability surfaces, the composer's context ring with its compaction popover ([Spec-011 §Context Window and Compaction](../specs/011-transcript-and-reasoning.md#context-window-and-compaction)), and the question card.

## Non-Goals

- Notification routing
- Provider-specific reasoning rendering beyond normalized surfaces
- Full transcript design polish

## Invariants

- **I-010-1** — Every run-scoped transcript row carries the complete attribution triple `runId` + `position` + `epoch`, all-or-none; a partial row fails the reply's schema parse rather than being delivered. **Run-scopedness is decided by three tests, not by category alone**: the row's category where that category is closed on the run-scoped side (`runLifecycle`), the row's canonical event type against the census of `Spec-005` types whose registered payload names a run unconditionally, and — for the types whose run identity is registered OPTIONAL, which no type-level test can decide — the row's own payload naming one. A row answering any of the three and carrying the attribution-free `kind` is refused, because such a row is reachable by no run filter and permanently current under rollback projection. Grounds in [Spec-011 §Required Behavior](../specs/011-transcript-and-reasoning.md#required-behavior).
- **I-010-2** — A rolled-back turn is never dropped from the transcript; it is marked superseded and stays renderable. Grounds in [Spec-003 §Required Behavior](../specs/003-queue-steer-pause-resume.md#required-behavior).
- **I-010-3** — The `superseded` marker is single-field (`targetPosition`); run identity and source epoch are read from the containing row, so live marking and catch-up marking cannot disagree. **The same no-second-source rule binds the row's payload**: where a projection echoes the canonical run identity or the `sourceEpoch` / `sourcePosition` origin keys, each must equal the row's own outer `runId` / `epoch` / `position`. Run identity is checked under **both** registered spellings — `runId`, and the intervention family's `targetRunId`, which is the same fact named from the other side of the relationship ([Spec-005 §Queue and Intervention (interactiveRequest)](../specs/005-session-event-taxonomy-and-audit-log.md#queue-and-intervention-interactiverequest)) — because a rule reading only the first leaves every intervention row free to be filed under one run while naming another, and the row's own general-arm refusal already treats both spellings as run attribution. The run-identity half binds every arm carrying an outer `runId`; the origin-key half binds the arm that carries ordinals. Echoing is optional and absence passes; disagreement is refused, because consumers key filtering and superseded treatment on the outer triple while the row's detail and provenance are read from the payload, so a row stating two attributions is filed under one turn and sourced from another. Grounds in [Spec-011 §Required Behavior](../specs/011-transcript-and-reasoning.md#required-behavior).
- **I-010-4** — Superseding is epoch-scoped: a re-executed reused ordinal in a later epoch renders current while the earlier epoch's same ordinal stays superseded. Grounds in [Spec-003 §Required Behavior](../specs/003-queue-steer-pause-resume.md#required-behavior).
- **I-010-5** — Every `agent.run.rolledBack` boundary payload validates into the typed `AgentRunRolledBackEvent` shape at projection; no consumer receives an untyped cutoff or performs a cast. Grounds in [Spec-011 §Required Behavior](../specs/011-transcript-and-reasoning.md#required-behavior).
- **I-010-6** — The rollback boundary is delivered on the session's one stream, `session.event.subscribe`. Grounds in [Spec-011 §Required Behavior](../specs/011-transcript-and-reasoning.md#required-behavior).
- **I-010-7** — A reasoning row is drawn for every reasoning text the provider sent, whole, and for nothing else: a turn whose provider kept no reasoning text, or kept it back itself, draws no reasoning row and no placeholder. Grounds in [Spec-011 §Acceptance Criteria](../specs/011-transcript-and-reasoning.md#acceptance-criteria).
- **I-010-8** — Every reasoning text the provider supplied is kept whole for as long as the session's events are kept: a text longer than one entry (16,384 characters) is stored as consecutive entries in order and read back as one, and no retention step trims, rewrites or drops it. Grounds in [Spec-011 §Required Behavior](../specs/011-transcript-and-reasoning.md#required-behavior).
- **I-010-9** — No renderer surface settles a question or a compaction: a question card closes and the compaction affordance shows its completed state **only** from what the daemon recorded — the question's attention entry resolving; the `agent.run.context.compacted` row — never from a dispatch being accepted or a locally predicted value. A question card holds no countdown at all, because an agent's question waits until it is answered. Grounds in [Spec-011 §Transcript Entry Types](../specs/011-transcript-and-reasoning.md#transcript-entry-types) (the question card) and [Spec-011 §Context Window and Compaction](../specs/011-transcript-and-reasoning.md#context-window-and-compaction).
- **I-010-10** — A child-run summary whose detail is incomplete stays visible and says so **explicitly**: its completeness marker is required, its incomplete arm names its cause, `detailFetchFailed`, together with the time observed, and the row's event count on that arm is a lower bound rather than a total. Incompleteness is never inferred from a low count and never rendered as absence. Grounds in [Spec-011 §Fallback Behavior](../specs/011-transcript-and-reasoning.md#fallback-behavior).
- **I-010-11** — Every reply of `TranscriptRead`, `TranscriptReasoningRead`, and `TranscriptChildRunExpand` rides **one** transport message body. The bound is stated on the reply's **encoded size** against the page's own byte budget, `PAGE_MAX_BYTES` (`crates/sidekicks-contracts/src/jsonrpc/page.rs`), a fixed size declared apart from the substrate's message-size limit and under it (CP-005-8), never on a row count — the row's free-form text fields and its opaque payload are each bounded independently of any count, so no count ceiling bounds the page — and it is a parse-time refusal rather than a transport-time discovery, because an oversized response cannot carry its own error and closes the connection instead. A producer that stops short of the caller's window reports `hasMore` and hands back the cursor that continues it; a terminal page may carry a cursor and is never required to. **The budget bounds aggregation and never bounds a page below one entry.** A continuing reply carries at least one entry — a page that promises more and delivers none re-offers the same cursor forever while reading like progress — so where the first candidate alone exceeds the budget the producer pages that single entry rather than answering with zero, and the reply is refused **for its size** at the response boundary, naming the member and its measured bytes on an error frame the substrate can deliver. The undeliverable row is therefore reported structurally, on every producer, and nothing oversized reaches the wire. A **terminal** page carries no such floor: an empty final page is the honest answer to a continuation whose cursor already sat at the end and to a filtered read that matched nothing. Grounds in [Spec-011 §Interfaces And Contracts](../specs/011-transcript-and-reasoning.md#interfaces-and-contracts).
- **I-010-12** — A returned page is internally consistent with the header it carries: its entries never move backwards in sequence, every run-scoped entry of a `TranscriptChildRunExpand` reply belongs to the run that reply names, and a child-run summary is never its own parent. Each of the three is a schema-level refusal on the response, not a renderer convention, so a projection bug surfaces at the contract boundary rather than as a misordered or misattributed surface. Grounds in [Spec-011 §Interfaces And Contracts](../specs/011-transcript-and-reasoning.md#interfaces-and-contracts).
- **I-010-13** — Every transcript reply is scoped to the request that asked for it: a `TranscriptRead` page contains rows of the requested session only, and a `TranscriptChildRunExpand` reply names the requested run. No response schema can state this — a schema never sees the request — so it is enforced at the daemon binder, on the caller's own parsed request. A cross-scope reply is refused as an **internal** failure and never delivered, because the caller asked a well-formed question and the daemon assembled a well-formed answer about a different subject, which correlates to the caller's own request id and is therefore indistinguishable from a correct answer. **Two further replies are judged against the request rather than against themselves**, and by the same mechanism for the same reason. A page may not exceed the window the caller asked for: the effective ceiling is `TranscriptRead`'s own `limit` where the request named one and the default row ceiling where it did not, and a response schema can bound a page only at the default, so a read for ten rows answering with the maximum is otherwise well-formed and a client sizing a viewport, a budget, or a render pass from its own request is handed more with nothing on the reply saying so — `TranscriptChildRunExpand` declares no `limit`, so its ceiling is that default, stated on the same binder so one rule covers both paged reads. And: a `TranscriptReasoningRead` answering `available` with **no entries** is correct on a continuation whose cursor already sat at the end of the surface, and a defect on a **first** read, where it renders as a surface that exists and shows nothing — indistinguishable from the unavailable state while asserting the opposite. The response schema cannot separate the two, because the request is what separates them; it carries the half it can see (the continuing arm's non-empty floor, which is the arm that can loop) and this binder carries the half it cannot. Grounds in [Spec-011 §Interfaces And Contracts](../specs/011-transcript-and-reasoning.md#interfaces-and-contracts).

## API And Transport Changes

- Add `TranscriptRead`, `TranscriptReasoningRead`, and `TranscriptChildRunExpand` to shared contracts, with the reads that complete the transcript — `transcript.body.read`, `transcript.patch.list` and `transcript.search`, registered through the same transcript method table — and the session's live figures and question: `session.context.subscribe`, `session.autoCompact.update`, `agent.turn.usage.subscribe`, `agent.turn.task.subscribe`, the `question.asked` record and `question.resolve` ([Spec-011 §Interfaces And Contracts](../specs/011-transcript-and-reasoning.md#interfaces-and-contracts)).
- The transcript has one live stream, the session's own `session.event.subscribe`; a reconnecting client resumes it by cursor, and catch-up windows come from `transcript.read`.
- Give all three reads the same continuation shape: `TranscriptReadRequest`, `TranscriptReasoningReadRequest`, and `TranscriptChildRunExpandRequest` each take an optional `afterCursor`, and each response carries `hasMore` with `nextCursor` **required** on the continuing arm and optional on the terminal one — the asymmetry deliberate, so a caller moving from a completed read to `session.event.subscribe` has an after-cursor to hand it wherever the daemon has one. The reasoning surface takes the split inside its `available` state only; `unavailable` carries no continuation, having no entries to continue.
- Bound every page on its **encoded size** against its own byte budget, `PAGE_MAX_BYTES` — sized to what one reply costs the desktop to decode and draw and the relay to carry, its figure set from its first measurement of those — declared apart from the substrate's message-size limit (CP-005-8) and under it, so a page never grows with the transport limit; checked once per reply and paired with the existing row ceiling, with the producer's page fill stopping at whichever trips first. The reserve the budget subtracts is likewise derived from enforced rules rather than assumed ones: the echoed request `id` is bounded at the request boundary by Plan-005 (CP-005-8), so no id the substrate accepted can displace a page this budget sized. A row-count ceiling alone cannot carry this: `TranscriptEventRow` mirrors the canonical event envelope's unbounded `payload` record, and even excluding it the ceiling's worst case over the row's independently-bounded free-form text fields exceeds the budget outright.
- The transcript row model carries an optional single-field `superseded` marker — `{targetPosition}`, present exactly when the row's turn is superseded, absence meaning current; the marker's run identity and source epoch are the containing row's own `runId` + `epoch`, so no duplicated fields exist to disagree and live marking is identical to catch-up marking by construction — identical on `TranscriptRead` windows and on live delivery ([Transcript Payload Contracts](../architecture/contracts/transcript-payloads.md) mirrors the shape); run-scoped rows are the required-attribution variant `RunScopedTranscriptEntry` — `runId` + `position` + `epoch` all required, all-or-none by construction, a partial row failing the reply's schema parse (the projection-resolved originating run position and execution epoch — Plan-002 T3.15's uniform row-to-turn assignment and row attribution; the session `sequence` is never a run position, and reused ordinals mean `position` can never recover the epoch) — and every transcript surface returns the `TranscriptEventRow` union, genuinely discriminated on the literal `kind` field (`rollbackBoundary` | `run` | `general` — consumers narrow structurally on `row.kind`, never probing the free-form `type`), whose boundary arm is the typed `TranscriptRollbackBoundary` (payload validated into the `AgentRunRolledBackEvent` shape at projection; the reply's parse hands consumers the narrowed arm, never a cast) carrying the rewind cutoff, the comparands of the live-stream client rule: cached rows of that run with `position` above it mark — each marker just the boundary's cutoff against the row's own identity, identical to catch-up by construction — and rows delivered after the boundary arrive marker-precomputed — a late straggler pre-marked exactly when its stamped attribution ranks above the run's effective lineage-minimum cutoff for its epoch, current within the surviving history; new-epoch rows unmarked — per [Spec-011 §Required Behavior](../specs/011-transcript-and-reasoning.md#required-behavior).

### Phase 1 — Transcript Contracts

#### Tasks

- **T1.1** — Define the `TranscriptEventRow` discriminated union in `crates/sidekicks-contracts/src/transcript/` — arms `TranscriptRollbackBoundary` | `RunScopedTranscriptEntry` | `TranscriptEntry`, genuinely discriminated on the literal `kind` field, mirroring [Transcript Payload Contracts](../architecture/contracts/transcript-payloads.md). `RunScopedTranscriptEntry` requires `runId` + `position` + `epoch` all-or-none with the optional single-field `superseded` marker. The `general` arm's refusal is three-legged per I-010-1 — the closed `runLifecycle` category, the derived census of `Spec-005` types whose registered payload names a run unconditionally, and the row's own payload naming one under `runId` or the intervention family's `targetRunId` — with the census **derived from Plan-004's per-category type arrays** rather than transcribed. The `run` arm additionally refuses a payload whose echoed run identity — under **either** spelling, `runId` or `targetRunId` — or whose echoed `sourceEpoch` / `sourcePosition` disagrees with the row's own outer triple, per I-010-3; the run-identity half of that check reads the same exported key list the general arm's third leg reads, so the two guards cannot drift apart.
  - **Spec coverage:** Spec-011 §Transcript Entry Types
  - **Verifies invariant:** I-010-1, I-010-3
- **T1.2** — Define `ChildRunSummary` (`runId`, `parentRunId`, `state`, `eventCount`, `completeness`) in `crates/sidekicks-contracts/src/transcript/`, mirroring [API Payload Contracts](../architecture/contracts/api-payload-contracts.md). `completeness` is a **required** discriminated union on `state`: `complete` carries nothing else, `incomplete` requires both `cause` — always `detailFetchFailed` — and `observedAt`. An internally tagged enum whose arms refuse unknown fields (`deny_unknown_fields`), so a complete row cannot carry a cause and an incomplete one cannot omit it.
  - **Spec coverage:** Spec-011 §Transcript Entry Types
  - **Verifies invariant:** I-010-10
  - **Tests:** the complete arm round-trips; the one cause round-trips on the incomplete arm; an absent `completeness` fails; the incomplete arm without `cause` or without `observedAt` fails; a cause outside the set fails; a `state` outside the two arms selects no arm; the complete arm carrying `cause` or `observedAt` fails strict parse; a non-ISO `observedAt` fails.
- **T1.3** — Define `TranscriptReasoningReadRequest` / `TranscriptReasoningReadResponse` in `crates/sidekicks-contracts/src/transcript/` — the response a closed discriminated union on `availability: 'available' | 'unavailable'` mirroring [API Payload Contracts](../architecture/contracts/api-payload-contracts.md): `available` requires the bounded `reasoningEntries` and `unavailable` carries none — an internally tagged enum whose arms refuse unknown fields (`deny_unknown_fields`), so no two states serialize identically and a state-inconsistent field set fails parse. The request takes an optional `afterCursor` and the `available` state splits again on `hasMore` — a nested tagged union inside the outer one — `nextCursor` required where more remains and **at least one entry** required with it, since a page that promises more and delivers none re-offers the same cursor forever. The terminal arm carries neither requirement: an empty final page is how a continuation says it reached the end of a surface that does exist, which `unavailable` would misstate. The floor that remains — an empty `available` page on a **first** read, which collapses onto `unavailable` while asserting the opposite — cannot be a schema rule, because only the request separates a first read from a continuation; it is enforced at the daemon binder under I-010-13 (T1.4). The `unavailable` state carries no continuation members at all, having no entries to continue, so a paging field on them fails strict parse rather than reading as an empty remainder. The request is strict, so the `cursor` spelling is refused rather than ignored: the member is `afterCursor` on all three reads, matching `TranscriptReadRequest`.
  - **Spec coverage:** Spec-011 §Interfaces And Contracts
  - **Verifies invariant:** I-010-7, I-010-11
  - **Tests:** each state round-trips; `available` without `reasoningEntries` fails; entries on `unavailable` fail strict parse; an `available: boolean` field fails parse (no tolerant fallback arm); the `available` state without `hasMore` fails; `hasMore: true` without `nextCursor` fails while `hasMore: false` parses with and without one; `hasMore: true` with an empty entry list fails and the same page with one entry parses; `hasMore: false` with an empty entry list parses; a continuation member on the `unavailable` state fails; a request spelling the cursor `cursor` fails.
- **T1.4** — Register the first transcript method strings — `transcript.read`, `transcript.reasoning.read`, `transcript.childRun.expand` — in the [Transcript Method-Name Registry](../architecture/contracts/transcript-payloads.md#transcript-method-name-registry) and against the daemon IPC `MethodRegistry`, so every operation's method string resolves and not merely its schema name. ## Rollback Or Fallback

- If payload shape regresses, render the placeholder in place of the affected payloads until it is fixed; nothing stored is trimmed, so every reasoning text reads back whole afterwards.

## Risks And Blockers

- Transcript projections will drift if row schemas are allowed to diverge from canonical event provenance
- A reasoning text cut to fit one stored entry would silently lose part of the record; splitting it across 16,384-character entries, read back as one, is what keeps every text whole
