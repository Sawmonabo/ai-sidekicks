## Goal

Implement immutable artifact publication and attachment ingestion — with the scan on Windows and a PDF's first page — the session's staging verbs and the cover of a staged picture, the artifact reads every linked device calls, deletion with CAS reclaim, and the session sweep the purge calls.

## Scope

This plan covers artifact ids and manifests, attachment ingest and its validation pipeline, the ingest worker (a PDF's first page, the cover), the scan on Windows, payload storage, derivative artifacts, a chat file's versions, `artifact.list` and `artifact.read`, the staging verbs, artifact deletion with CAS reclaim, and the session sweep the purge calls.

## Non-Goals

- Full artifact preview UX
- Notification behavior for artifact publication
- Renderer views: the inspector's artifact section, the files-written row, the file surface, the quick look and its cover control call this plan's methods and are built with the console ([Plan-021](./021-desktop-app-and-renderer.md))

## Data And Storage Changes

- Add durable `artifact_manifests` and `artifact_payload_refs` records with provenance and producer metadata, in the one collapsed schema and its test. A chat file's versions are manifests of one path in the chat's managed workspace, each with its version number and the time it was written.
- Keep manifest storage separate from large payload storage while preserving content-addressed lookup or equivalent immutable payload identity.
- Treat any redacted or summarized form as a separate derivative artifact record rather than as in-place mutation metadata on the original artifact. A covered picture is a new artifact naming no `subject`, and the uncovered copy it replaces is deleted.
- See [Local SQLite Schema](../architecture/schemas/local-sqlite-schema.md) for column definitions.
- **No schema change is made for the ingest stream protocol.** The ingest stream registry, its per-stream completion records, and the aggregate spool reservation are in-memory daemon state — a stream dies with the process and its spool goes quiescent for the `mtime` reaper — so no table is minted for a transient whose lifetime `max_ingest_stream_lifetime` already bounds, and the accepted cost is the named residual (a retried `Complete` after eviction ends as a second manifest row over one deduplicated CAS payload). Of an outside picture only the ingest worker's rewritten copy is stored, and a PDF's first-page picture and page count are stored beside the PDF.
- **No schema change is made for the CAS reference count** — it is derived by query over `artifact_payload_refs.storage_path` (I-012-12), deliberately not a stored counter column. Recorded here because "add a refcount column" is the obvious wrong turn and its absence should read as a decision, not an omission.

## API And Transport Changes

- Add `ArtifactPublish`, `ArtifactRead` (the wire method `artifact.read`), `artifact.list` and `AttachmentIngest` to shared contracts and the typed client SDK, and serve the session's staging verbs `session.attachmentAdd`, `session.attachmentRemove` and `session.attachmentCover`. `artifact.read` takes `{artifactId, version?}` and returns the version in view, how many versions exist and when the one in view was written; `artifact.list {sessionId}` returns the session's plans and, on a chat session, its files and folders with their versions.
- `AttachmentIngest` is carried as the `AttachmentIngestInit` / `AttachmentIngestChunk` / `AttachmentIngestComplete` trio under the Spec-006 1 MB frame ceiling, and `AttachmentIngestCompleteResponse` carries `derivedMediaType` and `derivedSizeBytes` — the server's own findings over the spooled bytes; Init's `mediaType` (**optional** — the pipeline's declaration-absent path is a first-class state a required field could never exercise) / `declaredSizeBytes` are annotated **advisory** and are reconciled, never persisted as fact (I-012-11). Attachment references on any carrier are typed `ArtifactId[]`, order-preserving, with an explicit unresolved marker rather than a silent omission (I-012-13).
- **No wire member is added, removed, or retyped by the stream protocol.** `AttachmentIngestCompleteRequest` still carries only the `ingestId` — which is exactly why the completion record is keyed on the stream and **stamped** with the committed digest rather than discriminated on a caller-supplied one: a _divergent_ Complete has no wire form to take, so the stamp is a fail-closed defense-in-depth check, never a new field. The retry semantics change only what a **second identical call** returns: the original response, verbatim, for as long as the stream's registry entry lives. No error code is minted by the stream protocol: `artifact.ingest_stream_invalid` (409) and `artifact.ingest_capacity_exhausted` (429) are registered in [error-contracts.md §Artifact](../architecture/contracts/error-contracts.md#artifact).
- Return manifest metadata first and use explicit payload handles for large or deferred content reads.

## Invariants

- **I-012-1 (Immutability):** A published artifact's payload is content-addressed (SHA-256) and never mutated in place; a live workspace path is never treated as durable payload identity. ([Spec-012 §Required Behavior](../specs/012-artifacts-files-and-attachments.md#required-behavior); verified by Task 2, Task 3.)
- **I-012-2 (Derivative-not-mutation):** A redacted/summarized shareable form is a separate manifest (own id, `subject` → original); the original manifest is never UPDATEd in place. ([Spec-012 §State And Data Implications](../specs/012-artifacts-files-and-attachments.md#state-and-data-implications); verified by Task 4, Task 12.) **Deletion inherits this:** a derivative is deleted with its source in the purge's one transaction and never by nulling its `subject` — a null-out is exactly the in-place mutation of a foreign row this invariant prohibits, and it would silently sever the derivative's provenance chain (Task 12).

- **I-012-11 (Server-derived, bounded ingest):** For caller-supplied bytes crossing the client→daemon trust boundary — the `AttachmentIngest` trio, and a boundary-crossing `ArtifactPublish`, because the pipeline binds to the boundary rather than to a method name (a boundary-crossing publish declaring the `file` family is refused outright and directed to `AttachmentIngest`) — the daemon derives media type and size **from the payload bytes it received**, and a caller-declared `mediaType` or `sizeBytes` is advisory input that is reconciled against the derived value, never persisted as fact and never used to make an admission decision. Every bound in [Spec-012 §Ingest Validation And Payload Bounds (V1)](../specs/012-artifacts-files-and-attachments.md#ingest-validation-and-payload-bounds-v1) is applied **before** any byte reaches the CAS or any manifest row is written, so a refused payload leaves no durable artifact behind; a payload whose signature cannot be determined is refused rather than admitted on the strength of its declared type unless that type is on the signature-exempt textual allow-list **and** the bytes prove well-formed UTF-8 — in which case the recorded classification is the declared subtype admitted under the exemption, an allow-list-bounded declaration rather than trust in the declaration (fail-closed — the one arm where "unknown" must not read as "probably fine"); a payload that fails a content gate (steps 3–8) is quarantined outside the CAS with no manifest, removed at `ingest_quarantine_ttl` or earlier under the `ingest_quarantine_max_bytes` oldest-`mtime`-first eviction (an entry that cannot fit even an emptied quarantine is deleted rather than held), while a stream breaching the byte bound is terminated with its spool deleted — refused garbage, never quarantined. The other `artifactType` families are producer-fixed and do not traverse this path **when the daemon itself produces them**; the same families arriving across the trust boundary do. **"Bounded" means bounded under concurrency, and "retry-safe" means retry-safe for the whole trio.** Three rules join this invariant. **(a) Completion is idempotent within its stream's lifetime.** The `AttachmentIngestComplete` response is recorded on that stream's registry entry, stamped with the committed digest, and a retry replays it verbatim — no gate re-run, no second manifest row. A lost response must not cost the caller a 100 MB re-upload, and the opposite failure is equally prohibited: re-running steps 3–8 and minting a second manifest for one completed stream. Completion surrenders the reservation, the count slot, and the spool at commit, so a completed entry pins no budget; past `max_ingest_stream_lifetime` the entry and its record are evicted and a retry takes the ordinary `artifact.ingest_stream_invalid` (409), whose named residual is one extra manifest row over a deduplicated CAS payload — never duplicated bytes, never a lost artifact. **(b) Both byte ledgers this pipeline bounds are reserve-then-install.** The aggregate admission ledger (`max_active_ingest_streams` plus the `ingest_spool_max_bytes` reservation total) and the quarantine directory (`ingest_quarantine_max_bytes`) each test and spend inside one critical section: a bound checked outside the mutation that spends it is exceeded by up to one payload per racing caller, which is the parallel-submission form of the very denial-of-disk each cap exists to stop. **(c) Every call on one `ingestId` is single-flight, and the reaper's eviction path takes the same exclusion** — sequence validation, spool append, running-count and last-chunk-digest advance, and acknowledgment are atomic per call, so an original racing its own retry cannot double-append or compare against half-updated state, and a stream is never served and evicted at once. The exclusions compose in one total acyclic order — per-`ingestId` → the admission ledger → at most one of per-`storage_path` or the quarantine directory ([Spec-012 §Implementation Notes](../specs/012-artifacts-files-and-attachments.md#implementation-notes)). A refused Init still creates nothing, and that is asserted through **admission** — the next Init admitting once a slot or reservation frees — never through an identifier the refusal never issued. ([Spec-012 §Ingest Validation And Payload Bounds (V1)](../specs/012-artifacts-files-and-attachments.md#ingest-validation-and-payload-bounds-v1); verified by Task 11.)
- **I-012-12 (Reclaim-at-zero):** A CAS payload is reclaimed only when its derived reference count reaches zero — the count is **computed over `artifact_payload_refs.storage_path`, never stored in a counter column**, so it cannot drift out of agreement with the rows it summarizes and no reconciliation job is owed. The purge removes a session's manifests and their payload-refs, and the cover removes the uncovered copy and its payload-ref; a shared blob survives while any other manifest still references it (the Task 2 / Task 3 dedup guarantee is exactly the case that makes this load-bearing). Reclaim is concurrency-excluded per storage key: every CAS writer checks-and-references inside that key's in-process exclusion, every reclaimer — the boot sweep included — derives-and-unlinks inside it, and the unlink re-derives the count after commit and aborts above zero, so no interleaving of a same-hash publish with a reclaim leaves a manifest over missing bytes. That per-key exclusion is one **leaf** of this plan's single acquisition order — per-`ingestId` → the ingest admission ledger → at most one of per-`storage_path` or the quarantine directory, the two leaves never held together ([Spec-012 §Implementation Notes](../specs/012-artifacts-files-and-attachments.md#implementation-notes)) — so the ingest path's exclusions compose with this one rather than racing or deadlocking against it; `AttachmentIngestComplete` is the path that holds a stream exclusion and then takes this leaf for its step-8 CAS rename. A derivative is deleted with its source, never after it (I-012-2). ([Spec-012 §Local Artifact Deletion And CAS Reclaim (V1)](../specs/012-artifacts-files-and-attachments.md#local-artifact-deletion-and-cas-reclaim-v1); verified by Task 12.)
- **I-012-13 (No silent attachment drop):** An attachment reference carried by any turn-scoped payload is a typed `ArtifactId`, never an opaque `unknown`, and the reference list is **order-preserving**: the position an attachment occupies on the way in is the position it occupies on the way out. An attachment that cannot be delivered — a deleted artifact, including a payload reclaimed under I-012-12 — is rendered as an **explicit unresolved marker in its own position** and never omitted, because a silently shortened list makes the recipient reason about a message that was never sent; the marker names its cause, `deleted`. The carrier is additionally bound by `max_attachments_per_carrier`, refused as a whole rather than truncated to fit. ([Spec-012 §Required Behavior](../specs/012-artifacts-files-and-attachments.md#required-behavior), [Spec-012 §Fallback Behavior](../specs/012-artifacts-files-and-attachments.md#fallback-behavior); verified by Task 13.)
- **I-012-16 (Original pictures):** A picture from outside the daemon — staged by attach, paste or drop, staged from another device, or written by an agent and shown in the transcript or the inspector — is stored, drawn and sent as its original bytes: nothing re-encodes it, strips its metadata or bounds its pixels before a decode. A PDF's first page is drawn only in the ingest worker, and a crash or a hang in the worker refuses that one file and never faults the daemon. ([Spec-012 §Ingest Validation And Payload Bounds (V1)](../specs/012-artifacts-files-and-attachments.md#ingest-validation-and-payload-bounds-v1) step 7; verified by Task 16.)
- **I-012-17 (Covered means gone):** After `session.attachmentCover`, the bytes a provider can receive for that attachment have every pixel under each box drawn black, not masked over, and the uncovered copy is deleted from the store; a sent picture is never covered. ([Spec-012 §Required Behavior](../specs/012-artifacts-files-and-attachments.md#required-behavior); verified by Task 18.)

### Phase 2 — Ingest And Publication Producers

**Precondition:** Phase 1 merged.

T14.2's `artifact-id.ts` brands the output of the daemon-wide UUIDv7 generator `mintUuidV7` (`packages/runtime-daemon/src/ids/uuid-v7.ts`) rather than generating bits of its own. Tasks 2 + 3 + 11 + 13 — the two independent producers (ingest and publish, each writing its own manifest) plus the CAS payload store, and the ingest-validation pipeline and the typed attachment-reference carrier; §Rollout Order steps 1–2 (local payload storage; attachment ingest and artifact publication in local sessions). **Task 11 lands in this phase deliberately, not in a tail phase:** it is the validation gate on the `AttachmentIngest` path Task 2 builds, and a gate that ships after the ingest it gates means shipping an unvalidated byte-accepting interface first — the pipeline and its producer are one slice. Task 13 joins them because `max_attachments_per_carrier` is one of the bounds Task 11 enforces, so the count cap and the typed carrier it binds are authored together.

#### Tasks

- **T14.2 — Attachment ingest + immutable payload store.** Implement `runtime-daemon/src/artifacts/attachment-ingest-service.ts` and `payload-store.ts`: normalize name/media-type/size, compute SHA-256, write the CAS-keyed payload blob, and — **in one transaction** — persist the attachment's own `artifact_manifests` row (`state` = `published`, an uploaded attachment _is_ a published artifact the moment it is ingested, [Spec-012 §Default Behavior](../specs/012-artifacts-files-and-attachments.md#default-behavior) newly-uploaded-attachments bullet + [Spec-012 §Example Flows](../specs/012-artifacts-files-and-attachments.md#example-flows) design-reference-image flow; **`created_by` stamped with the ingesting request's attributable caller** — NULL only when no caller is attributable, because a producer that leaves the stamp NULL silently converts every caller-originated upload into an unattributable artifact) followed by its `artifact_payload_refs` row (manifest first, to satisfy the `manifest_id NOT NULL REFERENCES artifact_manifests(id)` FK — [`artifact_payload_refs`](../architecture/schemas/local-sqlite-schema.md#artifact-tables-plan-012)), and return the minted `ArtifactId` (the manifest row's `id`). **This task CREATEs the corpus's one artifact-id minter, `runtime-daemon/src/artifacts/artifact-id.ts`, exporting `mintArtifactId(): ArtifactId`** — which **CONSUMEs `mintUuidV7` from `packages/runtime-daemon/src/ids/uuid-v7.ts`** (the daemon-wide RFC 9562 generator, Plan-001-owned per the `packages/runtime-daemon/src/ids/` ownership row) and **brands** its output as `ArtifactId`. It generates no bits of its own: the **UUIDv7** per [RFC 9562 §5.7](https://www.rfc-editor.org/rfc/rfc9562#section-5.7) that [Spec-012 §Required Behavior](../specs/012-artifacts-files-and-attachments.md#required-behavior)'s manifest bullet requires of every daemon-minted manifest id comes from that one generator, and this module is the call plus the brand. **A helper is necessary rather than a convention, and the reason is measured, not assumed:** the established daemon id idiom is `crypto.randomUUID()` (so named in `packages/runtime-daemon/src/workspace/workspace-event-emitter.ts` — evidence only that the daemon calls it, not of what it mints), and that emits **v4** on Node's own reference, [`crypto.randomUUID()`](https://nodejs.org/api/crypto.html#cryptorandomuuidoptions): "Generates a random RFC 4122 version 4 UUID" — the layout [RFC 9562 §5.4](https://www.rfc-editor.org/rfc/rfc9562#section-5.4) carries forward unchanged — so a producer reaching for the house idiom would mint a well-formed id that **passes `ArtifactIdSchema`** (which accepts any RFC 9562 form by design) while violating the spec's minting rule, silently and with no test that could catch it. **Consuming rather than re-implementing is that same rule one level up:** a private §5.7 implementation here would be a second daemon-side generator wearing an artifact-shaped name, and the `packages/runtime-daemon/src/ids/` ownership row makes `uuid-v7.ts` the daemon's only one. **Its unit test asserts what a consumer owns, and re-proves nothing the generator already proves.** Over a batch of minted ids it asserts the **version nibble reads `7`** (the most significant 4 bits of octet 6, [RFC 9562 §4.2](https://www.rfc-editor.org/rfc/rfc9562#section-4.2)), the **variant bits read `10`** ([§4.1](https://www.rfc-editor.org/rfc/rfc9562#section-4.1)), the value **parses under `ArtifactIdSchema`** and is typed as the **branded** `ArtifactId` rather than a bare string, and **no two minted ids are equal** — plus one **ordering smoke assertion** over that batch (the ids are non-decreasing), which holds whether or not the batch happens to share a millisecond and so is deterministic on any host. It deliberately stops there. - **T14.4 — Derivative artifacts.** Model derivatives as separate manifests with `subject` linkage. **Assertion:** a derivative is a distinct manifest row (own id) whose `subject` points to the original, and the original row is never UPDATEd in place; a publish whose `subject` names a manifest outside the request's session is refused with `artifact.not_found` (404) — subject resolution is session-scoped, so a derivative chain never crosses sessions; and the `subject` resolution **canonicalizes before it looks up** exactly as T14.13's resolver does: the caller's spelling passes through `canonicalizeUuid` from `packages/contracts/src/uuid-canonical.ts` before the `BINARY`-collated `artifact_manifests.id` comparison, so the uppercase and lowercase spellings of one minted id (the identity pair) resolve the **same** manifest and a case-variant spelling of an existing in-session manifest is never refused as `artifact.not_found`. **Spec coverage:** Spec-012 §State And Data Implications (a derivative must be a separate artifact with its own manifest, never an in-place mutation), Spec-012 §Local Artifact Deletion And CAS Reclaim (V1) (the session-scoped `subject` resolution). **Verifies invariant:** I-012-2 (derivative-not-mutation).

- **T14.5 — Artifact events.** Emit `artifact.published` / `artifact.superseded` via Plan-005's `EventLogService.append` with the Spec-005 payload shape; register `artifact.*` IPC handlers under Plan-006's registry. **Assertion:** publishing an artifact appends an `artifact.published` event to the session timeline with `{sessionId, artifactId, runId?, state}`, and a chat file's new version appends `artifact.published` for that version. **Spec coverage:** Spec-012 §State And Data Implications (manifests are durable records and part of replayable session history). **Verifies invariant:** none (no I-012 invariant names Task 5 — the emission rides Plan-005's taxonomy, asserted against the Spec-005 payload shape). **Consumes:** EventLogService.append ← Plan-005; `artifact_publication` taxonomy ← Spec-005 §Artifact and Diff Publication (artifact_publication) (by SHAPE); IPC registry ← Plan-006.

- **T14.12 — Artifact deletion + local CAS reclaim.** Implement `packages/runtime-daemon/src/artifacts/artifact-deletion.ts` and the reclaim half of `payload-store.ts`. No method deletes a single artifact and nothing is added to shared contracts for deletion: the store has two deletions, both inside the daemon. The **session sweep** is the session-keyed function the purge calls: `daemon.retentionPurge` (`Delete old data`, Plan-006 T-006r-1-12) deletes the session's rows with SQLite's `secure_delete` on, with a `TRUNCATE` checkpoint after commit ([Spec-020 §Ordering And Atomicity](../specs/020-data-retention-and-gdpr.md#ordering-and-atomicity); Plan-020 owns that erasure step), and this sweep removes the session's manifests and their `artifact_payload_refs` rows **in one transaction** (CP-012-8). The **one-manifest removal** is the cover's: after `session.attachmentCover` stores the covered copy (T14.18), the uncovered copy's manifest and its own payload-ref row are removed. This task also adds `idx_artifact_payload_refs_storage_path` to the one collapsed schema and its test: the derived-refcount query's lookup key, so every reclaim decision is index-backed rather than a full scan of all payload references. Both deletions reclaim a CAS payload **only if no surviving payload-ref still names that `storage_path`** — the reference count is **derived by query, never stored in a counter column**, so it cannot drift from the rows it summarizes and no reconciliation job is owed. **Reclaim is crash-safe by ordering**: the row-deleting transaction commits **first**, and the CAS unlink runs **strictly after** commit — a crash in the window leaks an orphaned CAS entry, never a manifest whose payload is gone (leak-then-reclaim, the recoverable direction; the inverse ordering dangles a manifest over deleted bytes, which no sweep can repair). The **orphan sweep** owns the leak — run at daemon start **and periodically as a job of the service's one scheduler, beside the quarantine reaper** (a boot-only sweep leaves a failed unlink's plaintext on disk for the lifetime of a long-running daemon): CAS entries no surviving `artifact_payload_refs` row names are unlinked, an unlink hitting `ENOENT` is success (a prior attempt or the sweep got there first), never an error — and no journal table is added for this (the payload-ref rows themselves are the journal; a post-commit unlink failing non-`ENOENT` needs no tombstone either — the zero-reference predicate **is** the durable reclaim record, and the next sweep pass retries). **Reclaim is additionally concurrency-safe by per-`storage_path` exclusion** — ordering alone leaves a live-writer race: the daemon is the CAS's single-process owner, so a writer's existence check + payload-ref insert and a reclaimer's refcount derivation + unlink each run inside an in-process critical section keyed by `storage_path`, the unlink **re-deriving the refcount inside the exclusion, after commit, and aborting on any count above zero** — a same-hash publish or ingest racing the reclaim either saves the entry (its reference lands before the re-check) or writes fresh bytes (it arrives after the unlink and the existence check misses), never a manifest over missing bytes; the boot sweep takes the same exclusion, so it is safe beside the accepting surfaces rather than dependent on startup ordering. The dedup guarantee Tasks 2 and 3 already assert is exactly what makes this load-bearing: two manifests over identical bytes share one CAS entry, and purging the session that holds one must leave the other readable. **A derivative goes with its source:** the session sweep never meets a cross-session referent, because `ArtifactPublish` resolves `subject` session-scoped — a foreign-session id refuses `artifact.not_found` (404) — so every derivative is deleted in the same transaction as its source, the sweep's completeness is by construction, never by cross-session search, and no `subject` is ever nulled (a null-out is the in-place mutation of a foreign row that I-012-2 prohibits). **Assertion:** purging one of two sessions whose manifests share a CAS blob leaves the other session's manifest readable and the blob present, and purging the second reclaims it; purging a session holding a derivative and its source removes both and leaves no manifest whose `subject` resolves nowhere; the cover's removal of an uncovered copy whose bytes another manifest shares leaves those bytes present; a post-commit unlink failing with an injected non-`ENOENT` error (`EIO`) leaves the purge complete, and the next **periodic** sweep pass reclaims the entry without a daemon restart; the session sweep removes every manifest of the session in one transaction and reclaims exactly the payloads no surviving manifest references, unlinking strictly after commit; killing the process between the row-deleting commit and the unlink leaves an orphaned CAS entry and **zero** dangling manifests, and the next boot's orphan sweep reclaims it (asserted through a crash-simulation seam that stops after commit, in both the one-manifest and session-sweep arms); a same-hash publish racing a post-commit unlink never yields a manifest over missing bytes — a reference landing before the reclaimer's in-exclusion re-check aborts the unlink and the bytes survive, while one landing after the unlink misses the existence check and writes fresh bytes (asserted through an interleaving seam in both orders, and for the boot sweep under the same per-key exclusion); and the unlink path treats `ENOENT` as success in the one-manifest, session-sweep and orphan-sweep arms. **Spec coverage:** Spec-012 §Required Behavior (no single-artifact delete; artifacts go with their session), Spec-012 §Local Artifact Deletion And CAS Reclaim (V1) (derived refcount, the crash-safe commit-then-unlink ordering with the boot-time + periodic orphan sweep, a derivative going with its source, and the session-deletion sweep), Spec-012 §State And Data Implications (no stored counter column). **Verifies invariant:** I-012-12, I-012-2. **Consumes:** `subject` self-FK linkage ← Task 4 (same phase — a derivative going with its source cannot be tested before derivatives are modeled); `artifact_payload_refs` + the CAS payload store ← Tasks 2 and 3; the purge that calls the session sweep ← [Plan-006](./006-local-ipc-and-daemon-control.md) T-006r-1-12 (CP-012-8); `idx_artifact_payload_refs_storage_path` ← [local-sqlite-schema.md](../architecture/schemas/local-sqlite-schema.md) (an index, not a table).

## Risks And Blockers

- Artifact immutability will be undermined if live workspace paths are allowed to masquerade as durable payload identity

## Design Decisions

- **D-012-1 — The OCI manifest envelope is realized as dedicated `artifact_manifests` columns + a named `ArtifactManifest` wire shape.** [Spec-012 §Interfaces And Contracts](../specs/012-artifacts-files-and-attachments.md#interfaces-and-contracts) specifies an OCI-inspired envelope (`subject`, `size`, `annotations`, `digest`=content_hash). This plan authors `artifact_manifests.subject` (self-referential FK), `size_bytes`, and `annotations` columns (local-sqlite-schema.md) and the matching `ArtifactManifest` wire shape (api-payload-contracts.md).
- **D-012-2 — `annotations` is a dedicated OCI string→string column, not folded into freeform `metadata`.** The OCI `annotations` map is a first-class manifest property ([OCI image-manifest spec](https://github.com/opencontainers/image-spec/blob/main/manifest.md)); it gets its own `artifact_manifests.annotations` column and a distinct `ArtifactManifest.annotations` wire field so the at-rest shape is 1:1 with the wire, while `metadata` stays purely freeform daemon-side provenance.
- **D-012-3 — `ArtifactPublish`/`ArtifactRead` compose a single named `ArtifactManifest`; publish embeds the manifest metadata (no `manifestUrl` pointer).** [Spec-012 §Interfaces And Contracts](../specs/012-artifacts-files-and-attachments.md#interfaces-and-contracts) mandates that publish return "artifact id **and** manifest metadata"; a `manifestUrl` pointer would drift from that clause ([Spec-012 §Interfaces And Contracts](../specs/012-artifacts-files-and-attachments.md#interfaces-and-contracts) grants handle/inline latitude to the _payload_ on `ArtifactRead` only, never to the manifest). The wire embeds `manifest: ArtifactManifest` on publish and `manifest` + `payloadHandle?`/`payload?` on read; producer inputs (`subject?`, `annotations?`) are accepted at publish so the `annotations` column and derivative `subject` are not write-dead.
- **D-012-4 — The `artifactType` discriminator is the union `file | diff | summary | log | design | workflow_output`.** [Spec-012 §Required Behavior](../specs/012-artifacts-files-and-attachments.md#required-behavior) lists the artifact families (`summary` covers the plan/summary family), and `workflow_output` is the [Spec-015 §Output Mode Specification](../specs/015-workflow-authoring-and-execution.md#output-mode-specification) workflow phase-output type. The typed union is the contract (api-payload-contracts.md `ArtifactType`); the schema CHECK mirrors it (`CHECK(artifact_type IN ('file','diff','summary','log','design','workflow_output'))`).
- **D-012-6 — The ingest worker uses `sharp` and `@hyzyla/pdfium`, and the scan is the operating system's AMSI on Windows only.** `sharp` 0.35.4 (Apache-2.0, prebuilt libvips 8.18.6) writes the first page's PNG and the covered copy, can restrict libvips to named loaders and ships prebuilt binaries. `@hyzyla/pdfium` 2.1.13 (MIT, PDFium in WebAssembly, no native build) draws a PDF's first page; `mupdf` was rejected as AGPL, and `pdfjs-dist` (Apache-2.0, 34.8 MB) because it is built to render in a browsing context, which is what this rule keeps PDFs out of. The scan is AMSI through the Windows half on both kinds of Windows computer; ClamAV was measured and rejected for macOS and Linux, since it would hold about 1.5 GB of memory for a check that protects little when the app never runs an attached file.

## References

Source for the SQLite collation premise T14.13's case-preserving resolver rests on:

- [SQLite — Datatypes In SQLite, §7 Collating Sequences](https://www.sqlite.org/datatype3.html#collation) — the built-in `BINARY` collating function "compares string data using memcmp(), regardless of text encoding", and §7.1 states that when two `TEXT` values are compared and neither operand carries a `COLLATE` clause or a column-level collation, "the BINARY collating function is used for comparison". `artifact_manifests.id` is declared `TEXT PRIMARY KEY` with no `COLLATE`, so its primary-key index and every equality lookup against it compare bytes: `ABC…` and `abc…` are two different keys, which is why the resolver canonicalizes the caller's spelling before the lookup rather than trusting the database to fold case.
