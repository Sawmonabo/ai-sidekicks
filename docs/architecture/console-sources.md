# Console Sources

The sources behind the console design of [Spec-021: Desktop App And Renderer](../specs/021-desktop-app-and-renderer.md).

## Console Design Sources

The rows below index the sources per axis behind [Spec-021 §Console Design (Meridian)](../specs/021-desktop-app-and-renderer.md#console-design-meridian), [Desktop App Implementation Notes §Console Libraries](desktop-implementation-notes.md#console-libraries), [Desktop App Implementation Notes §Console Test Tiers](desktop-implementation-notes.md#console-test-tiers), and [Desktop App Implementation Notes §Electron Version And Support Window](desktop-implementation-notes.md#electron-version-and-support-window). Type is one of: registry, upstream source, upstream docs, issue, changelog, measurement (local, in the repository's own Electron binary), license text, spec.

**Measurement record for the `Measured (ours)` rows.** Every `Measured (ours)` row in D.1–D.10 was measured on 2026-09-01, unless the row names its own date, on the reference development machine (Apple silicon, macOS 26, Node 24.18.0) by the method the row states or this record does: bundle rows use esbuild (`--bundle --minify --format=esm --platform=browser --target=es2022`, or the `chrome146` target where the row says so; `react` / `react-dom` / `react/jsx-runtime` externalized; gzip level 9; "total" summing the entry plus every async chunk emitted); heap rows use `node --expose-gc` retained-heap deltas after a forced collection; timing rows are warm-process medians over the corpus the row names (the 64 KB markdown message, the 10k-line TypeScript file and diff, the 20 000-entity map with 300 subscribers, the 100 000-string search corpus, the 120-column 10 000-line terminal scrollback); renderer probes ran inside the Electron binary the row names. No harness script is retained, so these rows are reproducible by method rather than by artifact; every verdict they drive also rests on a non-measured leg — a license, a maintenance signal, an API fact, a security posture — recorded beside them. The durable artifact is the bundle budget, which re-measures the adopted set's bytes on every console PR through `size-limit`; figures for libraries Spec-021 rejects stay as recorded here and are re-measured only when such a library is reconsidered.

## Console Surface Sources

The sources behind [Spec-021 §Console Design (Meridian)](../specs/021-desktop-app-and-renderer.md#console-design-meridian)'s surface set, its pane and window model, and the daemon-side library rows in [Desktop App Implementation Notes §Console Libraries](desktop-implementation-notes.md#console-libraries).

- Electron `dialog` API reference — `showOpenDialog`'s `openFile`, `openDirectory` and `multiSelections` properties, and the platform note that one picker cannot offer both files and folders on Windows or Linux; read 2026-09-14. Behind the composer's attach control and its files-only, several-at-once, never-a-folder rule.
- Two Chrome-debug clients on one page, measured 2026-10-01 on Electron 44.5.1, Chromium 152, `playwright-core` 1.63.0, macOS arm64: both clients attach in either order without error, the counter arithmetic is exact with no lost or doubled input, each observes the other's mutations, and the in-process debugger emits no detach event, so neither client needs exclusive ownership of the page. A never-shown window screencasts at 51 to 54 frames a second with zero acknowledgment errors while an external client drives the same page, with background throttling off and painting when initially hidden on; with no external client attached it gives no frames until focus emulation is on (85 to 94 frames a second once it is). The acknowledgment method must be called by its exact name, or the queue stalls after exactly three frames, which is the frames-in-flight default. A `BrowserWindow`'s never-navigated page target blocks an external attach forever (thirty-second timeout), where a `BaseWindow` completes the same attach in 37 to 48 milliseconds with four processes rather than five. A capture on a never-shown window returns a genuinely doubled image on a display whose scale factor is two while the platform reports a single scale factor, so the scale is read from the returned image. One hidden page view costs about 243 MB of working set and three extra processes over a bare main process, and driving both clients through two screencasts adds about 112 MB; on macOS at this Electron the process metrics carry only the working-set figures, so the working set is the figure read.
- Shared emulation state, same measurement: a connected external automation client unconditionally pins focus emulation and a light color scheme for as long as it is attached, so a screencast running underneath visibly changes theme and focus behavior. Each page setting therefore has one owner: the service's own connections pass `noDefaults`, so attaching pins nothing; the page's size is main's on the desktop; interception and network conditions are the agent's alone; and the service re-asserts focus emulation and the screencast's state after any client detaches. Evaluation, input and the screencast need no such ownership.
- Development-server discovery has no library: every candidate a registry search surfaces checks whether a port is _available_ rather than enumerating listening sockets with their owning process identities, so the daemon does it itself — three platform branches over the machine's listening sockets plus a short-timeout loopback probe, one probe loop per daemon, ticking only while a project session is live.
