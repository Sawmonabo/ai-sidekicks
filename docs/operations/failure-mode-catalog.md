# Failure-Mode Catalog

> **Doc shape note.** This is a process-methodology catalog (proactively invoked during commit / PR / review), not a failure-recovery runbook. The 10-section operations template (`docs/operations/template.md`) does not apply; the structure here is one row per failure pattern, indexed on **structural action**. The same convention is used by [`plan-implementation-readiness-audit-runbook.md`](./plan-implementation-readiness-audit-runbook.md), which is also a methodology doc rather than a recovery procedure.

## Purpose

Every row indexes one regression pattern — in the doc corpus itself, or in the tooling that guards it — by **structural action** (what the change physically does, to the corpus or to a gate) so disciplines, hooks, skills, and audit prompts resolve to the same canonical row regardless of which **domain framing** the author used. CAT-01 through CAT-09 and CAT-11 are corpus-regression rows; CAT-10 is the gate-integrity row, admitted here rather than in a registry of its own because this catalog is explicitly the single source of truth for rows that hooks and skills address by `CAT-NN`. This fixes the recall-by-domain-label miss documented in the PR-#27 post-mortem: the canonicalization-sweep-completeness discipline existed but did not fire for the surface label `archival` because the human framing was `archival` while the structural action was `string move`.

The catalog is the single source of truth. Hooks, skills, and audit-prompts reference catalog rows by ID (`CAT-NN`); adding a new failure pattern means adding one row plus wiring detection — there is no parallel registry.

## How to use

1. **Authoring an edit.** Read the row whose **Structural Action** matches what your edit physically does. The "What discipline restores correctness" cell names the pre-commit / CI / audit / human action you owe.
2. **Adding a new failure pattern.** Insert one row indexed on the structural action, never on the domain label. List the domain framings that triggered the discovery as **Surface-Label Aliases**. Wire detection (file path or skill name); a row with no detection-layer wiring is documentation theater.
3. **Skill `/ripple-check`.** Walks the catalog at runtime, identifies which rows' structural-action signals are present in the staged diff, and dispatches up to five parallel subagents — one per related-row group (A=CAT-01/02, B=CAT-03/04, C=CAT-05 broad, D=CAT-06/07) plus one cross-document coherence subagent (E) that audits the residual not keyed to any single row. CAT-08, CAT-09, CAT-10, and CAT-11 fire no subagent, for two different reasons. CAT-08, CAT-09, and CAT-11 are covered by a deterministic hook (`lychee` at CI for CAT-08; `table-total-coherence` at pre-commit + CI for CAT-09; `table-arity` at pre-commit + CI for CAT-11), so a subagent would duplicate settled work — with the honest qualifier that CAT-11's hook covers its GFM-table slice, and the row's other-markup residual has no diff signal distinct from CAT-05's. CAT-10 is the opposite case: it has no doc-diff signal to key a subagent on, because the regression lives in a gate rather than in the corpus the diff touches — it is discovered in review and closed per instance by a gate of its own. The within-document arithmetic is the deterministic slice of CAT-05's broader "table row added / removed" set change; that broader set-quantifier ripple still dispatches Subagent C (CAT-05).
4. **Audit-prompt augmentation.** Plan-readiness audit prompts include the line "walk every catalog row marked Detection-layer=audit and re-derive the claim from primary source".

### CAT-09 — Table-total arithmetic drift

| Field | Value |
| --- | --- |
| Structural Action | A data row is added / removed / re-counted in a table marked `<!-- corpus:total-check column="…" -->`, or a declared total is edited, so the summed column no longer equals the in-table **Total** row or a bound `prose-total` restatement. This marked-table arithmetic is the deterministic slice of CAT-05's broader "table row added / removed" set change. |
| Surface-Label Aliases | "census drift", "the count doesn't add up", "Total says N but the rows sum to M", "event-count mismatch". |
| Detection Layer | pre-commit hook + CI |
| Hook | [`tools/docs-corpus/lib/table-total-coherence.ts`](../../tools/docs-corpus/lib/table-total-coherence.ts) re-sums the marked column against the in-table **Total** row and every bound `prose-total` (both the `<label>: N` colon form and the `N-<label>` prefix form). Composed into [`tools/docs-corpus/bin/pre-commit-runner.ts`](../../tools/docs-corpus/bin/pre-commit-runner.ts) for the corpus lanes; the standalone [`tools/docs-corpus/bin/table-total-check.ts`](../../tools/docs-corpus/bin/table-total-check.ts) runs the same check in isolation for the audit runbook's gate G7. |
| Off-the-shelf Tool | None — summing a marked GFM column against a declared total is corpus-specific; no general linter does it. |
| Failing Example | PR #152 (Tier-6 plan-readiness audit), round 19: a prose restatement of the Spec-006 event-type total disagreed with the column it summarized while the in-table **Total** row stayed correct, so a Total-row-only check would have passed and missed it. It surfaced only late in PR #152's 21-round review because nothing re-summed the column against every site asserting the total. |
| What Discipline Restores Correctness | The hook fails the commit / CI; re-sum the column and reconcile the **Total** row and every `prose-total` in the same change. The same total restated in a SIBLING document (Spec-006 vs Plan-006) is cross-document, beyond this within-document hook — that reciprocity is the audit runbook's synthesis-stage [Cross-Document Design-Fact Reciprocity](./plan-implementation-readiness-audit-runbook.md) dimension. |

### CAT-10 — Gate reports clean over work it did not do

| Field | Value |
| --- | --- |
| Structural Action | A check, gate, or test runner emits a passing verdict for a screen that never ran: an empty match set read as a clean result, a guard whose predicate can never fire, or a scan whose input was silently truncated before it was measured. Distinct from a check that runs and reaches the wrong answer — here the verdict rests on no evidence at all, so the usual "it passed, so it was checked" inference is what breaks. |
| Surface-Label Aliases | "silently disabled", "false clean", "vacuous pass", "the suite is green but empty", "the hook never fires", "0 findings". |
| Detection Layer | CI, per instance — every shipped closure runs in a CI test job; none of them run in the lefthook pre-commit chain, so a local commit that regresses one of these gates still commits cleanly. |
| Hook | **No class-level detector exists**, and claiming one would be this row's own failure mode: nothing screens a diff for "this gate will report clean over work it did not do". What is wired is one closure per shape. **Zero-match test runs** — [`tools/run-node-tests.mjs`](../../tools/run-node-tests.mjs) refuses to spawn when any pattern resolves no files, which covers every caller routed through it; `--min-files=N` adds an opt-in floor above that refusal for callers that declare one. **Collapsed gate input** — [`tools/docs-corpus/bin/pre-commit-runner.ts`](../../tools/docs-corpus/bin/pre-commit-runner.ts) takes the same floor per LANE (`--min-md` / `--min-code`), armed by CI's `custom-checks` job and left OFF for lefthook, where a commit touching only `.json` derives an empty `.md` lane legitimately — the same empty input means "enumeration broke" in one caller and "nothing of that kind changed" in the other, and the flag is what distinguishes them. The floors are asserted after the argv partition, because that is where a collapse stops being visible: CI passes both lanes as one flat argv, so an `.md` collapse beside a healthy code lane clears any argv-TOTAL floor while five markdown checks skip on their `stagedMd.length > 0` guards. Both `git ls-files` pipelines there end in `\|\| true`, which is what converts a broken enumeration into an empty array rather than a non-zero exit. Clearing a floor is not evidence a lane is healthy, so the resolved per-lane counts print whenever one is armed. **Bin-script entry guards** — [`tools/__tests__/entry-guard.test.mjs`](../../tools/__tests__/entry-guard.test.mjs) `spawnSync`s each guarded CLI through a spaced, symlinked path, because a unit test that imports the exported logic bypasses the guard under test and silently re-creates the defect it is meant to catch. That fixture list is itself re-derived from the source tree on every run and fails when a guarded script is missing from it — the hand-maintained list had been an instance of this very row, enumerating only `.mjs` and therefore never spawning the three guarded TypeScript CLIs, `pre-commit-runner.ts` (the whole lefthook docs-corpus gate) among them. **Gate-4 cite screen** — the twelve instances PR #260 found are closed inside [`preflight.mjs`](../../.claude/skills/plan-execution/scripts/preflight.mjs) and specified in [`preflight-contract.md` §Cite screen — per-phase Gate-4 (armed)](../../.claude/skills/plan-execution/references/preflight-contract.md#cite-screen--per-phase-gate-4-armed). Twelve closed instances is not the same as a screen free of this row, and the difference is the whole point of the row: a further, larger one is open and recorded under Known Gaps below. |
| Off-the-shelf Tool | None. Coverage tools measure which code the tests executed; nothing generic measures whether a GATE's input set was non-empty, and a gate over zero inputs is exactly what coverage cannot see. |
| Failing Example | PR #259: `node --test` given a glob that matches nothing exits 0 printing `# tests 0`, and an entry guard comparing `import.meta.url` against a `file://` URL built from `process.argv[1]` by string equality no-ops on any spaced or symlinked path, disabling the script it protects. PR #260 then found TWELVE more in one screen, every one the same shape — a nullish default converting "could not determine" into "determined to be empty" (`?? []`, `?? planCount`, `?? ""`, and an `indexOf` miss falling through `-1` into `slice(0)`). The most instructive: a plan whose cite screen THREW stayed inside `surveyedPlanCount`, so the coverage line counted it swept, the markerless screen called the unrun check a vacuous pass, and the stale-exemption ratchet advised deleting a live exemption on evidence never gathered — a false clean that went on to produce a confident recommendation. |
| Known Gaps | **2026-07-27 (a) — survey-unit span complement. CLOSED 2026-07-28 (PR #262); was the largest live instance of this row — diagnosis retained below because the shape recurs.** `surveyCorpus` screens only the union of `### Phase N` spans, each bounded by the next phase heading or the next `## ` sibling, and the whole-document fallback fires only when a plan has ZERO survey units — so one phase heading switches a plan permanently onto the per-phase path. Marker lines before the first phase heading, or after a `## ` sibling that terminated the last one, are never parsed or verified by Gate 4 or by the inline anchor floor, while the plan is still counted in `coverage: N/N plan(s) cite-swept, 0 uncovered` and the run prints `cite anomalies: none`. Live instance: `docs/plans/025-self-hostable-node-relay.md` carries 35 marker lines and exactly one `### Phase N` heading (its Phase 1 crypto-substrate phase); **30 of the 35 sit above that heading**, inside three `#### Tasks` blocks under `## Implementation Steps`. Running the real `gateTasksBlockCites` over those unscreened ranges yields **36 error-severity findings** — 18 `unparseable-spec-subanchor`, 13 `unparseable-cite`, 5 `section-not-found` — none of which the armed survey has ever produced. The discriminator is POSITION, not heading shape: a non-`Phase` `###` heading placed AFTER a phase is swallowed into that phase's span and IS screened, so a fix keyed on heading shape would be keyed on the wrong property. Covering layer: after `surveyUnits` is built, take the complement of the covered line set and emit an additional survey unit over each contiguous uncovered region containing a bold marker, inside `surveyCorpus` so no caller can reopen it. The announcement half is already built and must NOT be re-derived: PR #260 added `unsweptMarkerPlans`, so the same run that prints `cite anomalies: none` also prints `cite markers OUTSIDE every survey unit — counted as swept, never screened` and names Plan-025 beneath it. The gap is therefore disclosed-but-unscreened rather than silent — the two verdict lines still overclaim, but the run does not conceal that an unscreened region exists, and screening the complement is the whole of what remains. (That disclosure counts marker OCCURRENCES where the census above counts marker LINES — 32 of 42 against 30 of 35, one fact in two units.) Any regression fixture must assert BOTH that a defective block inside a span gates AND that the identical block outside one is silent today — a zero-findings assertion alone would re-create this row's failure mode inside the test guarding against it. **Closure (PR #262):** the complement is emitted as additional survey units inside `surveyCorpus`, derived by SUBTRACTION from the covered line set exactly as prescribed above — never by heading shape — and `unsweptMarkerPlans` became the partition-leak assertion (it must now stay EMPTY) while a new `complementMarkerPlans` carries the disclosure and, more importantly, the screen's non-zero DENOMINATOR: `32 of 42 marker(s) in 2 complement unit(s)` on Plan-025. The 36 findings were then repaired rather than suppressed — re-spelled into already-accepted anchor shapes, on the ruling that the plan was malformed and the grammar correct (66 in-phase passing instances established the convention; Plan-025's spellings appeared nowhere else, so widening the parser to admit an unvalidated `Row N` production would have manufactured a fresh instance of this very row). The prescribed both-directions fixture is `preflight-survey.test.mjs`. **Two follow-on instances of this row surfaced INSIDE that fix and are also closed by PR #262** — worth recording because both are the pattern of a screen whose scope outruns its predicate: (1) a complement holding exactly ONE Gate-4 field failed `gateTasksBlockCites`'s both-markers floor, returned before `extractCiteAnchors` ran, and was screened by nothing while the report counted its marker as swept — the floor is now asymmetric (`requireBothMarkers: false` for complements, unchanged for the dispatch path, since one marker in a PHASE genuinely does mean the audit did not run); and (2) the marker-shape checks were both phase-only, though only one of them has a phase-specific predicate — W3 partial-marker asks about audit output (a complement has none, so it stays phase-only) while W4 legacy-unbold asks whether markers carry anchors the bold extractor cannot parse, which is well-posed anywhere and now runs on every unit. Residual, deliberate and named: marker-PAIR completeness inside complement regions is unscreened; every anchor a complement marker carries is verified. **2026-07-27 (b) — Gate-4 field scope, and the line-keyed exemption that leaks through it.** `extractCiteAnchors` parses only `**Spec coverage:**` and `**Verifies invariant:**`, so a `**Consumes:**` payload never reaches Gate 4's SEMANTIC screen even inside a swept span. That boundary alone is not a hole: the md lane still covers most of the field, and the gap must be stated as the difference rather than as "verified nowhere". `checkSectionCites` carries no plan-grammar exemption, so a backticked `§Heading` anchor in a `Consumes:` payload IS verified for heading existence; `checkMarkdownVolatileCites` treats a `Consumes:` line as ordinary prose and DENIES a raw line pin on it. What actually escapes is the intersection: that deny is skipped per LINE, not per field — a line carrying `**Spec coverage:**` is `continue`d whole, so a raw pin sitting in a `**Consumes:**` payload on that same physical line is exempted from the md lane and unparsed by Gate 4. Measured on Plan-025: of 20 `Consumes:` markers, 7 share a line with an exempt marker and **3 of those carry a raw pin** — those 3 are the live unverified set; the other 13 sit on their own lines and carry no raw pins. So the honest scope is "no semantic screen over the field, plus 3 line-keyed-exemption pins", not 20 unchecked markers. This is the same seam recorded on CAT-07 below, seen from the Gate-4 side. A latent shape with zero live instances on the two gated fields: a marker whose colon falls outside the bold (`**Spec coverage**: …`) or that carries a parenthesized suffix inside it (`**Spec coverage (partial):**`) matches neither the bold nor the unbold marker detector, yet `countCites` still counts it by bare substring — so the unit reads as having markers, emits no partial-marker or legacy-unbold diagnostic, and its cites go unparsed. Not hypothetical authoring: Plan-025 already writes `**Consumes (all SHAPE-verified against Plan-021):**`, the same suffix habit one field over, so the shape is zero-instance on the gated fields by luck rather than by construction. |
| What Discipline Restores Correctness | Make the empty case loud at the point of measurement rather than at the consumer: report "could not determine" as an outcome distinct from "determined to be clean", and never let a nullish default collapse the two. Concretely — floor the input count (`--min-files`); mask non-content input instead of deleting it so offsets survive; mark a unit UNCOVERED when its screen throws instead of letting the catch fall through into the swept tally; and apply the fix inside the leaf function rather than at the call site, so a later caller cannot reopen it. When auditing an existing gate, feed it a known-bad input in the same run: a zero-findings result is evidence only once the checker has been proven able to fail. And when a tool reports clean, check its channels separately, because they can disagree: `prettier --check` prints `[error] No files matching the pattern were found` ADDITIVELY — beside `All matched files use Prettier code style!`, not instead of it — so anyone reading OUTPUT sees a pass, while the exit code is 2 and tells the truth. The instructive part is what one flag does to that: `--no-error-on-unmatched-pattern` silences BOTH channels at once (exit 0, no error line, success line still printed), leaving a run over zero files indistinguishable from a real clean in every signal the tool emits. No amount of better output-reading or exit-code discipline survives that, which is why the closure for this row is an input FLOOR — a count taken before the tool runs, in a channel the tool's own flags cannot reach. |

### CAT-11 — Formatter normalizes malformed markup into format-stable corruption

| Field | Value |
| --- | --- |
| Structural Action | A formatter is handed structurally malformed markup, parses it at its literal (wrong) structure, and rewrites the source into well-formed output that encodes the corruption. The lasting damage is the normalization, not the original typo: the formatter is idempotent on what it produced, so every later `--check` certifies the corrupted form and the file is simultaneously wrong and perfectly formatted. Distinct from CAT-09 (a check runs and the arithmetic disagrees) and from CAT-10 (a verdict resting on no evidence) — here the check runs over real input and passes honestly, because the artifact really does match what the formatter would write. |
| Surface-Label Aliases | "prettier mangled the table", "format-stable corruption", "the diff looks clean now", "but prettier passes". |
| Detection Layer | pre-commit hook + CI |
| Hook | [`tools/docs-corpus/lib/table-arity.ts`](../../tools/docs-corpus/lib/table-arity.ts) — every row of a RECOGNIZED GFM table must carry its header's cell count, with cells split by the shared [`tools/docs-corpus/lib/markdown-tables.ts`](../../tools/docs-corpus/lib/markdown-tables.ts) walk so an escaped pipe counts as content rather than as a boundary. Composed by the dispatch runner [`tools/docs-corpus/bin/pre-commit-runner.ts`](../../tools/docs-corpus/bin/pre-commit-runner.ts). **Scope, stated plainly:** this wires the GFM-table-pipe SLICE of the class — the slice carrying both live instances — and within that slice it recognizes a deliberately conservative subset of GFM, each excluded table shape being a bound disclosed and measured in the module header rather than a silent gap. Other markup families where a formatter can stabilize a corruption (a broken list nesting reflowed into a valid one, a mis-indented fence normalized into a different block) have no detector and remain audit-layer residual on this row. |
| Off-the-shelf Tool | None, and the shape of the gap is the point: prettier is the AGENT of this failure, not a candidate detector. A formatter cannot flag input it exists to normalize, and its `--check` mode answers "does this match my output?" — exactly the question that returns yes once the corruption is stable. |
| Failing Example | Two live instances, independently authored, neither caught by any gate. (a) This catalog's own CAT-10 Hook cell during PR #267 prep: an unescaped `\|\| true` split the cell, so prettier rewrote the table with a 4-column delimiter row, demoted backticked `__tests__` to bold, and ate spaces at the new split boundaries — and the result was prettier-STABLE, leaving the zero-net-line check, `prettier --check`, and the docs-corpus runner all structurally blind; a human reading the commit caught it. (b) `Spec-015 §NTP Sync Precondition`: `<env \| file>` written unescaped inside a code span widened its row to 4 cells against a 3-cell header, and the delimiter row was then "repaired" to 4 columns to match it. Per the [GFM tables extension](https://github.github.com/gfm/#tables-extension-) (fetched 2026-07-28), a delimiter row that does not match its header means "a table will not be recognized" — so that matrix in an `approved` spec had been rendering as a paragraph of literal pipe text, never as a table, since it was written. Repaired in PR #269, the PR that registered this row. |
| What Discipline Restores Correctness | Escape the delimiter: a backslash immediately before the pipe is the only way to keep a literal pipe inside a GFM cell, and a backtick does NOT shield it — a code span is not a parsing boundary for the cell delimiter, which is the single fact both authors above did not have. Never reconcile an arity complaint by widening the delimiter row; that is the move which converts a one-character typo into a permanent structural lie. Generally: when a formatter's output surprises you, re-read the SOURCE structure before accepting the reformat, because the formatter has already voted and it only ever votes for its own output. |

## Known Limitations

- **Slug-algorithm divergence on niche Unicode — RESOLVED 2026-07-09.** lychee's filter and GitHub's slugger strip math-symbol characters (U+2192 `→` included), but the strip class in [`tools/docs-corpus/lib/slug.ts`](../../tools/docs-corpus/lib/slug.ts) was a truncated snapshot ending at U+205E — it KEPT the arrow, so for this character class the local slug diverged from what GitHub actually renders (authority inverted from this row's original claim). First live exercise 2026-07-08: the ADR-015 `### Amendment 2026-07-08: V1.1 deferred features 3 → 2 …` heading carried 14 inbound `…-3--2-…` fragment anchors across 11 files — all GitHub-correct, all lychee-validated, all computed WRONG by the then-current `slug.ts`. Resolution: the verbatim strip regex is spliced from the packaged `github-slugger@2.0.0` (root devDependency), the dedup walk mirrors upstream's collision algorithm, and the pin is CI-enforced — the oracle suite in `tools/docs-corpus/__tests__/slug.test.ts` asserts parity with the package over every committed corpus heading plus adversarial unicode, so a future truncation or paste error fails tests instead of silently re-inverting the authority. GitHub/lychee remain authoritative for rendered anchors; the local slug now agrees.
- **Doc corpus lacks a stable identifier system.** Heading text is being used as a stable identifier — a known design weakness. Long-term fix is to give each BL / NS / catalog item a slug-stable shortname (e.g., `<a id="bl-107"></a>` HTML anchors that don't depend on heading text). Out of scope for this catalog.
- **Mermaid graph IS the source of truth; prose enumerations are not generated from it.** Long-term fix is a build step that emits the prose enumeration from the graph. Out of scope for this catalog.

## Detection-layer matrix

| Layer | Runs on | Latency | Determinism | Cost |
| --- | --- | --- | --- | --- |
| pre-commit hook | every `git commit` | <5s p99 | bit-for-bit | $0 |
| CI workflow | every PR + push to develop / main | minutes | bit-for-bit | $0 |
| `/ripple-check` skill | author-invoked | 30-120s | probabilistic | $0.50-3.00 |
| audit prompt | plan-readiness audit | minutes | model-dependent | $0.10-1.00 |

The four layers are complementary, not redundant. Static hooks remove human-in-the-loop entirely for the deterministic 80%; the skill catches the residual 20% on demand. CI is the authoritative gate (matches branch-protection's `required_conversation_resolution` semantics from ADR-023).
