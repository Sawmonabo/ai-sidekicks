# Failure-Mode Catalog

> **Doc shape note.** This is a process-methodology catalog (proactively invoked during commit / PR / review), not a failure-recovery runbook. The 10-section operations template (`docs/operations/template.md`) does not apply; the structure here is one row per failure pattern, indexed on **structural action**. The same convention is used by [`plan-implementation-readiness-audit-runbook.md`](./plan-implementation-readiness-audit-runbook.md), which is also a methodology doc rather than a recovery procedure.

## Purpose

Every row indexes one regression pattern — in the doc corpus itself, or in the tooling that guards it — by **structural action** (what the change physically does, to the corpus or to a gate) so disciplines, hooks, skills, and audit prompts resolve to the same canonical row regardless of which **domain framing** the author used. CAT-01 through CAT-09 are corpus-regression rows; CAT-10 is the gate-integrity row, admitted here rather than in a registry of its own because this catalog is explicitly the single source of truth for rows that hooks and skills address by `CAT-NN`. This fixes the recall-by-domain-label miss documented in the PR-#27 post-mortem: the canonicalization-sweep-completeness discipline existed but did not fire for the surface label `archival` because the human framing was `archival` while the structural action was `string move`.

The catalog is the single source of truth. Hooks, skills, and audit-prompts reference catalog rows by ID (`CAT-NN`); adding a new failure pattern means adding one row plus wiring detection — there is no parallel registry.

## How to use

1. **Authoring an edit.** Read the row whose **Structural Action** matches what your edit physically does. The "What discipline restores correctness" cell names the pre-commit / CI / audit / human action you owe.
2. **Adding a new failure pattern.** Insert one row indexed on the structural action, never on the domain label. List the domain framings that triggered the discovery as **Surface-Label Aliases**. Wire detection (file path or skill name); a row with no detection-layer wiring is documentation theater.
3. **Skill `/ripple-check`.** Walks the catalog at runtime, identifies which rows' structural-action signals are present in the staged diff, and dispatches up to five parallel subagents — one per related-row group (A=CAT-01/02, B=CAT-03/04, C=CAT-05 broad, D=CAT-06/07) plus one cross-document coherence subagent (E) that audits the residual not keyed to any single row. CAT-08, CAT-09, and CAT-10 fire no subagent, for two different reasons. CAT-08 and CAT-09 are each fully covered by a deterministic hook (`lychee` at CI for CAT-08; `table-total-coherence` at pre-commit + CI for CAT-09), so a subagent would duplicate settled work. CAT-10 is the opposite case: it has no doc-diff signal to key a subagent on, because the regression lives in a gate rather than in the corpus the diff touches — it is discovered in review and closed per instance by a gate of its own. The within-document arithmetic is the deterministic slice of CAT-05's broader "table row added / removed" set change; that broader set-quantifier ripple still dispatches Subagent C (CAT-05).
4. **Audit-prompt augmentation.** Plan-readiness audit prompts include the line "walk every catalog row marked Detection-layer=audit and re-derive the claim from primary source".

Floor cases (file truncation) caught by hook; semantic cases are CAT-07. <!-- cite-shape-example --> |

(b) **Bare `:NNN` riding an earlier cite's basename** — `MixedVersionStatus.tsx:64` carried `", :581"`, a second locator with no basename of its own, invisible to every basename-keyed pattern (covering pattern: `[,(] ?:[0-9]+`); the instance had ALSO drifted two lines (true target :583), proving the class hides real drift, not just style debt. 2026-07-27 (PR #256, four instances): the **stale-forward-reference** shape — a multi-surface amendment whose surfaces land in a fixed order, where an earlier-written surface still describes the later one as pending. The covering layer is a near-deterministic INTERSECTION rather than a semantic read: (a) the `§Heading` anchors whose target section this diff modifies, against (b) inbound citers of those anchors whose surrounding sentence carries a pending-state token (open / not yet / to be decided / pending / will be / awaiting / "the other half"). That is scriptable against the staged diff and strictly narrower than CAT-07's general semantic residual. <!-- cite-shape-example --> |

### CAT-09 — Table-total arithmetic drift

| Field | Value |
| --- | --- |
| Structural Action | A data row is added / removed / re-counted in a table marked `<!-- corpus:total-check column="…" -->`, or a declared total is edited, so the summed column no longer equals the in-table **Total** row or a bound `prose-total` restatement. | Hook | [`tools/docs-corpus/lib/table-total-coherence.ts`](../../tools/docs-corpus/lib/table-total-coherence.ts) re-sums the marked column against the in-table **Total** row and every bound `prose-total` (both the `<label>: N` colon form and the `N-<label>` prefix form). Composed into [`tools/docs-corpus/bin/pre-commit-runner.ts`](../../tools/docs-corpus/bin/pre-commit-runner.ts) for the corpus lanes; the standalone [`tools/docs-corpus/bin/table-total-check.ts`](../../tools/docs-corpus/bin/table-total-check.ts) runs the same check in isolation for the audit runbook's gate G7. |
| Off-the-shelf Tool | None — summing a marked GFM column against a declared total is corpus-specific; no general linter does it. |
| Failing Example | PR #152 (Tier-6 plan-readiness audit), round 19: a prose restatement of the Spec-006 event-type total disagreed with the column it summarized while the in-table **Total** row stayed correct, so a Total-row-only check would have passed and missed it. ### CAT-10 — Gate reports clean over work it did not do

| Field | Value |
| --- | --- |
| Structural Action | A check, gate, or test runner emits a passing verdict for a screen that never ran: an empty match set read as a clean result, a guard whose predicate can never fire, or a scan whose input was silently truncated before it was measured. Distinct from a check that runs and reaches the wrong answer — here the verdict rests on no evidence at all, so the usual "it passed, so it was checked" inference is what breaks. |
| Surface-Label Aliases | "silently disabled", "false clean", "vacuous pass", "the suite is green but empty", "the hook never fires", "0 findings". |
| Detection Layer | CI, per instance — every shipped closure runs in a CI test job; none of them run in the lefthook pre-commit chain, so a local commit that regresses one of these gates still commits cleanly. |
| Hook | **No class-level detector exists**, and claiming one would be this row's own failure mode: nothing screens a diff for "this gate will report clean over work it did not do". What is wired is one closure per shape. **Zero-match test runs** — [`tools/run-node-tests.mjs`](../../tools/run-node-tests.mjs) refuses to spawn when any pattern resolves no files, which covers every caller routed through it; `--min-files=N` adds an opt-in floor above that refusal for callers that declare one. **Bin-script entry guards** — [`tools/__tests__/entry-guard.test.mjs`](../../tools/__tests__/entry-guard.test.mjs) `spawnSync`s each guarded CLI through a spaced, symlinked path, because a unit test that imports the exported logic bypasses the guard under test and silently re-creates the defect it is meant to catch. That fixture list is itself re-derived from the source tree on every run and fails when a guarded script is missing from it — the hand-maintained list had been an instance of this very row, enumerating only `.mjs` and therefore never spawning the three guarded TypeScript CLIs, `pre-commit-runner.ts` (the whole lefthook docs-corpus gate) among them. **Gate-4 cite screen** — its instances are closed inside [`preflight.mjs`](../../.claude/skills/plan-execution/scripts/preflight.mjs) and specified in [`preflight-contract.md`](../../.claude/skills/plan-execution/references/preflight-contract.md). |
| Off-the-shelf Tool | None. Coverage tools measure which code the tests executed; nothing generic measures whether a GATE's input set was non-empty, and a gate over zero inputs is exactly what coverage cannot see. |
| Failing Example | PR #259: `node --test` given a glob that matches nothing exits 0 printing `# tests 0`, and an entry guard comparing `import.meta.url` against a `file://` URL built from `process.argv[1]` by string equality no-ops on any spaced or symlinked path, disabling the script it protects. PR #260 then found TWELVE more in one screen, every one the same shape — a nullish default converting "could not determine" into "determined to be empty" (`?? []`, `?? planCount`, `?? ""`, and an `indexOf` miss falling through `-1` into `slice(0)`). The most instructive: a plan whose cite screen THREW stayed inside `surveyedPlanCount`, so the coverage line counted it swept, the markerless screen called the unrun check a vacuous pass, and the stale-exemption ratchet advised deleting a live exemption on evidence never gathered — a false clean that went on to produce a confident recommendation. |
| What Discipline Restores Correctness | Make the empty case loud at the point of measurement rather than at the consumer: report "could not determine" as an outcome distinct from "determined to be clean", and never let a nullish default collapse the two. Concretely — floor the input count (`--min-files`); mask non-content input instead of deleting it so offsets survive; mark a unit UNCOVERED when its screen throws instead of letting the catch fall through into the swept tally; and apply the fix inside the leaf function rather than at the call site, so a later caller cannot reopen it. When auditing an existing gate, feed it a known-bad input in the same run: a zero-findings result is evidence only once the checker has been proven able to fail. |

## Known Limitations

- **Slug-algorithm divergence on niche Unicode — RESOLVED 2026-07-09.** lychee's filter and GitHub's slugger strip math-symbol characters (U+2192 `→` included), but the strip class in [`tools/docs-corpus/lib/slug.ts`](../../tools/docs-corpus/lib/slug.ts) was a truncated snapshot ending at U+205E — it KEPT the arrow, so for this character class the local slug diverged from what GitHub actually renders (authority inverted from this row's original claim). First live exercise 2026-07-08: the ADR-015 `### Amendment 2026-07-08: V1.1 deferred features 3 → 2 …` heading carried 14 inbound `…-3--2-…` fragment anchors across 11 files — all GitHub-correct, all lychee-validated, all computed WRONG by the then-current `slug.ts`. Resolution: the verbatim strip regex is spliced from the packaged `github-slugger@2.0.0` (root devDependency), the dedup walk mirrors upstream's collision algorithm, and the pin is CI-enforced — the oracle suite in `tools/docs-corpus/__tests__/slug.test.ts` asserts parity with the package over every committed corpus heading plus adversarial unicode, so a future truncation or paste error fails tests instead of silently re-inverting the authority. GitHub/lychee remain authoritative for rendered anchors; the local slug now agrees.
- **Doc corpus lacks a stable identifier system.** Heading text is being used as a stable identifier — a known design weakness. Long-term fix is to give each BL / NS / catalog item a slug-stable shortname (e.g., `<a id="bl-107"></a>` HTML anchors that don't depend on heading text). Out of scope for this catalog.
- **Mermaid graph IS the source of truth; prose enumerations are not generated from it.** Long-term fix is a build step that emits the prose enumeration from the graph. Out of scope for this catalog.

## Detection-layer matrix

| Layer | Runs on | Latency | Determinism | Cost |
| --- | --- | --- | --- | --- |
| pre-commit hook | every `git commit` | <5s p99 | bit-for-bit | $0 |
| CI workflow | every PR + push to develop / main | minutes | bit-for-bit | $0 |
| `/ripple-check` skill | author-invoked | 30-120s | probabilistic | $0.50-3.00 |
| audit prompt | plan-readiness audit | minutes | model-dependent | $0.10-1.00 |

The four layers are complementary, not redundant. Static hooks remove human-in-the-loop entirely for the deterministic 80%; the skill catches the residual 20% on demand. CI is the authoritative gate (matches branch-protection's `required_conversation_resolution` semantics from ADR-023).
