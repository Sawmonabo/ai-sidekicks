# macOS Service Probes

The probes [Plan-005 §Phase R3 — Client Delivery](../plans/005-local-ipc-and-daemon-control.md#phase-r3--client-delivery) owes on a Mac, for the system service that keeps the background service running while the person is logged out, which `sidekicks daemon install --while-signed-out` installs ([Spec-006 §The service on a Mac while logged out](../specs/006-local-ipc-and-daemon-control.md#the-service-on-a-mac-while-logged-out)).

## Phase R3 — probes owed on a Mac

Each runs on a Mac before macOS's `--while-signed-out` is built (T-005r-3-11), as the person, with an administrator at hand for the one password. Apple's service manager registers a system service only for a notarized app ("Apps that contain LaunchDaemons must be notarized", `SMAppService.h` in the macOS 27.0 SDK), which the app is not, so the service is installed the old way: each row installs its test service as a property list in `/Library/LaunchDaemons` naming a small compiled test program in `/Library/PrivilegedHelperTools/`, behind one `osascript … with administrator privileges` prompt, and the test program starts as root, takes its account with `getpeereid(3)` and gives up root as [Spec-006 §The service on a Mac while logged out](../specs/006-local-ipc-and-daemon-control.md#the-service-on-a-mac-while-logged-out) says. Nothing changes a system setting except where the row says so, and those are reverted after. A fact Apple or a provider already documents is cited where the design states it, not probed: that launchd stops every user agent at logout ([Creating Launch Daemons and Agents](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingLaunchdJobs.html)), that a process outside a user context reaches only the System keychain ([TN3137: On Mac keychains](https://developer.apple.com/documentation/technotes/tn3137-on-mac-keychains)), and that Claude Code keeps a login in `.credentials.json` when the keychain rejects its write ([Claude Code §Credential management](https://code.claude.com/docs/en/authentication#credential-management)).
