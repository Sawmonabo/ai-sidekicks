## 1. Purpose & non-goals

### 1.1 Purpose

This document is the design contract for the **capability-enhancement integration campaign**: a sequenced program of governance-document amendments that designs all **34 adopted enhancement-corpus items** (P0 × 6, P1 × 10, P2 × 10, P3 × 8) **plus the seven R8 CLI-parity capabilities** (§3.4 Class-B, §5.1) into the V1 corpus — specs, plans, ADRs, contract docs, schema docs, and the cross-plan ownership map — so that each owning plan's own later `/plan-execution` run ships the code. The campaign's output (R9 two-bucket model): 23 governance-bundle PRs across four doc waves (W0: 1, W1: 10, W2: 10, W3: 2), per-plan targeted re-audit promotion PRs (W2.5), **and one prerequisite-code PR (W4: B23 — the bucket-1 code the pipeline needs before its next steps)**, including two net-new governance docs (Spec-028 / Plan-028). All other code (bucket 2) ships at each owning plan's own execution slot with its tasks already specified by this campaign.

The campaign simultaneously repairs the **phantom-reference class** a full-corpus audit surfaced (five phantom file references, one same-basename near-collision, four citation-drift defects, and four ownership-map gaps — §3), because the campaign's binding exit criterion is:

> **No phantom, no unwired — at V1 completion.** Every file/symbol referenced by any plan has exactly one CREATE owner; every enhancement designed in is reachable in the running app through a named consumer chain.

### 1.2 Non-goals (carve-out boundary)

- **Bucket-2 enhancement code (R9).** Except the bucket-1 prerequisite code (W4/B23), every code change enumerated here ships through its owning plan's own reviewed `/plan-execution` run at its natural slot — the campaign amends the governing docs those runs execute from, so each item is fully specified where it will be built.
- **Adjacent dormant backlog items.** [BL-144](../../backlog.md) (Plan-008 SSE concurrency cap) and [BL-145](../../backlog.md) (Plan-012 approval rate-limit wiring) sit next to campaign targets but are outside the 34-item corpus; the campaign's Plan-008/Plan-012 bundles stay disjoint from their scopes.
- **Plan-024 Phases 4–5.** CI cross-compile, signing, and the Windows default-flip remain procurement-bound ([BL-108](../../backlog.md), §6 nodes NS-09/NS-10). The campaign's new Phase 3B (§4, B16) is deliberately independent of them.
- **Re-litigating corpus rulings.** The enhancement corpus's accuracy-reviewed rulings are adopted as-is except where this campaign's own verification passes surfaced factual corrections (§3.2) or the user issued explicit course corrections (§1.3). Each such refinement is recorded with its evidence.
