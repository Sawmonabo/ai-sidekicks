# crates/sidekicks-cli — command-line rules

Applies to every change under `crates/sidekicks-cli/`, the `sidekicks` command line, on top of the [root `AGENTS.md`](../../AGENTS.md) and [`crates/AGENTS.md`](../AGENTS.md), which this file never restates.

## Exit codes and output

- **Exit codes (the CLI):** `main` returns `std::process::ExitCode`; a failure maps to a BSD `sysexits.h` code: `64` usage (and a daemon `-32600`, `-32601` or `-32602`), `65` malformed data (a daemon `-32700`), `69` the daemon not answering, `70` an internal failure (a daemon `-32603`). A daemon `-31000` refusal maps by its `data.category`, in one `match` over the categories `docs/architecture/contracts/error-contracts.md` lists: `invalidArgument` `65`, `notFound` `66`, `alreadyExists` `73`, `failedPrecondition` `78`, `permissionDenied` and `unauthenticated` `77`, `aborted`, `resourceExhausted` and `deadlineExceeded` `75`, `unavailable` and `unimplemented` `69`, `internal` `70`, and `canceled` the Ctrl-C ending. Ctrl-C stops only the `sidekicks` command in that terminal: it cancels only what that command waited on (as `account login` sends `account.signInAttempt.cancel`), and the background service, every session and every workflow keep running. The command then ends the way a Ctrl-C does, so a script running it stops too: on macOS and Linux it puts SIGINT's default action back and raises it (`signal_hook::low_level::emulate_default_handler`), which the shell reads as `130`, and on Windows it exits `0xC000013A` (`STATUS_CONTROL_C_EXIT`), each behind `sidekicks-platforms`' interface. A daemon `-32800` or a `canceled` refusal after the command's own cancel takes that same ending through its arm of the exhaustive `match`, which has no default arm; the CLI calls no method that answers `canceled` unasked. A panic is caught once at the top with `std::panic::catch_unwind` and returns `1` for `daemon update --check` (which exits `0` up to date, `100` update waiting, `1` could not check) and `70` elsewhere, so the CLI's native profile stays `panic = "unwind"`. Output goes through `writeln!` on a locked stdout, never `println!` (it panics on a closed pipe), and `ErrorKind::BrokenPipe` returns `141`. Arguments are parsed with `Command::try_get_matches_from` (`Parser::try_parse_from` in the derive form), never `get_matches` or `Error::exit`: a `clap::Error` whose `exit_code()` is 0 (help, version) is written to stdout and exits 0, any other is written to stderr and exits `64` (usage), a bare `sidekicks` among them. Its text is rendered into the run's injected writers, never through clap's `print()`, in clap's styles only when the stream it goes to shows them, which `main` decides for each real handle as clap's own output does, through `anstream`'s `AutoStream::choice` (`NO_COLOR` keeps it plain, else `CLICOLOR_FORCE` styles it, else `CLICOLOR=0` keeps it plain, else a terminal that shows colors or runs under a truthy `CLICOLOR` or `CI` does), keeps a terminal plain whose escape codes `anstyle-query` cannot turn on (a Windows console without them), and passes to the program as one flag per stream, and plain otherwise; that write failing with `ErrorKind::BrokenPipe` exits `141`, so `sidekicks --help | head -1` exits 141.
