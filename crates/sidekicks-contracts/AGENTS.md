# crates/sidekicks-contracts — wire contract rules

Applies to every change under `crates/sidekicks-contracts/`, the wire's one source, on top of the [root `AGENTS.md`](../../AGENTS.md) and [`crates/AGENTS.md`](../AGENTS.md), which this file never restates.

## Wire contracts (`sidekicks-contracts`)

The Rust types are the one source; TypeScript types and validators are generated from them.

- **Instants** stored or sent are written `Timestamp::strftime("%Y-%m-%dT%H:%M:%S%.3fZ")` in UTC (`jiff`), always three fractional digits, so text order and the canonical bytes hold; an incoming `occurredAt` is parsed component by component (an uppercase `T`, then `Z` or an offset, `-00:00` among them; seconds optional, `00` to `59`, so no leap second; any fraction length, a non-zero digit past the third refused and trailing zeros folded; a year outside four digits refused), its date checked with `jiff::civil::Date::new`, never by jiff's or chrono's RFC 3339 parser, whose accept sets differ (both take a lowercase `t` or a space; chrono refuses omitted seconds); one test covers `.000`, `.5`, `.5000`, an offset, `-00:00`, omitted seconds, `.0001`, a lowercase `t` and a leap second.
- **An incoming instant** is a `WireInstant` newtype whose garde `pattern` and JSON Schema `pattern` are one RFC 3339 pattern with offset (`INSTANT_PATTERN` in `wire/instant.rs`), anchored `^…$`, every digit class written `[0-9]`; never `format: "date-time"` and never jiff's parser alone, which takes `,` as the decimal sign. It keeps the text as received; a handler that compares or computes parses the checked text with `jiff::Timestamp`, dropping fraction digits past the ninth first. An incoming `occurredAt` also keeps the stricter rule above. One test refuses lower-case `t` and `z`, a space for `T`, `+0100`, `+24:00`, `23:59:60`, `2025-02-29` and a value without seconds, and accepts a ten-digit fraction.
- **`observedType`** is `"null"` for `Value::Null`, `"object"` for `Object` and `Array`, and `"boolean"`, `"number"` or `"string"` for the rest.
- **Platform and architecture** travel in Node's spelling: `Platform` (`darwin`, `linux`, `win32`) and `Arch` (`x64`, `arm64`) are contract enums with those serde names, and `sidekicks-platforms` returns the running ones from `cfg!(target_os = "macos")`, `cfg!(target_arch = "aarch64")` and the like; `std::env::consts` never reaches the wire or a release-manifest key (`darwin-arm64`, `linux-x64`).
- **Shape:** wire types use `#[serde(rename_all = "camelCase")]` and `deny_unknown_fields`, and a first-party enum's values are lowerCamelCase too (`waitingForApproval`), while a provider's or an outside standard's values stay as sent; types read from a provider stay tolerant. A union tagged on a wire field is an internally tagged enum (`#[serde(tag = "…")]`), its shared fields repeated per arm; an untagged union is an enum of closed structs; a file or message that holds exactly one of several facts, each a type of its own, is an externally tagged enum of newtype arms (`{"<fact>": {…}}`, the service's status file), where the one key names the fact and a second key is refused. serde takes an untagged union's first arm that reads, so no earlier arm reads a message meant for a later one: arms differ by a literal tag, a `Never` member or a member's JSON type, and an arm whose member is an array comes before one whose same member is a struct. Every arm is a struct variant, `Complete {}` and never `Complete` (serde ignores unknown fields on a unit variant). A member absent on one arm is `Option<Never>`, so TypeScript keeps `x?: never`. `flatten` is not used outside the kept-unknown types below; the members an arm repeats are written by one `macro_rules!` per contract.
- **Kept unknown members** ([ADR-017](../../docs/decisions/017-cross-version-compatibility.md)), the exceptions to Shape: the artifact publication payload and the artifact manifest carry no `deny_unknown_fields` and hold `#[serde(flatten)] rest: serde_json::Map<String, Value>`, the one allowed `flatten`, and an enum-valued member of either ends in a variant that keeps an unknown value (`#[serde(untagged)] Unknown(String)`, never `#[serde(other)]`, which drops it) or stays `String`; their schemas stay open (schemars marks a flattened map's parent open) and the closing pass skips them. The stored event envelope's `type` is a newtype over its text, so a newer producer's type is kept as a version stub, and its `payload` is a `serde_json::Map<String, Value>`, which keeps every member and canonicalizes to the bytes the stub keeps (the canonicalizer refuses `RawValue`); the strict `SessionEvent` is parsed from an envelope's `type` and `payload` when it is read, and Ajv reads the envelope tolerant and the event strict. One test round-trips an unknown member through each artifact type and keeps it.
- **Optional and nullable,** one attribute set each; a plain `Option<T>` never appears on the wire, since serde reads it as absent-or-null, which no contract means:
  - absent allowed, `null` refused: `Option<T>` with `#[serde(default, skip_serializing_if = "Option::is_none", deserialize_with = "wire::present")]` and `#[schemars(with = "T")]`;
  - `null` allowed, the key required: `#[serde(deserialize_with = "wire::nullable")]` and `#[schemars(with = "wire::NullableSchema<T>")]` (never `#[schemars(required)]`, which emits the non-null `T`);
  - both: `Option<Option<T>>` with `#[serde(default, skip_serializing_if = "Option::is_none", with = "serde_with::rust::double_option")]`, so absent, `null` and a value keep their three meanings in both directions; a member the service sends to a provider whose wire gives those three meanings takes the same set, and a test serializes each state.
- **Scalars are newtypes with private constructors** whose JSON Schema carries the same rule: a cap counts what its owner counts: a text cap in code points (`chars().count()`, as the generated Ajv validators count `maxLength`, so the daemon and the desktop refuse the same text; a cut at `char_indices().nth(max)`), a byte budget in UTF-8 bytes (`str::len()`: `contentLength`, a JSON-encoding budget counted as below; a part's offset checked with `is_char_boundary`) cut at a character boundary (`floor_char_boundary`), and a provider's own cap in its own unit (UTF-16 where it counts that, `encode_utf16()`), and a member reporting a cut value's original length counts in its cap's unit; whitespace is the ECMAScript `\s` set spelled out, no NUL; `SafeInt` stays within 2^53 − 1; every integer has an explicit range; bytes are `Bytes<MIN, MAX>`. A resume position into a stored body (`transcript.body.read`'s `offset`, a patch cursor) is the exception to the UTF-16 rule that follows: a UTF-8 byte offset, refused unless `str::is_char_boundary`. An offset into text counts UTF-16 units (`encode_utf16()`), as JavaScript indexes, and a list of text sorted as JavaScript's bare `.sort()` sorts it, whose order is stored, sent, hashed or decides which file wins, is ordered by UTF-16 code units (`left.encode_utf16().cmp(right.encode_utf16())`; `str` order differs once a character above U+FFFF meets one in U+E000–U+FFFF), a list that holds only ASCII keeping `str` order. No inline `(?i)` regex flags: a pattern spells its case out, as the UUID pattern takes `[0-9a-fA-F]`. Nor does a pattern use `\d`, `\D`, `\w`, `\W`, `\b`, `\B` or `.`, which Rust's `regex` reads as Unicode classes and JavaScript as ASCII: it spells the class out (`[0-9]`, `[A-Za-z0-9_]`), and any character but a line break is `[^\n\r\u2028\u2029]`, so Rust and Ajv's ECMA-262 engine accept the same strings. A record-typed map refuses the key `__proto__`, in the schema too (`propertyNames`), so no TypeScript reader meets it.
- **A cap on a value's JSON size** is the byte length `JSON.stringify` gives, counted without building the text: `serde_json`'s serializer over a counting writer, its numbers in ECMAScript form through `ryu-js`; never `serde_json::to_vec(…).len()`, which writes `1.0` where JavaScript writes `1` and `1e+20` where it writes `100000000000000000000`. `serde_json_canonicalizer` is for hashes and signatures.
- **Bytes** travel beside the JSON as attachments: a `Bytes<MIN, MAX>` field is `{"$bytes": index}` on the wire, its schema a `$ref` to `Bytes` with `minBytes`, `maxBytes` and `tsType: "Uint8Array"`. Ajv registers both size keywords with `passContext: true`, and every TypeScript caller passes `{attachments}`. The decoder refuses an attachment used twice or never used, a rule of the message checked once in each side's frame decoder.
- **Hashes and signatures over JSON** are over `serde_json_canonicalizer::to_vec` bytes (RFC 8785), never `serde_json::to_vec`; a value hashed through it is held as `Value` or typed structs, never `RawValue`, which it refuses.
- **Rules no shape holds** are `garde` checks, each with the same rule in the schema (`#[schemars(extend(…))]`), so TypeScript enforces it without a hand copy. A garde message never quotes the value it refuses. A type gaining its first rule derives the check, and every type holding it dives into it. The one exception is the schema a model's tool listing shows, which carries no rule at its root: the twin stays in the type's own schema, which the received check reads, and the listing states the rule in words (below).
- **A message a server receives** (the daemon's requests and notifications, an attachment message's typed body, an agent tool's arguments, the control plane's calls) is read as a `serde_json::Value`, checked against its contract schema's shape with `jsonschema` (`schema::received_check`, each validator built on first use and held; `wire::attachment::parse_received` for a framed message), read with `from_value`, then held to its garde rules: serde reads a JSON array as a struct and no serde setting refuses that, where the shape refuses it as Ajv does. The shape (`schema::received_shape`) keeps the structural keywords, writes every union and every `if`/`then`/`else` as an `allOf` rule (a tagged union as one `if`/`then` per arm keyed on its tag; a union of `null` and one arm as `if` null, `else` the arm; any other as `if` its arms, `else: false`), and drops every value rule, an Ajv `$data` among them, since `jsonschema` cannot read `$data`; so each rule a received type's schema carries has its garde or newtype twin. A reader takes `validate`'s one error, never `iter_errors` or `evaluate`, so a malformed message costs no more than its read. The daemon's dispatch parses a request once and hands the handler the value. A reader of the daemon's own output keeps `from_slice`.
- **An agent tool's input type** (`rmcp`'s `#[tool]`) is read through the tool route's own `Received<T>` extractor, which runs the received check above, never `Parameters<T>`, a plain serde read; each tool names its schema with `#[tool(input_schema = …)]`, taken from `schema::listed_schema_for`, which writes every subschema in place and keeps at the root only `type`, `properties`, `required` and `additionalProperties`: Claude Code flattens a root `anyOf`, `oneOf` or `allOf` and the API refuses one, and Codex drops a root `if`, `not` or `dependentRequired`, so a rule between members is written in the tool's or the field's description instead. The text the model reads for a field, its pattern, length and bounds in words, is that field's `#[schemars(description = "…")]`, never starting with `#` (schemars makes a leading `#` line the title), and its `///` doc keeps to one or two sentences.
- **One schema per contract module** (`schemars`, draft 2020-12), closed by the project's closing pass (`unevaluatedProperties: false` on the outermost object; `#[schemars(inline)]` on struct arms reached through `$ref`). From it come the TypeScript types (`json-schema-to-typescript`; a brand or an Ajv `$data` value takes `tsType`) and the validators (Ajv 2020, strict, every `format` and custom keyword registered, compiled to standalone code at build time).
- **Methods and refusals:** every method is declared once in the contracts crate's method table (params, result, refusal codes), and the TypeScript method map is generated from it. Refusal codes are one Rust enum, each code with its category and its HTTP status, emitted as a TypeScript string union; every refusal answers `-31000` with its code in `data.type` and its category in `data.category`. Every method, event and refusal name follows the wire grammar, which one `const fn is_wire_name` in the contracts holds (with `is_protocol_method_name` for `$/` names); `methods!`, `refusal_codes!` and `session_event_types!` assert each name they declare against it at build time, as do the hand-built descriptors `DaemonHandshake` and `SubscriptionCancel`, and `sidekicks-ipc`'s method registry checks only for a name registered twice. garde's issue paths are mapped to the wire's names once, in `sidekicks-contracts`' `jsonrpc::issue`, which the daemon and the client call, never by a per-field rename.
- **Generated TypeScript** is committed into `packages/contracts/src/generated/`, served at `@ai-sidekicks/contracts/<topic>/<module>` by the package's `exports`, with a "generated" header, formatted by the repo's Prettier in the same step, never edited by hand; CI regenerates it and fails on `git diff --exit-code`.
- **Constants** a TypeScript client reads as values are declared once as `pub const` in the contracts module that owns them and listed in that module's one `ts_constants!` table; the schema pipeline writes each into its module's generated file as `export const NAME = <value> as const;` (the value through `serde_json`): `MACHINE_SETTINGS_DEFAULTS`, the size caps and bounds, every closed set a client iterates (written from the enum's variants), every refusal code a client compares (beside its union) and the `JsonRpcErrorCode` object. The `*_METHOD_DESCRIPTORS` a client imports are the method map the method table generates, at their names and paths.
- **Hand-written TypeScript** is only what a schema cannot carry: the three registered `format` functions (`https-url`, `site-origin`, `web-url`), the frame decoder's attachment rule, the frame encoder's `toWellFormed()` on every string, the `EventCursorUnresolvableError` class, `SessionStreamFrameSchema` (a generic factory over the generated frame schema), and every function a TypeScript client imports, each in a hand-written module of its own in its topic folder, among them the five helpers (`parseWorkflowHandle`, `foldName`, `webAddressFault`, `decodeArtifactPayloadText`, and `composeAppLink` with `parseAppLink`, whose Rust form `sidekicks-contracts::app_link` serves `sidekicks open`, the TS pair taking its id checks from the generated validators), the event cursors, page fitting and JSON byte length, the transcript run-fact, turn-attribution and content readers, the run folder (`resolveDaemonRunFolder`, which desktop main's supervisor calls, its Windows arm resolving from the local application data folder and the user's SID, and `refuseWindowsDaemonRunFolder`, which the Windows operating-system objects name while neither reads the user's SID), process identity, the platform check, account labels, the provider-model lookup, the repair line and artifact payload decoding. `parseMachineSettingsFile` checks the file with the generated validator after the hand-written `overDefaults` lays it over `MACHINE_SETTINGS_DEFAULTS`. It all lives in `packages/contracts/src`, outside `generated/`. Where the daemon or the CLI runs the same rule, its Rust function writes one case table, `crates/sidekicks-contracts/tests/fixtures/<topic>.json`, that both test suites read, so the two copies cannot drift, and a new function the daemon also runs comes with its table; every other piece is tested against examples the Rust side writes.
- **Text a provider sends** (Claude Code's stdout and session files, Codex's socket, MCP servers) is read so that every line a provider writes parses: Claude Code is a JavaScript program, and JavaScript's `JSON.stringify` writes a lone surrogate as an escape, which `serde_json` refuses. Before `from_slice`, one pass gated by `memchr(b'\\', …)` walks the line's escapes left to right, each as one unit (`\\`, `\"`, `\/`, `\b`, `\f`, `\n`, `\r` and `\t` skip two bytes; `\u` reads four hex digits), keeps a high surrogate only when a `\uDC00`–`\uDFFF` escape follows at once, and overwrites a lone one in place with `\uFFFD`, the same six bytes, as the outbound `toWellFormed()` does; in valid JSON a reverse solidus occurs only as an escape's start (RFC 8259 §7), so the pass needs no quote tracking. Bytes that are not UTF-8 become U+FFFD through `String::from_utf8_lossy`. A line may nest deeper than `serde_json`'s 128-level recursion limit, which stays on: a frame is read into its top-level members as `RawValue`, each member then parsed on its own, so a member nested too deep for a value is left out and the frame's other members still read.
- **Framing:** JSON-RPC 2.0 messages in the one 10-byte-header frame codec, the same on the local socket and inside each Noise message, on the relay and on the direct path alike, so nothing above the carrier knows which one a channel is on. The frame codec has no cut-over kind: the cut-over is a channel-layer kind inside the sealed transport, beside rekey and read before the lane codec, each end's last message on the relay before it writes only on the direct path's data channel, so the relay sees no move; the lanes, call slots and subscriptions stay alive across it. Bytes go as attachments; each subscription has its own lane with receiver credit; `$/cancelRequest` is answered `-32800` with `data.type` `request.canceled`; terminal output travels as bytes. A subscription holds only its place, never a queue: it reads its next frame from the stored record at its cursor, or sends the newest state, when its lane has credit, so a slow reader costs no more than the one message its lane has begun; a connection holds at most 10,000 open subscriptions, a subscribe call past it refused with `connection.subscription.limitReached`, and a peer opening lanes past that bound is misframed; a connection holds at most `MAX_CALLS_IN_FLIGHT` (100) calls in flight, a figure that changes only with a new dated `protocolVersion`, each slot taken before dispatch and freed when its reply's last piece is cut, a call past it refused at once with `connection.call.limitReached`, a subscription cancel, a stop, a `daemon.ping` or a `terminal.write` taking no slot; a connection's writes to one shell are refused past `TERMINAL_WRITES_WAITING_LIMIT` (16) waiting with `terminal.write.limitReached`, each carrying at most `TERMINAL_WRITE_MAX_BYTES` (64 KiB).
