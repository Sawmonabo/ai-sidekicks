# crates/ — Rust rules

Binding for every change under `crates/`, on top of the [root `AGENTS.md`](../AGENTS.md), which this file never restates. It adds only what Rust needs.

## Layout and names

- **Every Rust crate lives in `crates/`, one level deep, its folder named exactly as its crate:** `crates/sidekicks-contracts/` holds the package `sidekicks-contracts`. Package names are kebab-case with the `sidekicks-` prefix; code reads them with underscores (`use sidekicks_contracts::…`). A program takes its crate's name (`sidekicks-daemon`); only two set `[[bin]] name`: the command line (`sidekicks`) and the macOS wake helper (`sidekicks-wake-helper`, a root program linking only `objc2-io-kit`'s `pwr_mgt` and talking only over its socket), which `sidekicks-platforms` builds.
- **A crate's TypeScript face** lives in its `packages/<name>` workspace package under its `@ai-sidekicks/*` name, imported by topic path (`@ai-sidekicks/contracts/preview/methods`), with no root `index.ts`.
- **Files and module folders are `snake_case`.** A module with children is `name.rs` beside `name/`, never `name/mod.rs`, tests included (a crate's integration binary is `tests/it/main.rs`, its helpers `tests/it/helpers.rs`). A file inside its namesake folder (`mcp/mcp.rs`) is still a defect.
- **Names follow Rust's API guidelines:** types, traits and enum variants `UpperCamelCase`; functions, methods, locals and modules `snake_case`; constants and statics `SCREAMING_SNAKE_CASE`. An acronym is one word (`JsonRpcMessage`, `Uuid`). No `get_` on a getter (`fn state(&self)`). Conversions: `as_` (cheap view), `to_` (copy), `into_` (consumes). Booleans read as questions (`is_held`, `can_take`). A trait takes no prefix. An identifier keeps its full name inside its module (`DaemonProcess` in `daemon`).
- **Operating-system code lives only in `sidekicks-platforms`,** in its `macos`, `linux` and `windows` modules and the `posix` module the first two share, behind one interface the core calls. No other crate holds a `cfg` on the operating system (`#[cfg(target_os = …)]`, `cfg!(windows)`, `#[cfg(unix)]`) or calls a platform API; where another crate needs a platform's behavior, `sidekicks-platforms` supplies it as a function or a value (`SHOULD_MEMORY_MAP_READS`, which the search index reads). How a system spells, joins and compares a path is `sidekicks_platforms::PathRules`, whose `PathRules::NATIVE` the platforms crate sets for the running system, with `resolve_path` and `resolve_path_against` beside it, so no caller checks which system it runs on. The direct path's operating-system pieces are its: the network watch's address set, the default-gateway read for the router's port mapping, and the Windows firewall rule's install and removal; `str0m`, `mdns-sd`, `crab_nat` and `igd-next` are cross-platform, so the daemon's `remote` module calls them without a `cfg`.
- **Provider code stays inside its own driver folder, `provider::driver::claude` and `provider::driver::codex`,** which `provider/driver.rs` declares privately beside the one table of providers, `PROVIDER_REGISTRATIONS`: one entry per provider, its descriptor and its driver's build, in the order the registry keeps, an id that repeats another or breaks the provider id pattern failing the build. A provider is its own folder and one entry in that table, so the compiler keeps every module outside `provider::driver` from naming a provider. That one provider's module never reaches the other's, that no shared module under `provider::driver` reaches either, and that only the daemon's start reads the table, are held in review.
- **A provider is an open id behind the driver interface:** shared code reaches a provider only through that interface and never branches on which provider or model it is, and what a screen names (the provider, its models, its settings) comes from the driver's descriptor and its live reads, so a provider added is one driver module and its entry in the table.
- **Every stored row id and event id is minted by the one `mint_uuid_v7`:** `clippy.toml`'s `disallowed-methods` lists `uuid::Uuid::new_v4`, `uuid::Uuid::new_v7` and `uuid::Uuid::now_v7`; `mint_uuid_v7` and each ephemeral token no row or event stores (a scratch file name, a subscription id, a terminal handle) carry `#[expect(clippy::disallowed_methods, reason = "…")]` at the call.
- **The read-side projectors** (`workspace::projector`, `git::worktree::projector`) and `provider::hand_over::brief::projection` take their inputs as arguments and read no clock, store, file or process; review holds it.

## Toolchain and manifests

- `rust-toolchain.toml` pins one exact stable release (`1.99.0`, profile `minimal`, `rustfmt` and `clippy`, target `wasm32-unknown-unknown`); `rust-version` names the same one, and CI installs what the file names. Moving to a new stable is its own PR, which fixes every lint it brings.
- A crate built to WebAssembly (`sidekicks-compression`, the matcher's build of `sidekicks-search`, the workflow checks' build of `sidekicks-contracts`) builds with the root `[profile.wasm-release]` (`panic = "abort"`, LTO, `strip`); the workflow checks' build strips debug info only, since the wasm-bindgen tool reads the link's `target_features` section.
- The root `Cargo.toml` holds the shared facts: `resolver = "3"`; edition 2024, `rust-version`, license and `publish = false` in `[workspace.package]`; every dependency version once in `[workspace.dependencies]`, internal crates by path. A crate writes `x.workspace = true` and `[lints] workspace = true`. Nothing sets lints through `rustflags`.
- **Turbo drives Cargo** through its Cargo support (`turbo` pinned exact): the root `Cargo.toml` names the workspace `sidekicks-crates` in `[workspace.metadata]`, no crate has a `package.json`, and no folder is both a crate and a pnpm package. A pnpm package that ships a crate's WebAssembly build depends on that crate's `build`, which the root `turbo.json` sets to `"command": null` so it carries only the crate's hash.
- **Dependencies between crates:** `sidekicks-contracts` depends on no workspace crate; `sidekicks-client` and `sidekicks-daemon` never depend on each other, and only `sidekicks-client-addon` binds the client to Node-API; the CLI never depends on `sidekicks-daemon` or `sidekicks-control-plane`. A crate uses another only through its `[dependencies]`, by path.

## Commands

`cargo fmt --all`, `cargo clippy --workspace --all-targets --all-features`, `cargo nextest run --workspace`, `cargo test --workspace --doc`, `cargo doc --workspace --no-deps`, `cargo shear`, `cargo deny check advisories bans sources`, `typos`, `tombi format`. CI sets `CARGO_BUILD_WARNINGS=deny`, so any lint warning fails it, rustdoc's included, and runs each Cargo command with `--keep-going` so every crate reports. `turbo run build lint test` drives Cargo beside the pnpm packages; the root `turbo.json` names `CARGO_BUILD_WARNINGS` in `globalEnv`, which Turbo otherwise withholds.

## Format and lints

- rustfmt with `style_edition = "2024"` and its defaults: 100 columns, 4-space indent. Comments wrap at 100 by hand. Imports sit in three groups (std, other crates, this crate), a blank line between.
- Clippy `pedantic` is on, with `must_use_candidate`, `missing_errors_doc`, `missing_panics_doc`, `too_many_lines` and `similar_names` allowed. Also on: `unwrap_used`, `panic`, `exit`, `todo`, `unimplemented`, `dbg_macro`, `print_stdout`, `print_stderr`, `allow_attributes`, `allow_attributes_without_reason`, `let_underscore_must_use`, `map_err_ignore`, `unused_result_ok`, `wildcard_enum_match_arm`, `mod_module_files`, `undocumented_unsafe_blocks`, `redundant_clone`, and `missing_docs_in_private_items` limited to `pub(crate)` items. Off on purpose: `expect_used` and `indexing_slicing` (they force branches for proven invariants) and `module_name_repetitions` (it flags `DaemonProcess`).
- rustc: `unsafe_code` denied; `missing_docs`, `unreachable_pub`, `dead_code_pub_in_binary`, `unused_lifetimes`, `redundant_lifetimes` and `unit_bindings` warn. `dead_code_pub_in_binary` is set in each program's `main.rs` (`#![warn(…)]`), never in the workspace table: rustc builds every library's unit tests as a program, where it would report each `pub` item the tests leave unused.
- **A suppression is `#[expect(lint, reason = "…")]`, never `#[allow]`;** the reason says why in plain words. One that no longer fires fails the build, so it is removed.

## Code

- **Errors:** a library crate defines its errors with `thiserror`; only `main` and the command line's top level use `anyhow`, with context. No `unwrap`, `panic!`, `todo!`, `unimplemented!` or `process::exit` in product code, except the `shell` mode's Windows middle process's one `process::exit`, which passes on the shell's 32-bit exit code that `ExitCode` cannot hold; `expect("why this holds")` states a proven invariant. `let _ =` never drops a `Result`, and `map_err(|_| …)` never drops a cause.
- **Exit codes (the CLI):** `main` returns `std::process::ExitCode`; a failure maps to a BSD `sysexits.h` code: `64` usage (and a daemon `-32600`, `-32601` or `-32602`), `65` malformed data (a daemon `-32700`), `69` the daemon not answering, `70` an internal failure (a daemon `-32603`). A daemon `-31000` refusal maps by its `data.category`, in one `match` over the categories `docs/architecture/contracts/error-contracts.md` lists: `invalidArgument` `65`, `notFound` `66`, `alreadyExists` `73`, `failedPrecondition` `78`, `permissionDenied` and `unauthenticated` `77`, `aborted`, `resourceExhausted` and `deadlineExceeded` `75`, `unavailable` and `unimplemented` `69`, `internal` `70`, and `canceled` the Ctrl-C ending. Ctrl-C stops only the `sidekicks` command in that terminal: it cancels only what that command waited on (as `account login` sends `account.signInAttempt.cancel`), and the background service, every session and every workflow keep running. The command then ends the way a Ctrl-C does, so a script running it stops too: on macOS and Linux it puts SIGINT's default action back and raises it (`signal_hook::low_level::emulate_default_handler`), which the shell reads as `130`, and on Windows it exits `0xC000013A` (`STATUS_CONTROL_C_EXIT`), each behind `sidekicks-platforms`' interface. A daemon `-32800` or a `canceled` refusal after the command's own cancel takes that same ending through its arm of the exhaustive `match`, which has no default arm; the CLI calls no method that answers `canceled` unasked. A panic is caught once at the top with `std::panic::catch_unwind` and returns `1` for `daemon update --check` (which exits `0` up to date, `100` update waiting, `1` could not check) and `70` elsewhere, so the CLI's native profile stays `panic = "unwind"`. Output goes through `writeln!` on a locked stdout, never `println!` (it panics on a closed pipe), and `ErrorKind::BrokenPipe` returns `141`. Arguments are parsed with `Command::try_get_matches_from` (`Parser::try_parse_from` in the derive form), never `get_matches` or `Error::exit`: a `clap::Error` whose `exit_code()` is 0 (help, version) is written to stdout and exits 0, any other is written to stderr and exits `64` (usage), a bare `sidekicks` among them. Its text is rendered into the run's injected writers, never through clap's `print()`, in clap's styles only when the stream it goes to shows them, which `main` decides for each real handle as clap's own output does, through `anstream`'s `AutoStream::choice` (`NO_COLOR` keeps it plain, else `CLICOLOR_FORCE` styles it, else `CLICOLOR=0` keeps it plain, else a terminal that shows colors or runs under a truthy `CLICOLOR` or `CI` does), keeps a terminal plain whose escape codes `anstyle-query` cannot turn on (a Windows console without them), and passes to the program as one flag per stream, and plain otherwise; that write failing with `ErrorKind::BrokenPipe` exits `141`, so `sidekicks --help | head -1` exits 141.
- **Stopping a child:** a child stopped with SIGTERM gets process-wrap's `ChildWrapper::signal(libc::SIGTERM)` on Unix, which reaches the child's own pid, never tokio's `kill()` or `start_kill()` (SIGKILL); a provider child is never wrapped in `ProcessGroup`, whose `signal` reaches the whole group and whose `wait` waits for every process in it. On Windows the stop ends the child's whole tree, as `taskkill /T /F` does: the child runs in process-wrap's `JobObject`, whose `start_kill()` is `TerminateJobObject`.
- **A child's exit crosses the wire as a signal name or a code:** an end by signal is read with `ExitStatusExt::signal()` and crosses the wire as its name, `nix::sys::signal::Signal::try_from(n)` then `.as_str()` (`SIGKILL`); a number the enum does not list (a Linux real-time signal) crosses as `SIGRTMIN+<n>`, the form signal(7) uses, which `sidekicks-platforms` names, never as exit code 0. A Windows exit code is `i64::from(code as u32)`, so a crash reads 3221225477. A missing code with no signal reads 0. On Windows a child the daemon itself ended (`start_kill`) crosses the wire with the name of the signal the stop asked for (`SIGTERM` or `SIGKILL`), and any other end with its exit code. A test checks that every signal the platform defines has a name. The exit is composed only after both `wait()` and the stderr reader's end. stderr is decoded across chunks: bytes are held until a whole UTF-8 sequence and decoded lossily once. The failure tail keeps the last 32,768 code points, the unit of the cap it fills, moved forward to the next grapheme boundary; the Codex proxy's stderr tail keeps its last 1,000 the same way. A shell's title takes whole graphemes up to 256 code points, and is cut at 256 code points only when one grapheme is longer than that. Every program a mode starts goes through `std` or `tokio` `Command` (`CommandExt::exec` where it replaces the process), never a raw `execvp`, so the child's SIGPIPE is back at its default, which std restores; the `shell` mode alone execs the program itself (below) and sets SIGPIPE back to its default itself first. A test runs `yes | head -1` through the command wrapper and in a shell, and reads no `Broken pipe` from either.
- **Spawning a child:** every child the daemon starts is spawned from one long-lived spawner thread, `sidekicks_platforms::Spawner` (made at start with `std::thread::Builder` and fed by a channel; the daemon makes it once and hands a cloneable handle to every crate that starts a child, and `run(job)` runs a closure there and answers through a oneshot), never from a tokio worker or `spawn_blocking`: Linux sends the parent-death signal when the thread that forked the child ends, and tokio's blocking threads end after 10 s idle. A `Command` child arms `PR_SET_PDEATHSIG` (SIGHUP) in its own `pre_exec`, then compares `getppid()` with the daemon's pid and exits on a mismatch. A shell, which `alacritty_terminal` forks with no hook, starts through the daemon's `shell` mode (`sidekicks-daemon shell <daemon-pid>`, passed as alacritty's `Options::shell`; the PTY writes the shell's program, arguments, folder, environment and any text the shell parses itself, and the fallback shell's launch, into the mode's start confirmation, so the mode's command line carries none of the person's input and the shell's own line is the only one bounded): the PTY spawns the mode, not the shell, in a stable folder, and the mode starts the shell in the folder the confirmation names. On Linux it arms the signal, re-checks `getppid()`, enters the folder with `nix::unistd::chdir` and execs the program; on macOS it does the `getppid()` check, then waits for the daemon's confirmation that it started this process (`sidekicks_platforms::ShellStartConfirmation`: a socket pair whose end the mode inherits, on which the daemon writes the id of the process it started and which it keeps open for the shell's life), refuses to start anything unless that id is its own, its parent wrote it and the parent is its own responsible process, and enters the folder with `chdir`; the shell inherits the folder across the exec. On Windows the mode starts the shell with the program exactly as the start confirmation carries it, the arguments through `args`, `Command::current_dir` set to the folder and the raw tail written last through `CommandExt::raw_arg`, which makes the shell's own line the whole bound, and keeps its own folder for its whole wait. On macOS and Linux it sets SIGPIPE back to its default, as std does for a `Command` child, then execs the program's resolved absolute path: on Linux with `execve`, on macOS with `posix_spawn` and `POSIX_SPAWN_SETEXEC` plus the attribute that disclaims the daemon's responsibility, so the shell is its own responsible process; never `execvp`, `posix_spawnp` or `Command::exec`: std's exec path calls `execvp`, and glibc's and macOS's `execvp`, like macOS's `posix_spawnp`, run a file the kernel refuses (`ENOEXEC`) through `/bin/sh`. Where the exec fails, the mode writes one line above the prompt naming the shell it could not start, the reason in plain words and the shell it runs instead, then execs the platform's default shell the same way. The calls are `nix` 0.31.3's (features `process`, `event`, `signal`, `fs`) in `sidekicks-platforms`, except macOS's spawn, which is `libc`'s, since `nix` has no `POSIX_SPAWN_SETEXEC`. A Linux test opens a shell, leaves the blocking pool idle for 15 s and asserts the shell is alive.
- **A socket path** is checked with `std::os::unix::net::SocketAddr::from_pathname` (Windows: `uds_windows`' own check) before binding: std refuses an over-long path with `InvalidInput` before any system call, so no probe waits for `EINVAL`; one fresh test checks a path at the limit and one past it.
- **The run folder** resolves in `sidekicks-platforms`, for the daemon and the CLI, exactly as desktop main's TypeScript resolver (`resolveDaemonRunFolder`) does. On Linux it is `$XDG_RUNTIME_DIR/ai-sidekicks` when `XDG_RUNTIME_DIR` is set and non-empty, else `<home>/.ai-sidekicks/run`; on macOS it is always `<home>/.ai-sidekicks/run`, since no system cleans a runtime folder there. A folder has one trailing `/` removed when it is longer than one character. On Windows it is `%LOCALAPPDATA%\ai-sidekicks\run`, the local application data folder read through the known-folder call (`FOLDERID_LocalAppData`), holding `daemon.token`, and the socket is the named pipe `\\.\pipe\ai-sidekicks-<user SID>`. Desktop main's supervisor keeps calling the TypeScript resolver, because main keeps the file tokens. One case table runs against both: `XDG_RUNTIME_DIR` set, set with a trailing `/`, set empty, and unset with a home folder ending in `/`, and on Windows a local application data folder with and without a trailing `\`. Before the daemon binds, and before `sidekicks-client` writes its first byte, `sidekicks-platforms` checks that the folder is private. On macOS and Linux `std::fs::symlink_metadata` (never `metadata`, which follows a link) reports a folder (`is_dir()`), owned by the user (`MetadataExt::uid`), with no group or other bits (`mode() & 0o077 == 0`). On Windows the check opens the folder with `FILE_FLAG_OPEN_REPARSE_POINT`, so a link is not followed, refuses a reparse point or a file, and reads the owner and the access list with `GetSecurityInfo`: the owner is the user, SYSTEM or the Administrators (who own what an elevated process makes); allowing entries name only those three; inherit-only and deny entries are skipped; any other entry type is refused, and so is a missing access list.
- **The home folder** is `std::env::home_dir()` (`HOME`, else the password entry; on Windows `USERPROFILE`, else `GetUserProfileDirectoryW`), the same home the desktop's main process reads, never `dirs::home_dir`, which asks Windows' known folders. It differs from main's only on an empty `HOME` (main answers `""`) and a `USERPROFILE` under three characters (main throws).
- **The daemon's stop and crash:** the stop request comes from `sidekicks-platforms` behind its one interface: on macOS and Linux SIGTERM and Ctrl-C; on Windows Ctrl-C and `WM_ENDSESSION` at the daemon's hidden top-level window, which answers `WM_QUERYENDSESSION` `TRUE` at once and returns from `WM_ENDSESSION` within about 4 s, inside the 5 s Windows gives a program with no visible window. `main` takes it before the start as the stop request every start step watches, and no code outside the platforms crate names a signal API. `main` also installs a `std::panic::set_hook` that writes the panic, its location and its backtrace to the service log and into the crash reports folder, flushes the file writer and calls `std::process::abort()`, so a panic in any task ends the service and the supervisor restarts it. The hook is the one place product code ends the process (`abort` is not `exit`); it keeps the workspace's `panic = "unwind"`, which the client addon needs. In the WSL server (`sidekicks-daemon wsl`) the end of the `h2` channel (`Connection::accept` returning `None` once standard input ends) or a failed write to standard output (`EPIPE`; Rust ignores `SIGPIPE`, so the write returns the error) is the same stop request SIGTERM raises, so a killed `wsl.exe`, which sends no signal, ends the server within a second.
- **Resolving a path:** every symlink-resolving call goes through `sidekicks-platforms`' one helper, `real_path`, never `std::fs::canonicalize` alone: on Windows it strips the verbatim prefix (`\\?\UNC\` becomes `\\`, any other `\\?\` goes, and a result with neither prefix is an error; `std::fs` re-adds the verbatim prefix itself for a path of 248 UTF-16 units or more, so the stripped form still opens), so a path shown, stored or handed to git or a provider carries no `\\?\` prefix and still opens, a network share and a path over 260 characters included; never `dunce`, which keeps the prefix on both. It returns the not-found error; only the deny-path caller keeps an absent path's expanded form; every other caller keeps its own answer to a missing path (a refusal, or no result). Containment is compared by components (`Path::starts_with`), never by string prefix. Environment names are compared under the host's rules (Windows: `env_remove` is case-insensitive). Windows tests: a deny path carries no `\\?\`, and a drive path, a `\\server\share` path, a name ending in a dot and a path over 260 characters each round-trip.
- **A path on the wire** is `Path::to_string_lossy()`, which writes one U+FFFD per invalid sequence, as the desktop renders it: the bytes `F0 80 80 41 E2 82` read as U+FFFD, U+FFFD, U+FFFD, `A`, U+FFFD on both, a test case.
- **Signatures:** an Ed25519 signature is checked with `ed25519-dalek`'s `VerifyingKey::verify_strict`, and an imported key is refused when `is_weak()`; never `verify`, which accepts a small-order forgery. `pasetors` keeps its own `ed25519-compact`. A secret is compared with `subtle`'s `ConstantTimeEq`.
- **Credentials:** on macOS and Windows every value goes through `keyring-core` with the platform's store, from `sidekicks-platforms`; on Linux the store is systemd's credential service, reached through the platforms crate's own client (`io.systemd.Credentials.Encrypt` and `Decrypt` with `scope: "user"` and no other option, one JSON message ended by a NUL byte each way over `/run/systemd/io.systemd.Credentials`, one connection per call, every buffer holding a value wiped on drop), which seals each item into the daemon's `secrets.json`, and the plain file where that service is absent, refuses at the first start, or binds PCR 7. An entry is built through the store, never a process default: on Windows `store.build(service, user, Some(&HashMap::from([("persistence", "local")])))`, since `windows-native-keyring-store` writes Enterprise persistence, a roaming one, unless told; a test reads `entry.get_attributes()?["persistence"]` back as `Local`. A refused call's `cause` is read from the store error's source, never its variant or message: on macOS `security_framework::base::Error::code()` (a direct `security-framework` 3.7.0 dependency, so the downcast type is the store's), -25308 `locked`, -25291 or -25294 `unavailable`; on Windows, whose store keeps its error type private, every store error reads `unavailable`; a store call in `spawn_blocking` that does not answer within `tokio::time::timeout` reads `locked`, its blocking thread held until the prompt ends. On Linux nothing can be unlocked, so every refusal, a seal that does not answer in time included, reads `unavailable`, and the daemon never branches on the credential service's error name but for the three its first start reads. A store error never carries a stored value: `keyring_core::Error::BadEncoding` and `BadDataFormat` hold the item's bytes, so the platforms error drops them. A test on macOS and Windows feeds each error and checks the cause.
- **Types:** an ID is a newtype. A closed set is an `enum`, the discriminated union the root's closed-sets rule asks for; a `match` names every variant. No `#[non_exhaustive]` and no `#[deprecated]` on workspace types.
- **Async and logs:** tokio's multi-thread runtime with two workers (`worker_threads(2)`); blocking work goes through `spawn_blocking`, except a child's spawn, which goes to the spawner thread (above); `tokio::sync` and `tokio::process` in async code. Logs go through `tracing` with typed fields; no `println!` outside the command line's output writer. An error is logged as `error = &error as &(dyn Error + 'static)`, which the fmt layer prints with its causes (`error.sources=[…]`), never `%error` or `?error`, which print only its top message or its debug form. The daemon's service log is one `tracing-subscriber` fmt layer writing to standard error and to flexi_logger's `FileLogWriter`: `logs/service-<local time begun, to the millisecond>.log`, a new file at each start, each day and at 16 MiB, flexi_logger's own cleanup off. The service's scheduler deletes a file last written longer ago than `Keep diagnostic logs for`, never the one being written. tokio's clock stops while the machine sleeps, so a wall-clock instant is armed on the operating system's wall-clock timer through `sidekicks-platforms`, which fires at that time across sleep and any clock change, and re-armed from its durable row at start; sleep, wake and clock changes reach the scheduler as the operating system's events, and nothing looks at the clock on a timer.
- **Network changes:** the daemon learns of them only from `sidekicks-platforms`' network watch, which reports one change after 1 s quiet and only when usable addresses or the network path changed, loopback and link-local aside: macOS `NWPathMonitor` through `nw_path_monitor_*` on `block2`, never SCNetworkReachability; Linux and Windows through `netwatcher` on tokio. It never polls and never claims the network works. The same watch reports the usable address set, which is the direct path's host candidates, so the addresses have one source; a change pings the relay connection and asks every direct peer to restart ICE.
- **Keyed locks:** a lock that can be held across a nested call is `KeyedLock` (`keyed_lock.rs`), never a bare mutex. Taking the lock returns a hold, and code the holder calls takes that hold as an argument instead of locking again, so the type system rules out a nested call waiting on its own holder, and a spawned task carries the hold it was given; no task-local carries it.
- **Visibility and docs:** private by default, `pub(crate)` when the crate shares an item, `pub` only for the crate's API. Every `pub` and `pub(crate)` item has a one- or two-sentence `///` doc with its error contract in the sentence; every crate root has a `//!` doc.
- **Unsafe:** a crate that binds a C interface allows it at its root with a reason, and every `unsafe` block carries a `// SAFETY:` comment. Where a library's trait or an export form demands `unsafe` in another crate, that one item carries `#[expect(unsafe_code, reason = "…")]`, and an `unsafe impl` or block in it its `// SAFETY:` comment: the daemon's `ProvidesStaticType` impl that hands `starlark`'s builtins their context, and the matcher's WebAssembly exports in `sidekicks-search`.
- **Node-API:** the client's addon, `sidekicks-client-addon`, builds with `panic = "unwind"` and puts `#[napi(catch_unwind)]` on every sync export, so a panic becomes a JavaScript error; its reader task fails every pending call and ends every stream when it stops.
- **The Worker (`sidekicks-control-plane`):** `std::time::SystemTime::now` and `Instant::now` compile on `wasm32-unknown-unknown` but panic when called, so the Worker reads time through `time` with its `wasm-bindgen` feature, and a dependency that reads the std clock is refused. Every await on a JS promise or `worker::Delay` inside an axum handler is wrapped in `worker::send::SendFuture`. `worker-build` runs in its default release profile (a `--dev` build panics in `worker::Delay` from compat date 2026-08-04), and the npm manifest stays out of the crate root, which `worker-build` refuses when it lists dependencies. The relay's Durable Objects, the account object and each machine's forwarding object, are declared with `worker`'s `#[durable_object]`, and the account object keeps the account's data in its SQLite storage; the macro needs `wasm-bindgen` as a direct dependency of the crate.
- **The Worker's config** is `wrangler.jsonc`. Production deploys only through `--env production`; `workers_dev` and `preview_urls` are `false` in every environment; every binding, var and secret is declared again under `env.production`, since none is inherited. Credentials stay in the package's gitignored `.env`, never in `wrangler.jsonc`, and `wrangler dev` never loads `.env` into the Worker: the development gate's keys sit in a `.dev.vars` made from `.dev.vars.example` and are listed in the top-level `secrets.required`, and every production secret in `env.production.secrets.required`. Nothing is deployed and no secret is set without the user's yes.

## Wire contracts (`sidekicks-contracts`)

The Rust types are the one source; TypeScript types and validators are generated from them.

- **Instants** stored or sent are written `Timestamp::strftime("%Y-%m-%dT%H:%M:%S%.3fZ")` in UTC (`jiff`), always three fractional digits, so text order and the canonical bytes hold; an incoming `occurredAt` is parsed component by component (an uppercase `T`, then `Z` or an offset, `-00:00` among them; seconds optional, `00` to `59`, so no leap second; any fraction length, a non-zero digit past the third refused and trailing zeros folded; a year outside four digits refused), its date checked with `jiff::civil::Date::new`, never by jiff's or chrono's RFC 3339 parser, whose accept sets differ (both take a lowercase `t` or a space; chrono refuses omitted seconds); one test covers `.000`, `.5`, `.5000`, an offset, `-00:00`, omitted seconds, `.0001`, a lowercase `t` and a leap second.
- **An incoming instant** is a `WireInstant` newtype whose garde `pattern` and JSON Schema `pattern` are one RFC 3339 pattern with offset (`INSTANT_PATTERN` in `wire/instant.rs`), anchored `^…$`, every digit class written `[0-9]`; never `format: "date-time"` and never jiff's parser alone, which takes `,` as the decimal sign. It keeps the text as received; a handler that compares or computes parses the checked text with `jiff::Timestamp`, dropping fraction digits past the ninth first. An incoming `occurredAt` also keeps the stricter rule above. One test refuses lower-case `t` and `z`, a space for `T`, `+0100`, `+24:00`, `23:59:60`, `2025-02-29` and a value without seconds, and accepts a ten-digit fraction.
- **`observedType`** is `"null"` for `Value::Null`, `"object"` for `Object` and `Array`, and `"boolean"`, `"number"` or `"string"` for the rest.
- **Platform and architecture** travel in Node's spelling: `Platform` (`darwin`, `linux`, `win32`) and `Arch` (`x64`, `arm64`) are contract enums with those serde names, and `sidekicks-platforms` returns the running ones from `cfg!(target_os = "macos")`, `cfg!(target_arch = "aarch64")` and the like; `std::env::consts` never reaches the wire or a release-manifest key (`darwin-arm64`, `linux-x64`).
- **Shape:** wire types use `#[serde(rename_all = "camelCase")]` and `deny_unknown_fields`, and a first-party enum's values are lowerCamelCase too (`waitingForApproval`), while a provider's or an outside standard's values stay as sent; types read from a provider stay tolerant. A union tagged on a wire field is an internally tagged enum (`#[serde(tag = "…")]`), its shared fields repeated per arm; an untagged union is an enum of closed structs. serde takes an untagged union's first arm that reads, so no earlier arm reads a message meant for a later one: arms differ by a literal tag, a `Never` member or a member's JSON type, and an arm whose member is an array comes before one whose same member is a struct. Every arm is a struct variant, `Complete {}` and never `Complete` (serde ignores unknown fields on a unit variant). A member absent on one arm is `Option<Never>`, so TypeScript keeps `x?: never`. `flatten` is not used outside the kept-unknown types below; the members an arm repeats are written by one `macro_rules!` per contract.
- **Kept unknown members** ([ADR-017](../docs/decisions/017-cross-version-compatibility.md)), the exceptions to Shape: the artifact publication payload and the artifact manifest carry no `deny_unknown_fields` and hold `#[serde(flatten)] rest: serde_json::Map<String, Value>`, the one allowed `flatten`, and an enum-valued member of either ends in a variant that keeps an unknown value (`#[serde(untagged)] Unknown(String)`, never `#[serde(other)]`, which drops it) or stays `String`; their schemas stay open (schemars marks a flattened map's parent open) and the closing pass skips them. The stored event envelope's `type` is a newtype over its text, so a newer producer's type is kept as a version stub, and its `payload` is a `serde_json::Map<String, Value>`, which keeps every member and canonicalizes to the bytes the stub keeps (the canonicalizer refuses `RawValue`); the strict `SessionEvent` is parsed from an envelope's `type` and `payload` when it is read, and Ajv reads the envelope tolerant and the event strict. One test round-trips an unknown member through each artifact type and keeps it.
- **Optional and nullable,** one attribute set each; a plain `Option<T>` never appears on the wire, since serde reads it as absent-or-null, which no contract means:
  - absent allowed, `null` refused: `Option<T>` with `#[serde(default, skip_serializing_if = "Option::is_none", deserialize_with = "wire::present")]` and `#[schemars(with = "T")]`;
  - `null` allowed, the key required: `#[serde(deserialize_with = "wire::nullable")]` and `#[schemars(with = "wire::NullableSchema<T>")]` (never `#[schemars(required)]`, which emits the non-null `T`);
  - both: `Option<Option<T>>` with `#[serde(default, skip_serializing_if = "Option::is_none", with = "serde_with::rust::double_option")]`, so absent, `null` and a value keep their three meanings in both directions; a member the service sends to a provider whose wire gives those three meanings takes the same set, and a test serializes each state.
- **Scalars are newtypes with private constructors** whose JSON Schema carries the same rule: a cap counts what its owner counts: a text cap in code points (`chars().count()`, as the generated Ajv validators count `maxLength`, so the daemon and the desktop refuse the same text; a cut at `char_indices().nth(max)`), a byte budget in UTF-8 bytes (`str::len()`: `contentLength`, a JSON-encoding budget counted as below; a part's offset checked with `is_char_boundary`) cut at a character boundary (`floor_char_boundary`), and a provider's own cap in its own unit (UTF-16 where it counts that, `encode_utf16()`), and a member reporting a cut value's original length counts in its cap's unit; whitespace is the ECMAScript `\s` set spelled out, no NUL; `SafeInt` stays within 2^53 − 1; every integer has an explicit range; bytes are `Bytes<MIN, MAX>`. A resume position into a stored body (`transcript.body.read`'s `offset`, a patch cursor) is the exception to the UTF-16 rule that follows: a UTF-8 byte offset, refused unless `str::is_char_boundary`. An offset into text counts UTF-16 units (`encode_utf16()`), as JavaScript indexes, and a list of text sorted as JavaScript's bare `.sort()` sorts it, whose order is stored, sent, hashed or decides which file wins, is ordered by UTF-16 code units (`left.encode_utf16().cmp(right.encode_utf16())`; `str` order differs once a character above U+FFFF meets one in U+E000–U+FFFF), a list that holds only ASCII keeping `str` order. No inline `(?i)` regex flags: a pattern spells its case out, as the UUID pattern takes `[0-9a-fA-F]`. Nor does a pattern use `\d`, `\D`, `\w`, `\W`, `\b`, `\B` or `.`, which Rust's `regex` reads as Unicode classes and JavaScript as ASCII: it spells the class out (`[0-9]`, `[A-Za-z0-9_]`), and any character but a line break is `[^\n\r\u2028\u2029]`, so Rust and Ajv's ECMA-262 engine accept the same strings. A record-typed map refuses the key `__proto__`, in the schema too (`propertyNames`), so no TypeScript reader meets it.
- **A cap on a value's JSON size** is the byte length `JSON.stringify` gives, counted without building the text: `serde_json`'s serializer over a counting writer, its numbers in ECMAScript form through `ryu-js`; never `serde_json::to_vec(…).len()`, which writes `1.0` where JavaScript writes `1` and `1e+20` where it writes `100000000000000000000`. `serde_json_canonicalizer` is for hashes and signatures.
- **Bytes** travel beside the JSON as attachments: a `Bytes<MIN, MAX>` field is `{"$bytes": index}` on the wire, its schema a `$ref` to `Bytes` with `minBytes`, `maxBytes` and `tsType: "Uint8Array"`. Ajv registers both size keywords with `passContext: true`, and every TypeScript caller passes `{attachments}`. The decoder refuses an attachment used twice or never used, a rule of the message checked once in each side's frame decoder.
- **Hashes and signatures over JSON** are over `serde_json_canonicalizer::to_vec` bytes (RFC 8785), never `serde_json::to_vec`; a value hashed through it is held as `Value` or typed structs, never `RawValue`, which it refuses.
- **Rules no shape holds** are `garde` checks, each with the same rule in the schema (`#[schemars(extend(…))]`), so TypeScript enforces it without a hand copy. A garde message never quotes the value it refuses. A type gaining its first rule derives the check, and every type holding it dives into it.
- **A message a server receives** (the daemon's requests and notifications, an attachment message's typed body, an agent tool's arguments, the control plane's calls) is read as a `serde_json::Value`, checked against its contract schema's shape with `jsonschema` (`schema::received_check`, each validator built on first use and held; `wire::attachment::parse_received` for a framed message), read with `from_value`, then held to its garde rules: serde reads a JSON array as a struct and no serde setting refuses that, where the shape refuses it as Ajv does. The shape (`schema::received_shape`) keeps the structural keywords, writes every union and every `if`/`then`/`else` as an `allOf` rule (a tagged union as one `if`/`then` per arm keyed on its tag; a union of `null` and one arm as `if` null, `else` the arm; any other as `if` its arms, `else: false`), and drops every value rule, an Ajv `$data` among them, since `jsonschema` cannot read `$data`; so each rule a received type's schema carries has its garde or newtype twin. A reader takes `validate`'s one error, never `iter_errors` or `evaluate`, so a malformed message costs no more than its read. The daemon's dispatch parses a request once and hands the handler the value. A reader of the daemon's own output keeps `from_slice`.
- **An agent tool's input type** (`rmcp`'s `#[tool]`) is read through the tool route's own `Received<T>` extractor, which runs the received check above, never `Parameters<T>`, a plain serde read; each tool names its schema with `#[tool(input_schema = …)]`, taken from `schemars`. The text the model reads for a field, its pattern, length and bounds in words, is that field's `#[schemars(description = "…")]`, never starting with `#` (schemars makes a leading `#` line the title), and its `///` doc keeps to one or two sentences.
- **One schema per contract module** (`schemars`, draft 2020-12), closed by the project's closing pass (`unevaluatedProperties: false` on the outermost object; `#[schemars(inline)]` on struct arms reached through `$ref`). From it come the TypeScript types (`json-schema-to-typescript`; a brand or an Ajv `$data` value takes `tsType`) and the validators (Ajv 2020, strict, every `format` and custom keyword registered, compiled to standalone code at build time).
- **Methods and refusals:** every method is declared once in the contracts crate's method table (params, result, refusal codes), and the TypeScript method map is generated from it. Refusal codes are one Rust enum, each code with its category and its HTTP status, emitted as a TypeScript string union; every refusal answers `-31000` with its code in `data.type` and its category in `data.category`. Every method, event and refusal name follows the wire grammar, which one `const fn is_wire_name` in the contracts holds (with `is_protocol_method_name` for `$/` names); `methods!`, `refusal_codes!` and `session_event_types!` assert each name they declare against it at build time, as do the hand-built descriptors `DaemonHandshake` and `SubscriptionCancel`, and the daemon's method registry checks only for a name registered twice. garde's issue paths are mapped to the wire's names once, in `sidekicks-contracts`' `jsonrpc::issue`, which the daemon and the client call, never by a per-field rename.
- **Generated TypeScript** is committed into `packages/contracts/src/generated/`, served at `@ai-sidekicks/contracts/<topic>/<module>` by the package's `exports`, with a "generated" header, formatted by the repo's Prettier in the same step, never edited by hand; CI regenerates it and fails on `git diff --exit-code`.
- **Constants** a TypeScript client reads as values are declared once as `pub const` in the contracts module that owns them and listed in that module's one `ts_constants!` table; the schema pipeline writes each into its module's generated file as `export const NAME = <value> as const;` (the value through `serde_json`): `MACHINE_SETTINGS_DEFAULTS`, the size caps and bounds, every closed set a client iterates (written from the enum's variants), every refusal code a client compares (beside its union) and the `JsonRpcErrorCode` object. The `*_METHOD_DESCRIPTORS` a client imports are the method map the method table generates, at their names and paths.
- **Hand-written TypeScript** is only what a schema cannot carry: the three registered `format` functions (`https-url`, `site-origin`, `web-url`), the frame decoder's attachment rule, the frame encoder's `toWellFormed()` on every string, the `EventCursorUnresolvableError` class, `SessionStreamFrameSchema` (a generic factory over the generated frame schema), and every function a TypeScript client imports, each in a hand-written module of its own in its topic folder, among them the five helpers (`parseWorkflowHandle`, `foldName`, `webAddressFault`, `decodeArtifactPayloadText`, and `composeAppLink` with `parseAppLink`, whose Rust form `sidekicks-contracts::app_link` serves `sidekicks open`, the TS pair taking its id checks from the generated validators), the event cursors, page fitting and JSON byte length, the transcript run-fact, turn-attribution and content readers, the run folder (`resolveDaemonRunFolder`, which desktop main's supervisor calls, its Windows arm resolving from the local application data folder and the user's SID, and `refuseWindowsDaemonRunFolder`, which the Windows operating-system objects name while neither reads the user's SID), process identity, the platform check, account labels, the provider-model lookup, the repair line and artifact payload decoding. `parseMachineSettingsFile` checks the file with the generated validator after the hand-written `overDefaults` lays it over `MACHINE_SETTINGS_DEFAULTS`. It all lives in `packages/contracts/src`, outside `generated/`. Where the daemon or the CLI runs the same rule, its Rust function writes one case table, `crates/sidekicks-contracts/tests/fixtures/<topic>.json`, that both test suites read, so the two copies cannot drift, and a new function the daemon also runs comes with its table; every other piece is tested against examples the Rust side writes.
- **Text a provider sends** (Claude Code's stdout and session files, Codex's socket, MCP servers) is read so that every line a provider writes parses: Claude Code is a JavaScript program, and JavaScript's `JSON.stringify` writes a lone surrogate as an escape, which `serde_json` refuses. Before `from_slice`, one pass gated by `memchr(b'\\', …)` walks the line's escapes left to right, each as one unit (`\\`, `\"`, `\/`, `\b`, `\f`, `\n`, `\r` and `\t` skip two bytes; `\u` reads four hex digits), keeps a high surrogate only when a `\uDC00`–`\uDFFF` escape follows at once, and overwrites a lone one in place with `\uFFFD`, the same six bytes, as the outbound `toWellFormed()` does; in valid JSON a reverse solidus occurs only as an escape's start (RFC 8259 §7), so the pass needs no quote tracking. Bytes that are not UTF-8 become U+FFFD through `String::from_utf8_lossy`.
- **Framing:** JSON-RPC 2.0 messages in the one 10-byte-header frame codec, the same on the local socket and inside each Noise message, on the relay and on the direct path alike, so nothing above the carrier knows which one a channel is on. One frame kind, the cut-over frame, is each end's last frame on the relay before it writes only on the direct path's data channel; the lanes, call slots and subscriptions stay alive across it. Bytes go as attachments; each subscription has its own lane with receiver credit; `$/cancelRequest` is answered `-32800` with `data.type` `request.canceled`; terminal output travels as bytes. A subscription holds only its place, never a queue: it reads its next frame from the stored record at its cursor, or sends the newest state, when its lane has credit, so a slow reader costs no more than the one message its lane has begun; a connection holds at most 10,000 open subscriptions, a subscribe call past it refused with `connection.subscription.limitReached`, and a peer opening lanes past that bound is misframed; a connection holds at most `MAX_CALLS_IN_FLIGHT` (100) calls in flight, a figure that changes only with a new dated `protocolVersion`, each slot taken before dispatch and freed when its reply's last piece is cut, a call past it refused at once with `connection.call.limitReached`, a subscription cancel, a stop or a `terminal.write` taking no slot; a connection's writes to one shell are refused past `TERMINAL_WRITES_WAITING_LIMIT` (16) waiting with `terminal.write.limitReached`, each carrying at most `TERMINAL_WRITE_MAX_BYTES` (64 KiB).

## Tests

- **Tests sit at the critical minimum.** A behavior is proven by the fewest tests that fail when it breaks, and only where a failure is expensive (root `AGENTS.md` rule 5): the critical path, data loss, a leaked secret, a resource budget, a boundary another surface reads. No test of shape, wiring, a derive, a getter, generated code or coverage; tests that prove one behavior are one test.
- Unit tests sit in `#[cfg(test)] mod tests` at the bottom of their file (`name/tests.rs` past the 900-line limit). A crate's integration tests are one binary, `tests/it/main.rs`, declaring a module per behavior (`tests/it/provider_turns.rs`), with shared helpers in `tests/it/helpers.rs`: Cargo links each file directly under `tests/` as its own binary, so one binary keeps link time and disk down. Data a test reads is in `tests/fixtures/`.
- **Reuse.** Plain `#[test]` by default; `rstest` (`#[case]`, `#[fixture]`) where several cases share one body or one fixture, so near-duplicate tests become one case table. A helper another crate's tests need sits in the module that owns its type under `#[cfg(any(test, feature = "test-support"))]`, and the consuming crate turns `test-support` on in `[dev-dependencies]` only, which the feature resolver keeps out of the normal build. A helper both of the daemon's test binaries need sits there too.
- Property tests (`proptest`) guard parsers, wire decoding and crypto, regression files committed, at 100 cases on a PR and 10,000 in the nightly run (`PROPTEST_CASES`). Fuzz targets live in `crates/sidekicks-daemon/fuzz/`, a workspace member left out of `default-members` whose dependencies come from the workspace table, so it shares the root lock and the daemon's feature lists; `libfuzzer-sys` is declared under `cfg(fuzzing)`, which only `cargo fuzz` sets, so a workspace check, lint or test builds none of libFuzzer and the target there is an empty program. Targets are run by `cargo fuzz run <target> -s none` on the pinned stable toolchain: `-s none` passes no `-Z` flag and keeps libFuzzer's coverage guidance, giving up only AddressSanitizer, where unsafe code is denied. Crashers are minimized into `fuzz/corpus/<target>/regressions/`, and each target's whole corpus, crashers included, is replayed by one nextest test in the normal run. Snapshot tests (`insta`) only where the snapshot is the behavior. No retries in the runner. `cargo mutants --in-diff` proves a failure-path test.
- The endurance tests are the daemon's `tests/endurance.rs` binary, which only nextest's `endurance` profile runs; every other test run, mutation and coverage included, goes through nextest, whose default filter keeps it out. Both filters are written in the change that adds the binary, since nextest refuses a filter naming a binary no workspace target has.

## Memory

Memory is why the service is in Rust; each of these holds by default:

- The global allocator is mimalloc on macOS and Linux and the system allocator on Windows, supplied by `sidekicks-platforms` as `GlobalAllocator` and `GLOBAL_ALLOCATOR` and declared once, in the daemon's `main.rs`, so the command line and the client's Node addon keep the system allocator, with the call that hands freed memory back (`mi_collect(true)`, a no-op on Windows until the allocator switch), which the daemon makes once its work goes quiet, from a one-shot timer that new work resets. On Linux the daemon turns transparent huge pages off for itself at start and clears that in each child before exec.
- JSON is read with `from_slice` into typed structs, except a message a server receives, which takes the shape check (Wire contracts); a payload the service only relays and never hashes stays a `&RawValue` (`serde_json`'s `raw_value` feature).
- Each SQLite connection sets its `cache_size`, the connections are counted, and `prepare_cached` is sized to the statement set.
- `reqwest` clients cap `pool_max_idle_per_host`.
- File watching goes through one bounded handler. Where the backend watches a tree (FSEvents, `ReadDirectoryChangesW`) it watches the root; inotify watches one folder at a time, so on Linux only the folders an ignore walk keeps are watched.
- The search index writes with one indexing thread and the smallest budget that keeps up.
- No queue drops a log line silently: a non-blocking writer either blocks or reports each dropped line.

## Unused code and spelling

- An item kept for a consumer a document names carries `#[expect(dead_code, reason = "<the consumer, in plain words>")]`; a file or dependency kept the same way takes one entry in the crate's `[package.metadata.cargo-shear]` with a plain comment.
- `typos` checks code with `locale = "en-us"`; documents are not checked. A spelling a provider sends goes in its allow list.
