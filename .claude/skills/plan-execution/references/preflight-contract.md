# Preflight Tool Contract

The orchestrator invokes this tool at Phase 0 of plan-execution. It is the authoritative source for all mechanical gates that block dispatch.

## Invocation

    node .claude/skills/plan-execution/scripts/preflight.mjs <plan-file> [phase] [--allow-stale-manifest] [--allow-unpromoted]

When `phase` is omitted, the tool walks the plan's Implementation Phase Sequence and resolves to the first un-shipped phase whose preconditions all pass. When provided, it validates the specified phase explicitly (used when the user override-supplies a phase).

`phase` accepts two forms, parsed by `parsePhaseArgument`: a **phase number** (`4`) and a **supplement label** (`3B` — the campaign-supplement heading shape `### Phase 3B — …`). Anything else exits `2` with a `bad phase argument:` line that names both accepted forms. The numeric arm is evaluated first, so every numeric invocation resolves exactly as it did before supplement dispatch existed.

**Supplement phases are dispatch-by-name.** The no-argument walk is numeric-only by construction — `walkPhases` matches `### Phase <digits>` alone — and never selects a supplement however eligible it is; `findSectionBoundary` independently treats a supplement heading as a section boundary, so the numbered phase above one does not swallow its tasks. Passing the label explicitly is the only way to reach it, and it then runs **every** gate a numeric phase runs, through the same `_checkPhase`: Gate 2's strict per-phase audit leg, Gate 3, Gate 4 (both the token floor and the semantic anchor check), and both legs of Gate 5 — with the plan-level gates (1, 2 lenient, 6, 7) unchanged ahead of it. Resolution is by string equality against a heading scan (`walkSupplementPhases`) that requires the ` — <title>` separator, so "resolvable by name" and "extractable as a section" are the same shape; matching by equality rather than by interpolating the argument into a pattern also keeps a caller-supplied `runPreflight` argument (`3.*`) from becoming a live regex inside `extractPhaseSection`. A label naming no such heading halts (exit 1) listing the supplement headings the plan does declare, and names the missing-separator trap. Remainder labels (`R2`) are deliberately NOT dispatchable — they are operands of the cross-plan `external_plan_phase_merged` gate (§Gate 5), not execution targets — so they take the `bad phase argument` path.

`--allow-stale-manifest` skips Gate 6 (manifest freshness), whose pass depends on network reachability rather than repo state. `--allow-unpromoted` skips Gate 7 (status promotion) for authoring-time inspection of `draft` / `review` plans — the campaign's own plan-022 verification runs are the use case. Both skips log to stderr so a bypassed run is never silent. Programmatic callers (`runPreflight`) get the inverse defaults (`checkFreshness: false`, `checkStatusPromotion: false` unless opted in) so fixture-driven test suites stay network-free and gate-focused; `main()` always passes `checkFreshness: !allowStaleManifest` and `checkStatusPromotion: !allowUnpromoted`.

The tool MUST be run from the repo root (Gate 5 `pr_merged` and `adr_accepted` resolvers and Gate 6's freshness cross-check shell out to `gh` / read `docs/decisions/`, which expect the cwd's git remote and repo layout).

## Exit codes

- `0` — all gates pass. `stdout` contains exactly two lines: the resolved phase — a phase number (e.g., `4`), or a supplement label (e.g., `3B`) under explicit dispatch — then `size-class: S|M|L` (§Size classes below). Demoted Gate-4 grammar findings, when present, print on `stderr` — non-blocking but never silent.
- `1` — a gate failed. `stdout` contains a self-contained halt message the orchestrator surfaces verbatim (failure type, file paths, remediation hint). `stderr` empty.
- `2` — internal error (malformed plan markdown, malformed YAML preconditions, missing tool deps). `stderr` describes the error; `stdout` empty. Orchestrator escalates to user; not a normal halt.

## Size classes

Every phase classifies S / M / L via `classifyPhaseSize(declaredTaskIds, targetPaths)` — inputs are the phase's declared task IDs (Gate 3's `extractDeclaredTaskIds`) and the path-shaped tokens from its `Files:` fields (`extractDeclaredFilePaths`). S: ≤1 task; M: 2-3 tasks whose code paths sit in a single top-level `packages/<name>` / `apps/<name>` root (non-code paths don't count against it); L: everything else. Two fail-closed rules bound the classifier: zero parsed task IDs → L (unrecognized Tasks-block shape gets the full ceremony), and for the 2-3-task branch zero parsed `Files:` paths → L (single-root confinement unproven; docs-only phases with parsed non-code paths keep M). Definition + rationale: `docs/superpowers/specs/2026-07-06-plan-execution-refinement-design.md` §5. The class rides the success return (`sizeClass`) and stdout line 2; SKILL.md § Size-Classed Ceremony maps it to review + housekeeping tiers, and Gate 4 tiers its strictness by it (§Gate 4 aggregation). In auto-walk mode the success return's `warnings` also carry demoted findings accumulated from phases the walk SKIPPED (e.g. an S phase halted only by an unmet precondition) — the never-silent contract covers skipped phases too. Halt returns carry `warnings` as well (explicit-phase halts, walk strict-halts, and the walk-exhausted halt); the CLI folds them INTO the stdout halt text (`Demoted grammar warnings (non-blocking, carried by the halt):` block) because orchestrators surface stdout verbatim on non-zero exit — stderr remains the success-path warnings channel, keeping the success stdout contract at exactly two lines. Substrate-exempt phases classify too (the ceremony map still applies even though Gate 4 is skipped).

## Gates

Each gate runs in order; halt on first failure. The tool MUST NOT proceed past a failed gate (no aggregated multi-gate output).

### Gate 1 — Project-locality

Reads `requires_files:` from the skill's own frontmatter (`.claude/skills/plan-execution/SKILL.md`). Asserts `fs.existsSync` for each entry, resolved against the repo root. Failure message names the missing files and tells the user this skill is shaped for the ai-sidekicks-style repo surface.

### Gate 2 — Audit-complete checkbox (top-level lenient + per-phase strict)

Two-layer gate. The top-level `gateAuditCheckbox(planSource, planFile)` runs once before phase resolution and passes when EITHER (a) the plan body has the ticked `^- \[x\] \*\*Plan-readiness audit complete` row OR (b) any phase in the plan declares a `type: audit_status` precondition entry (the substrate-vs-namespace carve-out path). The strict per-phase enforcement runs inside `_checkPhase` via `gatePhaseAuditCheckbox(planSource, phaseSection, planFile, phaseNumber)`, which requires the resolved target phase specifically to carry either the plan-level checkbox OR its own `type: audit_status` declaration.

The two-layer split exists because plans like Plan-023 ship Tier 1 phases under substrate carve-outs while Tier 8 remainder phases haven't been authored. A purely plan-scoped check would force every yet-to-be-authored phase to carry the YAML up-front; a purely lenient check would let those un-authored phases dispatch through the carve-out path. The lenient top-level + strict per-phase combination is what admits Plan-023 Phase 1 today without preauthorizing future Phase 2+ dispatches.

Failure references the audit runbook path, the Status Promotion Gate concept, and the runbook §Per-Phase Audit Semantics section.

### Gate 3 — Phase un-shipped

Reads the plan file in two passes:

1. **Declared tasks.** Extract the phase's `#### Tasks` block via `extractDeclaredTaskIds(phaseSection)`. Both audit-Tasks-block layouts are accepted: sub-header form (`##### T1.1 — title` — Plan-001 style) and bullet+bold inline form (`- **T-007p-1-1** (Files: …) — …` — Plan-007 partial style). Returns a sorted unique array of task ids.
2. **Shipped tasks for this phase.** Extract via `parseManifestBlock(planSource)` from `lib/manifest.mjs`, then `shippedTaskIdsForPhase(manifest, phaseNumber)` which collects entries where `entry.phase === phaseNumber`, flattens the `task` field across both string and array forms (legacy multi-task PRs predate NS-02), and returns a `Set`.

Halt if `declared ⊆ shipped` — every declared task for the phase appears in the manifest. NS-02 partial ships (e.g., Plan-001 Phase 5 Lane A T5.1 alone, with T5.5/T5.6 still declared and un-shipped) leave the gate open. Phases whose tasks block contains zero ids fall through to Gate 4 (the audit's G4 traceability gate catches missing Tasks-block content).

When phase is auto-selected, the tool just skips already-shipped phases; the explicit halt message fires only on explicit-phase overrides for already-shipped phases.

**Supplement targets compare against the whole manifest.** A supplement label (`3B`) can never BE a manifest phase key — `validateEntry` forces `phase` to a positive integer — so phase-key equality would return an empty shipped set, classify every supplement `partially_shipped`, and let an already-shipped supplement re-dispatch forever. Explicit supplement dispatch therefore passes `shippedAcrossEveryPhaseKey: true` to `classifyPhaseShipment`, which sources the shipped set from `shippedTaskIdsAcrossManifest(manifest)`: the union of every entry's task ids under whatever integer phase the supplement's work actually landed as. That is the same task-set-membership reasoning the `external_plan_phase_merged` label branch uses (§Gate 5), hoisted into one shared helper so the two cannot drift into disagreeing about whether the same section has shipped. The opt is **explicit rather than inferred** from the argument's type: shape-keying inside the classifier would also reroute the `plan_phase` resolver, where a malformed `phase: "3B"` entry halts today and would silently start passing — fail-open on malformed input. The numeric path is unchanged.

**Why manifest set-comparison, not gh search.** The pre-Commit-3 mechanism inferred shipment from PR title/body via `gh pr list --search "Plan-NNN in:title,body"` plus three regex matchers (`Plan-NNN PR #N`, `Plan-NNN Phase N`, phase-title substring) and a code-prefix filter. The history is documented in [BL-110](../../../../docs/archive/backlog-archive.md) and the Plan-001 shipment-manifest refactor: PR-body conventions vary across plans (Plan-001 uses `Plan-NNN PR #N`, Plan-007 partial uses `T-NNNp-N-N`, post-NS-02 uses task ids in titles), every regex pattern bought one false-match class while introducing another, and the 1000-PR fetch ceiling forced a sentinel halt. The structured manifest moves shipment state out of free-form prose and into a `### Shipment Manifest` YAML block per plan; Gate 3 becomes a set-comparison against an explicit data structure. Less code (~30 lines vs ~145), no network call, no fetch ceiling, and the partial-ship class (NS-02 lane carve-outs) falls out of the set-comparison naturally rather than requiring an asymmetric-pattern-reach hack.

**Strict halt on parse failure.** Gate 3 halts (exit 1) when `parseManifestBlock` returns `!ok` — including the `no_section` case (no `### Shipment Manifest` heading), `no_yaml_fence` (heading exists but the ```yaml fenced block is missing or truncated), `missing_schema_version`(fence parsed but the top-level`manifest_schema_version`key is absent), and`missing_shipped`(schema-version present but the`shipped:`top-level key is absent — plan author must add`shipped: []`for an empty manifest or list entries under it). Pre-round-7 the gate fail-opened on parse failure; in auto-walk mode this could re-dispatch already-shipped phases after any manifest formatting error (Codex P1 finding on PR #35 round 7). The`missing_shipped`case was added in round 10: pre-round-10 the parser returned`{ ok: true, version, shipped: [] }`when only the version line was present, which silently zeroed out the shipped-tasks set and re-opened Gate 3 for already-shipped phases (Codex P1 finding on PR #35 round 10). Plans created before Commit 1's template change must add the`### Shipment Manifest`section per`docs/plans/000-plan-template.md` before preflight resolves them.

**Strict halt on entry-schema failure.** Even when the YAML structure parses, every `shipped[]` entry runs through `validateEntry` from `lib/manifest.mjs`. Type or shape errors (e.g. `phase: "5"` as a string instead of an integer, missing `task`, unknown field names) trigger the `manifest_invalid_entries` classifier kind and halt with a per-entry error list. Pre-round-8 the classifier read entry fields directly without schema validation, so type-mismatched entries silently produced an incomplete shipped-tasks set and re-opened Gate 3 for already-shipped phases (Codex P2 finding on PR #35 round 8).

**Auto-walk surfaces strict halts.** `_checkPhase` propagates the classifier kind on every Gate 3 failure (`reason: ship.kind`), and the auto-walk loop in `runPreflight` only silent-skips `reason: "fully_shipped"`. Both `manifest_unparseable` and `manifest_invalid_entries` short-circuit the loop with `{ exit: 1, stdout: r.halt }`, so the strict halts above fire in auto-walk mode the same way they fire in explicit-phase mode. Pre-round-9 `_checkPhase` collapsed every failure to `reason: "shipped"`, so the loop silenced manifest corruption and emitted "no eligible un-shipped phase" with the halt buried in the per-phase `skipped[]` text (Codex P1 finding on PR #35 round 9). The explicit allow-list — not a default — guarantees future strict-halt classifications also surface unless they are explicitly added as silent-skip.

**Soft skips carry full halt bodies.** The two soft-skip reasons that fall through to the walk's terminal aggregate — `no-section` and `preconditions` — render in `skipped[]` as each phase's complete halt body, indented under its `Phase N (reason):` bullet with the redundant per-phase `## Preflight halt:` header stripped. The aggregate is the ONLY halt an auto-mode run prints when no phase is eligible; the prior shape kept just the halt's first line per phase, which reduced every Gate 5 failure — the failing yaml entry, the unchecked and orphaned box lines, the remediation prose — to the generic header in exactly the invocation mode SKILL.md runs first and surfaces verbatim as "self-contained".

**Schema-version forward compat (only intentional fail-open).** `parseManifestBlock` returns `{ ok: true, version, shipped }` for any version >= 1. Gate 3 treats unknown future versions (`manifest.version > MANIFEST_SCHEMA_VERSION`) as opaque — fail open, do not block dispatch on a partial migration. The policy lives in `lib/manifest.mjs`'s header. This is the only case where Gate 3 silently passes; every other parse outcome (failure or full-shipped) halts loudly.

**Why phase-walk, not title-count.** Plans with substrate/namespace or partial/remainder carve-outs ship phases non-contiguously across tiers. Plan-007 ships Phases 1-3 in Tier 1 (substrate partial carve-out) and Phases 4+ in Tier 4 (remainder). Counting merged `Plan-007` PRs after the third merge returns next M=4, which silently maps to Tier-4 work whose preconditions (Plan-001 + others) may not be met. The phase-walk gates each phase on its declared Precondition (Gate 5), so the auto-selected phase is always the lowest-numbered phase whose preconditions all pass — substrate-carved or otherwise.

### Gate 4 — Tasks-block G4 cites

Extracts the selected phase's section (between `### Phase N —` and the next `### Phase` header). Counts `Spec coverage` and `Verifies invariant` substring matches. Each must be ≥ 1. Failure means the audit's G4 traceability gate did not produce content; user must re-run the audit.

Marker counting and cite extraction are **fence-masked** first. Every line the shared structural scanner consumes — fenced code blocks, raw-HTML blocks, HTML comments, multi-line inline code spans — is blanked to spaces before any marker regex runs. The mask is length-preserving on purpose: extraction is offset-driven (`marker.index` slices the payload, `lineNo` counts prefix newlines), so blanking with spaces rather than deleting keeps every offset and reported line number byte-identical to the raw source. A `**Spec coverage:**` row inside a ```markdown example is illustration, not audit output; before masking, a phase-less plan whose ONLY markers lived in an example block reported as cite-swept, non-vacuous and anomaly-free — and the screen VERIFIED the example's cites against real spec files, so the false clean came with fabricated evidence. Applies to `countCites`(which`hasCiteMarkers`keys on),`classifyPhaseMarkers`, `countBoldCiteMarkers`, `extractCiteAnchors`, and `extractInlineCitePayloads`, so no caller can reintroduce the hole.

The token-presence floor above ran alone until 2026-05-21, when post-mortem `51ca5f3d` revealed it false-greened on seven distinct cite-anchor defect classes that the audit subagent prompt did not operationalize against (DP-1 in the post-mortem; PR #95's nine latent defects on `develop` @ `7d3abb3`). Gate 4 now also runs a **semantic anchor check** that parses each `**Spec coverage:**` and `**Verifies invariant:**` payload, verifies each anchor exists in the cited spec, and surfaces structured failures. The two-layer split exists so audit-output that lacks G4 content (the original false-negative) and audit-output whose G4 content is semantically incorrect (the post-mortem defect class) both halt — neither subsumes the other.

#### Semantic anchor check — parser grammar

Per-payload parsing runs as `extractCiteAnchors(phaseSection)` → `parseCitePayload(rawPayload)` → `parseSegment(seg)`. Tokenization is paren-aware (commas, semicolons, and `+` inside `(...)`, `[...]`, or `{...}` are not anchor separators), quote-aware (the same three characters inside a straight-ASCII-double-quoted run are not separators either, so a cite may quote the spec sentence it describes without the quoted commas shattering it into fragments — only `"` toggles a region; typographic quotes and apostrophes are deliberately untracked. A malformed quoted run is one hole with THREE signatures, and `parseCitePayload` checks all of them because none subsumes the others: an ODD count leaves the toggle open through end-of-payload, collapsing the tail into one token — caught by parity; an EVEN count that OPENS inside a bracketed group and CLOSES outside it swallows that group's closing bracket, so the splitters' depth never returns to 0, the next depth-0 separator is ignored, and two cites merge into one whose surviving token can parse as a perfectly valid anchor — caught by the negative-local-depth signature; and a run carrying an opener of its OWN never dips negative even while swallowing a separator (`line 10 (5" (window), line 99999 (30" grace)` runs +1/0/+1 and yields the line-10 anchor alone, zero failures) — caught by the net-non-zero-at-close signature, conjoined with "the run contained a `,`/`;`/`+`" so that a run which merely opens a bracket and strands nothing (`line 10 ("foo (bar"), line 20`) stays clean. All three emit `unbalanced-cite-quote`. The collapse is NOT self-gating in any case: the anchors ahead of the malformed quote parse clean, so without these checks the payload reports nothing while the claims behind it are silently discarded), and dash-normalized (`–` U+2013 and `—` U+2014 fold to ASCII `-`) BEFORE pattern-match — without normalization the load-bearing en-dash compound-range defect (post-mortem class 2) is silently missed.

Top-level segment boundaries (depth-0): `;` is canonical (cross-namespace, e.g. `Spec-001 AC8; ADR-018 §Decision #4`); `,` is also a segment boundary when followed by another recognized namespace prefix (`Spec-NNN`, `ADR-NNN`, `<doc>.md`, `cross-plan-deps`). The latter shape (`Spec-002 AC1 (line 178), Spec-002 line 87 + AC1 (I3)`) appears in approved plans (Plan-002 T5.1/T5.3) to disambiguate `(line N + AC M)` sub-anchor groups. A comma followed by a sub-anchor keyword (`AC`, `line`, `lines`, `§`) stays inside the current namespace.

Accepted shapes (each emits one or more anchors with `severity: info|warn`; `severity: error` is rejection-only):

- `Spec-NNN ACX` — single bare AC, where `X` is the ordinal digits with NO hyphen: `AC8`, never `AC-8` — the parser regex is anchored `^AC(\d+)`, so a hyphenated `AC-1` is an unparseable sub-anchor, not a match (this notation bug cost a Gate-4 halt at the Tier-8 audit; the live example on the segment-boundary line above, `Spec-001 AC8`, has always shown the real shape). `severity: info` (line-hint recommended).
- `Spec-NNN ACX (line YY[ — Subject])` — AC with explicit line + optional identifier-token subject.
- `Spec-NNN ACX (descriptor)` — AC with prose descriptor (no identifier-token subject). `severity: info`.
- `Spec-NNN AC line YY[ (descriptor)]` — acceptance criterion named by the LINE it sits on rather than by ordinal (Plan-011 / Plan-014 / Plan-025 idiom). Emits an `ac-line` anchor, NOT a plain `line` anchor: the verifier additionally requires line YY to sit inside the §Acceptance Criteria line bounds and to be a `- [ ]` / `- [x]` checkbox bullet (`ac-line-out-of-range` / `ac-line-outside-section` / `ac-line-not-bullet`), so the shape is strictly stronger than a bare line cite, never a loosening. A cite that ALSO names a section must have that section CONTAIN line YY (`line-outside-section`): resolving the heading proves only that it exists somewhere, so without containment `§Required Behavior AC line 7` was certified by a bullet sitting under §Acceptance Criteria and a stale qualifier stayed green. Only a section the anchor itself claims — the payload's own `§` prefix — is enforced: `section` is sticky across sub-tokens by design (`§Foo line 10, line 12`) and an `AC line` token can never carry its own `§` (its regex is anchored at `^AC`), so a SIBLING's re-section is recorded on the anchor but not enforced against it. Plan-011's `… line 68 + §Git Hosting Adapter lines 118-152 (…), AC line 175` is the live shape: line 175 is a correct §Acceptance Criteria bullet, and enforcing the sibling's span against it would fail a valid cite.
- `Spec-NNN line YY[ (Subject)]` — line with optional descriptor.
- `Spec-NNN §Section line YY[, line ZZ[, line WW]][ (descriptor)]` — comma-separated multi-line under one §Section. Splits into N anchors.
- `Spec-NNN §Section line YY[ (Subject)]` — single §Section + line + optional descriptor.
- `Spec-NNN line YY + ACX[ (Subject)]` — `+`-combined line + AC (same hyphenless `ACX` ordinal form). Splits into two anchors.
- `Spec-NNN §A line YY, §B line ZZ` — comma-separated re-section sub-anchors. Each `§<Section> line N` token inside a single `Spec-NNN` namespace switches the active section and emits one line anchor.
- `Spec-NNN §Section` (no line) — bare §-cite. `severity: warn` (line-anchor recommended; non-blocking by design).
- `Spec-NNN lines YY-ZZ (single-subject descriptor)` — multi-line block with one identifier-token subject in descriptor (e.g., `RateLimitResponse lines 127-133`). One anchor.
- `ADR-NNN §Section[ (row|item) M[ (descriptor)]]` — ADR-namespaced anchor. Parser verifies ADR file glob; section verification is documentary not mechanical.
- `<doc>.md[ §Section][ (descriptor)]` — architecture-doc cite (e.g., `error-contracts.md`, `cross-plan-deps`). `severity: warn` if §Section absent.
- `cross-plan-deps §N[ row M][ + §K row M][ (descriptor)]` — cross-plan-deps multi-row form.
- Literal `none[ (descriptor)]` — forward-compat scaffold or no-spec rationale. `severity: info`.
- Bare Plan-local IDs (`Cn` / `Pn` / `Pr-n` / `In` / `I-NNN-N` and ranges `I-NNN-N..M`) outside any `Spec-NNN` namespace prefix. Pattern: `^(?:C|P|Pr|I)-?\d+(?:\.\.\d+)?(?:-\d+(?:\.\.\d+)?)*$`. `severity: warn` in `**Spec coverage:**`; canonical (no warn) in `**Verifies invariant:**`.

Rejected shapes (each emits one failure with `severity: error`; **blocks Gate 4**):

- **`compound-range-multi-subject`** — `Spec-NNN lines YY-ZZ (...)` where the descriptor names ≥ 2 distinct identifier-token subjects (e.g., `PresenceUpdate/PresenceRead`). One-anchor-per-behavior rule. Defense-in-depth: a payload-level scan runs after per-segment parsing and re-fires this rule when the surrounding shape (multi-§Section, mixed-namespace continuation) prevented `parseSpecSegment` from reaching the range branch.
- **`namespace-violation`** — `Plan-NNN:LLL` (colon-line-number) inside any `Spec-NNN ... (... Plan-NNN:LLL ...)` parenthetical. Plan-NNN line cites do not belong in `**Spec coverage:**`. Discriminator: `Plan-NNN §Section` (no colon-line-number) inside the same parenthetical is accepted as legitimate cross-plan context.
- **`plan-local-id-as-spec-anchor`** — `Spec-NNN <PlanLocalID>` (e.g., `Spec-002 C5`) at first anchor position. Plan-local row IDs are not Spec-NNN anchors. Discriminator: `<PlanLocalID> (Spec-NNN line YY — descriptor)` (Plan-local-ID outside Spec namespace prefix) is accepted.
- **`phantom-section`** — `Spec-NNN §<section>` where the section heading does not exist in `docs/specs/NNN-*.md` (case-insensitive substring match against `^#{1,6}\s+<section>\s*$`).
- **`spec-file-not-found`** — `Spec-NNN ...` where `docs/specs/NNN-*.md` glob has zero matches or multiple matches.
- **`out-of-range-line`** — `Spec-NNN line YY` where YY is blank or past EOF.
- **`subject-mismatch`** — `Spec-NNN line YY (Subject)` where the identifier-token `Subject` does not appear on line YY of the spec (tolerant of separator variants: `PresenceHeartbeat` ↔ `presence.heartbeat` ↔ `presenceHeartbeat`).

`unparseable-spec-subanchor` (Spec-NNN sub-token that didn't match any sub-shape), `unparseable-cite` (top-level token that matched no namespace pattern), and `plan-local-id-malformed-trailer` (plan-local-id segment with a leading `,` / `;` / `+` trailer, e.g. `I-024-3, typo`) all emit at `severity: error` and block the gate — they close false-green paths Codex flagged on PR #96: a malformed sub-anchor used to silently warn-pass, a top-level token like `xyz junk` used to silently warn-pass despite §Pre-3 implication 6 mandating error reporting, and a comma-separated plan-local-id list (`I-024-1, I-024-2`) used to swallow the trailing IDs into the first anchor's descriptor. The top-level splitter now also recognizes `, Cn`/`, Pn`/`, Pr-n`/`, In`/`, I-NNN-N`/`, none` as segment boundaries so multi-id payloads split cleanly. Namespace-recognized but shape-malformed cites (`adr-unparseable`, `arch-doc-unparseable`, `cross-plan-deps-unparseable`, `plan-local-id-unparseable`) stay at `severity: warn` to fail-open on unknown shape variants the parser doesn't yet recognize.

#### Semantic anchor check — verifier rules

Each emitted anchor is verified by `verifyAnchorAgainstSpec(anchor, repoRoot)`:

- `type: line` — locate the spec file via `findPaddedFiles(specsDir, anchor.spec)`. Fail with `spec-file-not-found` if no match, or `spec-file-ambiguous` if multiple files share the same numeric prefix. Then read line `anchor.line`; fail with `out-of-range-line` if blank or past EOF. If `subject` present, lowercase + strip-punctuation both sides and verify subject tokens appear on the cited line. Fail with `subject-mismatch` if not.
- `type: line-range` — verify `[anchor.start, anchor.end]` lies within file bounds and `anchor.start <= anchor.end`; fail with `line-range-out-of-bounds` otherwise. If `anchor.subject` present, search the cited range _plus ±2 ambient lines_ (clamped to `[1, specLines.length]`) for the normalized subject token; fail with `subject-mismatch-in-range` if absent. The ambient window exists because Spec contracts commonly name the identifier on a prose intro line immediately above (or below) a fenced shape block — e.g., in Spec-002 §Rate Limiting the "When a rate limit is exceeded" intro line naming `RateLimitResponse` sits immediately above the canonical-shape code block it introduces. Citing only the shape was previously over-rejected, forcing authors to widen the range artificially; the ±2 bound preserves intent (cite the shape) while accepting one-line introductions on either side.
- `type: ac` — find `^## Acceptance Criteria` heading; count `^- \[[ x]\]` bullets in the section; assert the X-th exists. If `lineHint` present, assert that line is the N-th AC bullet specifically (fail with `ac-line-hint-wrong-bullet` when the hint lands on a different AC index, `ac-line-hint-outside-section` when outside §AC, `ac-line-hint-not-bullet` when not a checkbox row). A named section must CONTAIN the criterion, under the same prefix-vs-inherited rule as `ac-line` above; the check runs against the resolved AC bullet's own line, so the hintless `§X AC-N` shape — which cites no line at all — is bounded too.
- `type: section` — verify named section heading exists in the spec. Matching is exact-after-normalize (lowercased + non-alphanumeric stripped); partial heading prefixes like `§Token` against `Token Security Properties` fail with `section-not-found`.
- `type: adr-section` — file-existence check against `docs/decisions/NNN-*.md` (via `findPaddedFiles`). Fail with `adr-file-not-found` if no match, or `adr-file-ambiguous` if multiple files share the same numeric prefix. Section + item/row are not mechanically verified (they are documentary).
- `type: arch-doc` — file-existence check against `docs/architecture/**/<filename>` (recursive via `findArchDocFiles`, handling the `contracts/` and `schemas/` subdirs). Fail with `arch-doc-not-found` if no match, or `arch-doc-ambiguous` if the filename collides across subdirs. Section is documentary.
- `type: cross-plan-deps` — file-existence check against `docs/architecture/cross-plan-dependencies.md`. Fail with `cross-plan-deps-file-not-found` if missing. Section + row are documentary.
- `type: none-literal` / `type: plan-local-id` — trivial pass (no external doc to verify). Reason: `no-external-doc-to-verify`. **True for `C5` / `P3` / `Pr-3`, false for `I-024-4`**, which names its owning plan in its own bytes; those are resolved separately by §Invariant-reference resolution below, not here.

The existence checks above are gated by orchestrator-supplied paths (`adrsDir`, `archDocsDir`, `crossPlanDepsFile` in `verifyAnchorAgainstSpec` opts). When a path is omitted (e.g. unit tests that only exercise Spec verification) the verifier returns `valid: true, reason: <namespace>-dir-unconfigured` — anchors pass instead of false-failing the test. `gateTasksBlockCites` resolves all paths from `repoRoot` so production runs always exercise existence checks.

#### Gate 4 aggregation

`gateTasksBlockCites(phaseSection, planNumber, phaseNumber, opts)` collects (a) the token-presence floor result and (b) the semantic-anchor failures across every cite in the phase. The gate halts when any failure has `severity: error`; `severity: warn` failures surface in the report but do not block. The halt message lists each blocking failure with `[kind] T-N.M (field): message` + `cite: <raw>` + `fix: <remediation>`, and cross-links the authoring contract (`docs/operations/plan-implementation-readiness-audit-runbook.md` §Subagent Prompt Template) and this verifier contract.

**Size-classed tiering.** When `opts.sizeClass` is `S` or `M`, grammar/format kinds demote from blocking errors to warnings — they ride the ok-path return (`{ ok: true, warnings }`) and, when the gate still halts on other findings, a `Demoted to warnings under size-class <X>:` block lists them so they are never silent. Demotion additionally re-applies the existence floor: a demotable parse failure whose raw payload names a Spec that does not resolve to exactly one file stays HARD (no-anchor parse kinds never reach the verifier, so the spec-file check is re-run at the demote gate). The demote set (`G4_GRAMMAR_DEMOTE_KINDS`) is **fail-closed**: it enumerates exactly what demotes (parser grammar/format kinds and AC line-HINT refinement kinds — NOT the semantic `subject-mismatch` kinds, which stay hard because a cited line that names different behavior is a content failure, not a format one), so every existence-shaped kind — file-not-found / section-not-found / line-out-of-range / AC-missing and every FUTURE kind — stays a hard error for every class. L phases (and calls with no `sizeClass`) keep the full grammar hard-gate unchanged. The token-presence floor stays hard for all classes.

#### Invariant-reference resolution

`verifyInvariantReferences(section, opts)` resolves every `Verifies invariant:` id against the `## Invariants` block of the plan the id NAMES, across **both marker channels** — the bold `**Verifies invariant:**` form (`extractCiteAnchors`) and the legacy compact-inline form (`extractInlineCitePayloads`). The two channels are counted and reported separately and never summed: a single combined total is how 58 references across Plan-008 — a plan with zero bold markers — reached no screen at all while the gate printed a clean number.

Each reference is first classified, fail-closed: an owning id (`I-NNN-M`, any depth) resolves as itself; a range (`I-NNN-…-A..B`) expands to its members, capped at 64 (a wider span is a typo, not a citation); a plan-local id that names no owning document (`C5` / `P3` / `Pr-3` / a bare `In`) is silent by construction; and anything else in the structured `I-NNN-…` namespace is `invariant-reference-malformed` — a token the screen is supposed to resolve and cannot. That last arm is deliberately shape-scoped rather than "every parse failure in the field": prose descriptors and `Spec-NNN §…` references also appear there, and adjudicating what the field may CONTAIN is a separate question from whether an invariant id resolves. **The unit of count is the reference, not the member** — a range spanning five declared invariants is one resolved reference, and every undeclared member reports individually while the reference counts as zero.

Kinds: `invariant-undeclared`, `invariant-plan-not-found`, `invariant-plan-ambiguous`, `invariant-block-absent`, `invariant-block-unparsed`, `invariant-reference-malformed`, `invariant-test-id`. Structural failures (the last four shapes of owning-plan lookup) report **once per owning plan**, not once per citing reference. A facet id (`I-008-7c`) rolls up to its declared parent (`I-008-7`) and is counted as `parentResolved` — a weaker claim, printed as such, because the sub-clause letter is declared nowhere.

The screen runs on **both paths**. Under `--survey` it emits the census (references resolved per channel, `none`-arm acceptances, facet roll-ups, and the fenced-YAML disclosure below) — a zero finding count is ambiguous between "clean" and "never ran", and those numbers are the only evidence anything was checked. On the **dispatch path** it runs from `_checkPhase` against the selected phase and halts with `## Preflight halt: Gate 4 invariant-reference resolution failed`, emitting no census lines (survey-scoped reporting a dispatch has no business printing). Without the dispatch leg a phase citing `I-999-1` was dispatch-eligible, because the token-presence floor counts the marker and the anchor verifier passes any plan-local id untouched. None of these kinds is in `G4_GRAMMAR_DEMOTE_KINDS` or `LEGACY_INLINE_EXEMPT_KINDS`, so they gate for every size class and on exempt plans alike.

**Fenced-YAML disclosure (not verification).** Ids inside fenced `verifies_invariant:` YAML — task-DAG blocks and Shipment-Manifest entries alike — are masked from both extractors, so the survey prints how many references it did NOT screen. The live total is pinned by no test and quoted by no doc, because every Phase-E Shipment-Manifest append moves it; `preflight-gate4.test.mjs` reconciles the two readers by IDENTITY instead — the fenced reader's ids and the Shipment-Manifest parser's ids must cover each other exactly, leaving two named residues empty: fenced ids the manifest does not claim (a task DAG committed into a plan file) and manifest ids the fenced reader did not see (drift between the two readers of one fence). Comparing the two TOTALS would be unsound in a way that hides exactly the defect the check exists for — a missed manifest id cancels a counted task-DAG id, so the difference reads zero precisely when the readers disagree — which is why `verifyInvariantReferences` returns the `fencedYamlRefIds` list alongside the `fencedYamlRefs` tally. Both residues are satisfied by silence — a plan whose Shipment Manifest disappears has both readers return nothing and passes vacuously — so the same test carries a pinned per-plan floor naming the plans that must each contribute at least one manifest reference; it is pinned rather than derived because a set derived from the bytes under test is that vacuity hole, and it is a floor rather than an equality so a plan newly carrying a manifest never fails it. The count reads the key line and its continuation lines (block sequences and wrapped flow lists), applying the fencedness oracle per counted line; a key-line-only count read 48 while 67 existed, understating the unscreened surface while looking precise.

#### Why error vs warn

The seven rejection classes above correspond 1:1 to defect classes the post-mortem named — each one shipped a load-bearing semantic regression to `develop` that Codex would have caught had Phases 3-6 reached non-draft review. Treating them as `error` is the verification-side half of the root-cause fix; the authoring-side half is the four mechanism clauses in the runbook §Subagent Prompt Template (per-anchor verify / one-per-behavior / Plan-vs-Spec namespace / return-DONE self-verify). `warn`-level findings (bare §-cites, bare ACs, unknown-shape long tail) surface for human review without forcing a re-audit on every plan that pre-dates the new contract — the gate is additive, not retroactively destructive.

#### Cross-link

The cite-amendment subagent template (`docs/operations/plan-implementation-readiness-audit-runbook.md` §Cite-Amendment Subagent Prompt Template) names Gate 4 as its orchestrator-side verifier: subagent self-verification is authoring discipline; Gate 4 is enforcement. Both layers must be present — neither alone closes the post-mortem root cause.

### Gate 5 — Phase preconditions

Two independent legs, **both** of which must pass: structured entries (the `preconditions:` YAML block, else the prose `**Precondition:**` line) and a scan of the phase's `**Preconditions**` checkbox rows. Neither leg disables the other; when both fail, the halt reports both.

The structured leg parses the phase's `preconditions:` YAML block (see plan template § Implementation Phase Sequence). For each entry:

- `{type: pr_merged, ref: <N>}` → `gh pr view <N> --json state` returns `MERGED`.
- `{type: adr_accepted, ref: <NNN>}` → `docs/decisions/<NNN>-*.md` Status field equals `accepted`.
- `{type: plan_phase, plan: <NNN>, phase: <N>, status: merged}` → that plan's `### Shipment Manifest` block fully ships every declared task for Phase `<N>` (declared ⊆ shipped, the same set-comparison Gate 3 runs on the local plan). Pre-round-7 the resolver matched any phase entry (`some(e.phase === entry.phase)`); after manifest entries became task-level under NS-02, that became a partial-ship false-positive — Plan-001's T5.1 entry would unblock a downstream Plan-001 Phase 5 dependency even though T5.5/T5.6 were unshipped (Codex P2 finding on PR #35 round 7). Halt outcomes: `partially_shipped` (lists missing tasks), `manifest_unparseable` (mirrors Gate 3's strict halt on parse failure), `no_phase_section` (upstream plan lacks the requested phase). Fail-open outcomes: `fully_shipped` (precondition satisfied), `manifest_future_schema` (mirrors Gate 3's schema-version-future fail-open), `no_declared_tasks` with a phase-presence match (legacy fallback for plans whose `#### Tasks` block lacks task ids — phase-presence in the manifest is treated as evidence of completion). (Pre-Commit-6 the resolver matched on `## Progress Log` prose for `Phase N` or `PR #N` substrings; the new mechanism reads the structured manifest the same way Gate 3 does.)
- `{type: cross_plan_carve_out, ref: <id>}` → entry exists in `docs/architecture/cross-plan-dependencies.md` §5. The membership check is scoped to §5 only via the shared `extractSection5` helper — pre-fix it used `source.includes(ref)` over the whole file, which passed when the ref appeared in §3 prose or §6 NS-rows even when §5 had no entry. Tool only verifies §5 presence, not semantic correctness; the substantive shape check (substrate-vs-namespace structure) is covered by the `audit_status: substrate_exempt` criterion (3) below.
- `{type: audit_status, status: complete, evidence_pr: <PR#>, baseline_tag: <git tag>}` → the act of declaring `complete` is the load-bearing assertion (matches the existing Gate 2 behavior of trusting the human-set checkbox). `evidence_pr` + `baseline_tag` are documentary; preflight does not mechanically verify them — see runbook §Per-Phase Audit Semantics.
- `{type: audit_status, status: substrate_exempt, carve_out_ref: <§5-heading-text>}` → three criteria. (1)+(2) human-judged at audit time per Plan-007 §Execution Windows. (3) is mechanically verified: (a) `carve_out_ref` MUST appear inside §5 of cross-plan-dependencies.md via the shared `extractSection5` helper; (b) phase body MUST contain one of the canonical empty-coverage sentinels (`covers no Spec-NNN acceptance criteria`, `covers NO Spec-NNN AC`, `substrate is pre-behavior plumbing`); (c) the `#### Tasks` block MUST NOT cite Spec coverage in bracket-form (`Spec coverage: [Spec-NNN row M]`) — prose-form mentions are tolerated because they describe coverage absence. A phase that declares `substrate_exempt` ALSO causes Gate 4 (Tasks-block G4 cites) to be skipped — by criterion (3) the phase ships zero Spec AC, so Gate 4's "Spec coverage" substring requirement would halt it by design.
- `{type: external_plan_phase_merged, plan: <NNN>, phase: <N | R<n> | <n>X>}` → the corpus's structured form for cross-plan phase gates (Plan-007's R-section YAML blocks already declare it). An **integer** `phase` delegates to `plan_phase` semantics verbatim. A **label string** — remainder (`phase: R2`) or supplement (`phase: 3B`) — resolves by task-set membership: every task id declared in the upstream's `### Phase R2` / `### Phase 3B` section must appear in that plan's manifest shipped task lists under **any** integer phase. Neither label shape can ever be a manifest phase key (the entry validator forces positive integers), so phase-key equality is structurally unanswerable; membership halts today (`Phase R2 not shipped — missing tasks: …`) and passes when the labelled section's tasks ship. Both label shapes share one grammar constant with the `--survey` label scan and the explicit phase-argument parser (§Invocation), so what this gate accepts as an operand and what the CLI accepts as a dispatch target cannot drift apart in spelling — they differ only in that supplement labels are additionally dispatchable and remainder labels are not. Fail closed: a missing labelled section, zero parseable task ids, an unparseable manifest, or a malformed `phase` value all halt; a future-schema manifest opaque-passes, mirroring `plan_phase`. Introduced for Plan-022 Phase 1's Plan-007 R2 (`DaemonKeyStore`, CP-007-8) gate — Codex P2, PR #193 round 4.
- `{type: bl_closed, ref: <N>}` → backlog item `BL-<N>` (the `ref` is zero-padded to three digits) has Status `completed`. The resolver reads `docs/backlog.md` first via the shared `extractBacklogItemSection` helper; when the item is absent from the active backlog — the normal post-resolution state, since closed items are swept to `docs/archive/backlog-archive.md` per the CLAUDE.md backlog discipline — it falls through to the archive. In **both** locations the Status line is re-parsed by `judgeBacklogCompletion` and must read `completed`: archive presence is never trusted on its own, because the archive also holds `withdrawn`/`superseded` items that did not land (BL-136 is the canonical `withdrawn` example). Halt outcomes: any open state (`todo`/`in_progress`/`blocked`), a non-`completed` archived state, an unparseable Status line, or a `BL-<N>` found in neither file (mint the item or correct the ref). Introduced for Plan-003 Phase 3 (NS-32), which gates on the Spec-003 §Default-Behavior heartbeat-threshold amendment — a governance change whose PR number is unknowable at declaration time and whose value is a spec default, not ADR-worthy, so neither `pr_merged` nor `adr_accepted` can express the dependency (Codex P2 on PR #138).
- `{type: precondition_box_checked, box: "<box-text prefix>"}` → the local plan's top-level `## Preconditions` section contains exactly one checkbox whose text (bold markers stripped) starts with `box`, and that box is checked. This is the machine-enforcement leg for **named scoped boxes** — the custom `## Preconditions` boxes Gate 7 deliberately does not match (its scan covers only the `000-plan-template` governance trio, because a scoped box gates specific phases, not the whole plan): without this entry, a custom box is documentation, not enforcement. Prefix-matched under the same convention as the Gate-7 trio (authors append dated notes after the box text). Fail closed on every indeterminate shape: no `## Preconditions` section, no box matching the prefix (fix the entry or add the box), an ambiguous prefix matching several boxes, an empty `box` value, or plan source unavailable to the resolver. The resolver reads the whole plan (`planSource`, threaded from the phase walk like `phaseSection`), not the phase section — the box lives at plan level; the phase-scoping comes from which phase declares the entry. **Carry the entry onto every phase the box gates**: the auto-walk treats a preconditions-ineligible phase as a soft skip and tries later phases (deliberately — see the walk's strict-halt list), so declaring the entry on one phase alone lets the walk select its successor past the unmet dependency; pair it with the sequential `plan_phase` chain on those later phases (Codex P1, PR #212 round 5 — live repro: Phase 1 shipped + box unchecked auto-selected Phase 3). Introduced for the Spec-012 Part-B ask-expiry legs — Plan-012 Phase 2 gates on the B13-authored T2.8 normalizer task, Plan-004 Phase 3 on the B9-authored park-leg task, each declared as an unchecked box the owning bundle PR checks (a task id unknowable at declaration time, and `bl_closed` would mint backlog items for work already tracked by the campaign) — Codex P1, PR #212 round 4: the boxes' original text claimed Gate-7 enforcement that gate never implemented.

If the phase has no `preconditions:` YAML block (legacy plan), fall back to regex parsing of the prose `**Precondition:**` line. Four patterns are recognized (all case-insensitive):

- `PR #N merged` → `{type: pr_merged, ref: N}`
- `ADR-NNN accepted` → `{type: adr_accepted, ref: NNN}`
- `Plan-NNN Phase K merged` → `{type: plan_phase, plan: NNN, phase: K, status: merged}`
- `Phase K merged` (bare, no `Plan-NNN` prefix) → `{type: plan_phase, plan: <local plan>, phase: K, status: merged}`. The bare form resolves to the plan the precondition lives in — corpus convention across Plan-001/003/007/024. The bare-form regex carries a negative lookbehind `(?<!Plan-\d{3}\s+)` that excludes the segment inside an already-matched `Plan-NNN Phase K merged`, so providing the explicit-prefix form does not produce a duplicate entry against the local plan.

The `audit_status`, `cross_plan_carve_out`, `bl_closed`, and `precondition_box_checked` types are YAML-only — they have no prose-line analog. Prose preconditions that interpolate link-text or other tokens between `Phase K` and `merged` (`[Plan-NNN Tier K Partial](...) merged`, `Plan-001 Phase 5 CP-001-2 cwd-translator merged`) are NOT matched by either regex; the line emits zero entries and `gatePreconditions` silently passes (legacy free-form tolerance). Express such cross-plan carve-out dependencies as a YAML `cross_plan_carve_out` + `pr_merged` pair to put them on the machine-enforced path (Plan-002 Phase 2's Plan-025 Tier 1 Partial dependency is the canonical example). Both schema and regex failures escalate to exit code 2 if the precondition is wholly unparseable.

**The checkbox leg.** Independently of the above, the gate scans the phase section for `**Preconditions**` bold headers (`.`, `:`, or bare — the corpus writes `**Preconditions.**`) and collects the `- [ ]` / `- [x]` rows beneath each one. Two kinds of structural line bound a region, differently: an ATX heading or a bold paragraph at column 0 **ends** the preconditions area (boxes beyond it belong to new prose and are ignored), while a ```-fence line or an HTML comment (the `<!-- prettier-ignore -->` pragma preceding most YAML blocks) only **suspends** it — canonical layout puts the YAML block after the COMPLETE checkbox list, so a box found between the fence/pragma and the next prose break is an **orphan** and halts, checked or not, with a move-it-above-the-fence remediation (a ticked box stranded below the fence is one un-tick away from gating nothing, silently — the fail-open class recurring as a layout defect). Indented lines are bullet continuations and bound nothing. Every header in the section arms a fresh region. **Any unchecked box halts**, listing each unchecked row verbatim (elided past 120 characters); all-checked, no boxes, and no header alike pass.

The two legs are additive because they answer different questions. YAML entries are the machine-enforced depth — resolvable facts a tool can check. The boxes are the human-tracked record, and they include gates no entry type can express: D-ratifications, spec-amendment adoptions, upstream substrate landings (Plan-010 Phase 1 alone carries three — its D-010-2/5/11 ratification rows; the phase's other two boxes are the `plan_phase` entries its YAML block does encode). Letting a YAML block suppress the scan would retire those rows permanently — a later amendment could un-tick one and the phase would still dispatch. Before this leg existed the plural header matched no recognized form at all, so Gate 5 read every such phase as an undeclared legacy plan and passed it: Plan-009 Phase 2 resolved eligible with its Plan-006 Phase 3 box unchecked (Codex P1, PR #251 round 2). Note the residual: a singular `**Precondition:**` header carrying a parenthetical (`**Precondition (campaign B10):**`, Plan-005 Phase 3) matches neither the prose regex nor the checkbox header, so such a phase resolves on its YAML block alone.

### Gate 6 — Manifest freshness (plan-level; executed before the phase walk)

Cross-checks the plan's `### Shipment Manifest` against merged PRs whose **title** cites the plan, and halts when a merged material PR has no manifest entry. Numbered 6 by accretion order (Gates 1-5 keep their historical numbers), but EXECUTED between Gate 2 and the per-phase walk: Gate 3 and Gate 5's `plan_phase` resolver both treat the manifest as authoritative, so a stale manifest corrupts phase selection — a merged-but-unrecorded shipment re-opens an already-shipped phase and re-dispatches completed work. That silent-drift class is exactly what [BL-110](../../../../docs/archive/backlog-archive.md) tracked: the post-merge housekeeper is the sole manifest writer, and any run that dies between merge and housekeeping (or any follow-up PR shipped outside a plan-execution run) leaves the manifest silently stale.

**This is not a return to the gh-search shipment inference Gate 3 removed** (§Gate 3 "Why manifest set-comparison, not gh search"). The manifest remains the sole authority for phase selection; gh is consulted only to cross-check manifest **completeness** — ground truth stays git, the manifest is a cache. Three deliberate narrowings keep the old false-match classes out:

1. **`in:title` only, never `in:title,body`.** PR bodies cite plans in passing constantly (the 2026-07-06 baseline sweep measured 80 body-matches for Plan-001 alone); titles cite the plan they ship for. The empirical sweep found title-search precision exact across all 27 plans. Recall is the traded cost: a shipment PR whose title omits the `Plan-NNN` token is invisible to this gate — which is why the Phase 0.3 scaffold makes the token mandatory in PR titles. That same recall trade is the enhancement-lane boundary: lane-2/3 PRs (CONTRIBUTING.md §How Code Lands) deliberately omit the token and are invisible to this gate by design.

   **Strict-token post-filter.** GitHub's `in:title` is a **tokenizer** match, looser than a word-boundary match, so the returned rows are re-filtered locally through `hasPlanTitleToken(title, paddedPlan)` — `/\bPlan-NNN\b/i` — before anything else. `rebuild-shipment-manifest.mjs`, the tool this gate's own halt text prescribes as the remedy, **imports that same predicate**: the two must agree on the population or the tools deadlock. They did on 2026-08-15 — Gate 6 halted Plan-025 naming merged PR #216 (`chore(repo): retire Plan-007/025 compact-inline cite exemptions`, which GitHub tokenized into a `Plan-025` match though that literal token never occurs in it) while rebuild's word-boundary test correctly declined to emit an entry, leaving the operator a halt with no move. Sharing one exported predicate makes that divergence unrepresentable; the `i` flag is load-bearing on both sides (a lowercase `plan-001` title is search-visible). The filter can only **remove** candidates, so its risk is blinding the gate, not false-halting it: a corpus sweep on the same date over all 28 plans found 118 of 125 tokenizer matches survive it, and of the 7 rejected only #216 touches a material path — the rest are `ADR-024` / `cp-004-12`-style numeric collisions that the material-path filter already excluded. A **third** matcher exists and is deliberately not shared: `tools/docs-corpus/bin/lane-boundary-check.ts` §`extractTitlePlanTokens` runs pre-merge in CI and _extracts_ every plan a title cites (`/\bplan-(\d{3})\b/gi`) rather than testing one, so it cannot take a `paddedPlan` argument. It agrees with `hasPlanTitleToken` by construction — same boundaries, same case-insensitivity, same 3-digit width, verified 2026-08-15 across the compound / lowercase / 4-digit / `workplan-` / numeric-collision shapes. That guard left-shifts _part_ of the class `non_shipment_prs` cleans up after, and the scope matters: it fails a tokened material PR only when **neither** a `<type>/plan-NNN-*` branch **nor** a `docs/plans/NNN-*.md` edit is present. PR #216 itself would pass it — its diff touches `docs/plans/007-*.md` and `docs/plans/025-*.md` alongside one material file (`.github/workflows/docs-corpus.yml`), and that plan-doc allowance is presence-only by design (a content check cannot distinguish an amendment from a prose edit). The ratified-non-shipment residual is therefore permanent, not a pre-guard legacy: a tooling PR that edits plan docs can still merge carrying a token and reach this gate.

2. **Material-path filter.** Only candidates whose diff touches a material path — `packages/`, `apps/`, `.github/`, or `deploy/` (`MATERIAL_PATH_PREFIXES`) — count as shipments (two commands per candidate: `gh pr view N --json changedFiles` for the authoritative count, and `gh api repos/{owner}/{repo}/pulls/N/files --paginate --jq '.[].filename'` for the file list, reconciled against that count). `packages/` + `apps/` are the ownership map's code families; `.github/` is included because Plan-024 Phase 4 ships workflow-only tasks whose sole file is `.github/workflows/sidecar-build.yml` (T-024-4-1; Codex P2 on PR #182); `deploy/` is included because Plan-025 ships self-host compose tasks whose files live under `deploy/self-host/` alone (T-025d-14-1) — formerly the G6 blind spot the token-first rebuild redesign could only mitigate downstream. The inverted form (material = anything outside `docs/`) was rejected on corpus evidence: governance PRs whose titles cite plans also ship root files — PR #1 touches `.gitignore` / `README.md` / `AGENTS.md` under a Plan-001 title — so exclude-docs would permanently false-halt Plan-001. Root-config-only shipments remain outside the predicate; no plan in the ownership map ships root files alone, and the filter should be revisited if one appears.
3. **Halt-with-remediation, never auto-derive.** A missing entry halts and names `rebuild-shipment-manifest.mjs --plan NNN --dry-run` as the reconciliation path. The gate never writes manifest entries itself: rebuild's operator-confirmation model owns phase/task attribution ambiguity, and BL-110's option-(b) self-healing was deliberately adapted to fail-closed-with-remediation for that reason.

**The ratified-non-shipment escape (`non_shipment_prs`).** The strict-token filter closes the tokenizer class but not its residual: a title can carry a **genuine** `Plan-NNN` token and still have shipped none of that plan's tasks. PR #216 is both cases at once — `Plan-007` really is a token inside `Plan-007/025` (`/` is a word boundary), yet it is a lane-3 tooling PR, and the manifest schema has no honest `shipped[]` shape for it (every entry requires a `phase`/`task` pair it does not have). The manifest's optional top-level `non_shipment_prs: [216]` key resolves it: Gate 6 subtracts those numbers from the candidate population after the strict-token filter and before the per-PR `gh pr view` fetch, and `rebuild-shipment-manifest.mjs` skips them so it never re-proposes an entry the operator ratified away (it does round-trip the key into its `--dry-run` stream).

Use it **only** for a merged PR that carries this plan's title token but shipped no task of it — normally a lane-2/lane-3 PR whose title violates the lane convention. It is never a substitute for a `shipped[]` entry, and never a way to quiet a halt about work that did ship. The key is deliberately an explicit, greppable, review-visible operator assertion rather than a heuristic: an **unratified** title-tokened material PR still halts, so the gate stays fail-closed. Values parse strictly (positive integers only, and none may also appear as a `shipped[]` entry's `pr` — the two keys make opposite assertions about one merge; `reason: "invalid_non_shipment_prs"` otherwise, surfaced by Gate 3 with a per-value diagnostic) — a permissive read would let a typo silently widen the exemption, the one failure mode a fail-closed gate cannot tolerate. Schema authority and the full rationale live in `.claude/skills/plan-execution/scripts/lib/manifest.mjs`; the key is additive and does **not** bump `manifest_schema_version`.

Outcome table:

- Manifest unparseable → **pass** (`deferred_to_gate3` — Gate 3 owns the structural halt with richer remediation; running the cross-check on an unparseable manifest would double-report).
- Manifest schema-version future → **pass** (mirrors Gate 3's only intentional fail-open).
- All merged in-title material PRs present in `shipped[].pr` → **pass**.
- Search row whose title fails `hasPlanTitleToken` (tokenizer artifact) → **dropped before the per-PR fetch**; never a candidate, never an API call.
- Candidate listed in the manifest's `non_shipment_prs` → **dropped before the per-PR fetch** (operator-ratified non-shipment).
- Missing material PR(s) → **halt** listing each PR (number, merge date, material-file count, title) + the rebuild remediation + the `non_shipment_prs` ratification path + the escape flag.
- gh unreachable / malformed output → **halt** (fail closed per the ADR-023 gate-vs-detector discipline: gates fail closed, detectors warn; a manifest that cannot be cross-checked is treated as potentially stale, not silently trusted).
- `gh pr list` returns exactly `FRESHNESS_FETCH_LIMIT` rows → **halt** (possible truncation; mirrors rebuild's exit-6 saturation sentinel).
- Per-PR file list does not reconcile — the paginated walk returned a different number of paths than `changedFiles` reports, in either direction, or that count was absent → **halt** (`freshness_files_unreconciled`; mirrors rebuild's exit-7 discipline; an unclassifiable candidate cannot be assumed doc-only). GitHub documents that the files endpoint's responses "include a maximum of 3000 files", and a walk that reaches that ceiling stops with no in-band signal, so the count is the only completeness evidence there is. `gh pr view --json files` is deliberately not the source: it compiles to a single `pullRequest.files(first: 100)` GraphQL page and halted this gate on every candidate above 100 files.

### Gate 7 — Plan status promotion (plan-level; executed before the phase walk)

Reads the plan's header-table ``| **Status** | `x` |`` row (the `000-plan-template` shape). `approved` and `completed` pass; `draft` / `review` halt with the promotion remediation (a `completed` plan still halts truthfully at Gate 3 — all phases shipped). A missing or unparseable Status row halts (fail closed); the search is scoped to the plan header region (before the first `##` section heading), so a Status-shaped table row embedded later in the body cannot green-light a plan whose header row is missing. Rationale: the corpus promotion gate (CLAUDE.md §Current State, AGENTS.md §Doc-First Discipline) admits a plan's first code PR only after `review` → `approved`, but Gate 2 verifies only the AUDIT fact — before this gate an audit-complete `review` plan cleared preflight end-to-end and the pipeline would scaffold a code branch off an unpromoted plan (Codex P2, PR #193). Runs immediately after Gate 2, before the phase walk and before Gate 6's `gh` calls, so the halt path is network-free. CLI escape: `--allow-unpromoted` (stderr-logged); promotion itself stays a human act — this gate only makes skipping it explicit instead of silent.

The same gate — same placement, same escape flag — also runs `gatePlanPreconditionBoxes`: a scan of the plan's top-level `## Preconditions` section for unchecked **plan-governance** boxes, the `000-plan-template` trio `Paired spec is approved` / `Required ADRs are accepted` / `Blocking open questions are resolved…` (prefix-matched, since authors append dated gate notes after the box text; the template quartet's fourth box — the plan-readiness audit — already halts at Gate 2). Any unchecked governance box halts, listing the boxes verbatim. Rationale: a W1 spec-amendment flip records `approved → review` on the SPEC and re-opens the plan's paired-spec box, but the plan's own header Status stays `approved` — so the status row alone green-lit dispatch against an un-promoted spec (Codex P2, PR #202: Plan-010's Phase 1 was selected with its paired-spec box unchecked). Deliberately NOT every unchecked box in the section: plans also carry scoped upstream-dependency boxes — Plan-023's `(Tier 8 remainder only.)` boxes, Plan-024's procurement boxes gating Phases 4–5 only — whose unchecked state must not halt phases they do not gate; that subset gating belongs to per-phase `preconditions:` blocks (Gate 5), where the `precondition_box_checked` entry type puts a named scoped box on the enforced path.

## Survey mode

    node .claude/skills/plan-execution/scripts/preflight.mjs --survey

Corpus-wide extractor screen — no plan file, no gates, no network. Iterates every `docs/plans/NNN-*.md` (the `000-` template excluded), walks each plan's `### Phase N` headings, runs the production extractors (`extractTasksBlock` → `extractDeclaredTaskIds` / `extractDeclaredFilePaths` → `classifyPhaseSize`), and reconciles the parsed task-id set against a **deliberately looser raw oracle** in both directions. An oracle row is a Tasks-block line opening as a top-level bullet (optional GFM checkbox, 1-3 asterisks) or `#####` heading whose token begins `T<digit>`/`T-` — head-anchored so detail bullets that mention task ids in prose (`- **Step:** ... T3.6 ...`, the Plan-003 shape) are not rows, but tolerant in exactly the dimensions the extractor has historically missed (no closing-`**` tail — the PR #190 star-in-title class; 1-3 asterisks — bold-italic rows).

- **omission** — an oracle row no parsed id appears on: the extractor missed a real task row (the phase-falsely-shipped class; this direction caught the second-`#### Tasks`-block bug on PR #190).
- **phantom** — a parsed id absent from every oracle row: the extractor invented a task (Gate 3 would see the phase as never shippable).

Reconciliation compares head ids exactly: each oracle row's LEADING task id (the oracle regex only admits id-headed rows) must be a parsed id, and every parsed id must head some oracle row. Whole-row scans were abandoned after three misses — substring (`T1.1` covered `T1.10`), digit-only boundary (`T-025` covered `T-025d-14-1`), and tail cross-references (parsed `T2.1` covered an unparseable `- ***T2.7 — depends on T2.1***` row) — Codex P2, PR #192 rounds 2-5. Erring toward "not covered" is the fail-closed direction — a false anomaly is visible, a false pass is the miss class the screen exists for.

Output: one line per walked plan (`P<N> <class>(<id-count>)` per phase; a plan with no phase heading prints `0 phase(s) — whole-document cite sweep`), the S/M/L distribution, the coverage line (below), zero-phase plans as **notices** (they are invisible to `walkPhases`; a normal preflight run on one exits 2 fail-closed — the notice names that dispatch gap, and the whole-document sweep below covers the plan's cites regardless), and two anomaly lists (below). The **two-sided task-row `anomalies`** gate the exit: `0` clean / `1` on any anomaly — authoring and extractor-refactor workflows gate on it, and `preflight-survey.test.mjs` runs the real-corpus screen in CI (ci.yml's skill-test step) so a newly authored plan with an unparseable Tasks-block shape fails the PR that introduces it. The oracle is a screen, not a proof: a truncated-id parse whose prefix appears on the same row can still hide.

**Coverage line (fail-closed).** `coverage: N/M plan(s) cite-swept, K uncovered` prints on **every** run, ahead of every verdict line, because `cite anomalies: none` means "checked and clean" only when the screen actually reached every plan — a skipped plan folded into a clean verdict is a false-clean gate, which is the precise shape this line exists to make impossible. Phase-based scoping used to create exactly that: a plan with no `### Phase N` heading was `continue`d before any cite screen ran, and the verdict still printed `cite anomalies: none` (9 of 28 plans, zero cite coverage, exit 0). Those plans are now swept as a single **whole-document unit** instead of skipped, listed under `whole-document fallback`. The fallback keys on the COMBINED numeric + remainder label set, so the remainder-only shape (`### Phase R2` with no numeric phase) is covered too. A plan none of whose survey units carries a cite marker passes **vacuously**, and is listed separately under `swept but no cite markers to verify` so a nothing-to-check pass can never be read as a verified one. That test is per PLAN and applies to **both** unit shapes: it was once gated on the whole-document fallback, which left the phase-based spelling of the same emptiness undisclosed — a plan with even one `### Phase` heading never takes the fallback (it fires only at `surveyUnits.length === 0`), every markerless phase is skipped by `hasCiteMarkers`, and nothing recorded it, so the plan landed inside `N/N plan(s) cite-swept, 0 uncovered` carrying zero anomalies. Plans 023 and 028 were hidden exactly that way. A plan with markers in SOME units is verified, not vacuous — the flag keys on "no unit anywhere had markers". `K uncovered` is the residual: any plan whose survey throws is recorded by name with its reason and pushed to the two-sided `anomalies` channel, so it gates **unconditionally** — it does not wait for `--enforce-cites` to be armed. TWO throw sites reach it, not one: the per-plan survey catch, and a per-unit **cite screen** that throws (`[cite-check-threw]`, from `gateTasksBlockCites` or the inline anchor floor). The per-unit catch used to record its anomaly and stop there, leaving the plan inside `surveyedPlanCount` — so the coverage line counted a screen that never ran, `markerlessPlans` labelled the unrun screen a vacuous pass, and the stale-exemption ratchet below saw an exempt plan emitting zero findings and advised deleting a live exemption on evidence that was never gathered. That last guard already existed for the per-plan catch; the per-unit one walked past it. A screen that failed to RUN judged nothing, so either route marks the plan uncovered (deduped by name). There is deliberately no fourth path: every plan is swept, vacuous, or gated. Whole-document units are coverage devices, not dispatchable phases, so they are excluded from `phaseCount` and the S/M/L distribution.

**Intra-plan coverage — phase sections AND their complement.** A plan carrying at least one `### Phase N` heading is swept across its phase sections _and_ the **complement**: the set-difference between the plan source and the union of every phase span. The complement is derived by SUBTRACTION, never by matching heading shapes — the discriminator is position, not heading form — so a `### Tier-7 Remainder — …` block, a preamble ahead of Phase 1, and a trailing appendix are all screened without the walk needing a production for any of them. Phase spans and their complement partition the source; `unsweptMarkerPlans` is the partition-leak check and MUST stay empty (a non-empty entry means text belongs to neither side, which is a bug in the subtraction, not a new residual class).

Coverage is still counted per PLAN, so the marker-level denominator is printed explicitly with the coverage block on every run — ``Gate-4 markers OUTSIDE every `### Phase N` section — screened via the complement path (N plan(s), M marker(s))``, itemized per plan. That line exists because a zero finding count is meaningless without a non-zero denominator: a complement screen that regressed to a no-op would zero it while every other line of output stayed byte-identical. `docs/plans/025-self-hostable-node-relay.md` is the corpus's only material instance (32 of its 42 bold markers across 2 complement units). The 36 error-severity findings it carried when the screen was first armed were **repaired**, not suppressed — re-spelled into already-accepted anchor shapes in the same change, on the ruling that the plan was malformed rather than the grammar too strict (66 in-phase passing instances established the convention; Plan-025's spellings existed nowhere else in the corpus, so widening the parser to admit them would have been a CAT-10 factory).

**Marker-floor asymmetry (load-bearing).** `gateTasksBlockCites` requires BOTH `Spec coverage:` and `Verifies invariant:` on the dispatch path — one marker in a phase's `#### Tasks` block is a partial audit, and "the audit has not run" is the correct read. A complement has no audit output, so it takes `requireBothMarkers: false` and verifies whatever markers it carries. Without that split, an out-of-phase block holding only `**Spec coverage:** Spec-999 §Missing` failed the AND, returned before `extractCiteAnchors` ran, and was screened by nothing while the report counted its marker as swept — CAT-10 reproduced inside the CAT-10 fix (Codex P1, PR #262 round 1). Correspondingly, of the two survey-only marker-shape checks, **W4 legacy-unbold runs on every unit** (its predicate — "markers whose anchors the bold extractor cannot parse" — is well-posed anywhere text carries markers) while **W3 partial-marker stays phase-only** (its predicate is about audit output, which a complement does not have; firing it there would report a partial audit that never happened). The one deliberate residual that remains: marker-PAIR completeness inside complement regions is unscreened. Every anchor a complement marker carries IS verified.

**Field scope.** `**Consumes:**` is NOT a Gate-4 field. `extractCiteAnchors` scans only `**Spec coverage:**` and `**Verifies invariant:**`, so anchors and raw line pins inside a `Consumes:` payload are never verified — including inside a fully swept phase section. This is by design (Consumes records a dependency edge, not a spec claim), but it is stated here because a reader counting markers would otherwise read coverage the screen does not provide.

### Cite screen — per-phase Gate-4 (armed)

The survey ALSO runs the Gate-4 cite check (`gateTasksBlockCites`) on every survey unit — numeric phases, remainder phases (`### Phase R2`), the **complement** of every phase span on a phase-bearing plan, and the whole-document unit a phase-less plan falls back to — and records every finding in a SEPARATE `citeAnomalies` channel, kept out of the two-sided `anomalies` above. Fail-closed: a gate that THREW becomes a `[cite-check-threw]` entry on the two-sided `anomalies` channel — NOT `citeAnomalies` — so it gates **unconditionally**, exactly as an uncovered plan does. A screen that failed to RUN is a structural failure of the survey rather than a judgement about cite quality; parked in the gated channel it would wait for `--enforce-cites`, and a plain `--survey` run would exit 0 over a unit that was never screened. Both cite screens are internally fail-closed (a missing or unreadable spec becomes a `[spec-file-not-found]` FINDING, not a throw), so no corpus fixture reaches those `catch` arms; `surveyCorpus` therefore accepts `runCiteGate` / `runInlineAnchorFloor` seams — defaulting to the real implementations, with a test pinning the defaults — purely so the arms stay verifiable. Findings from a whole-document unit are labelled `<plan> (whole document)` where a phase unit reads `<plan> Phase <N>`. Kinds:

- The full Gate-4 anchor grammar (`unparseable-cite`, `unparseable-spec-subanchor`, `unbalanced-cite-quote`, `section-not-found`, `subject-mismatch`, `line-blank`, `ac-section-missing`, the `ac-line-*` and `ac-line-hint-*` families) — one row per finding.
- `[markers-partial]` / `[legacy-markers-partial]` — a phase with exactly one field-marker side present (`Spec coverage` XOR `Verifies invariant`, counting both the bold `**…:**` form and the unbold/inline `; …:` form). A zero-marker phase is an audit-not-run skip, not an anomaly; a lone side is a partial audit output. The kind is evidence-split: `[legacy-markers-partial]` when the partial phase holds ZERO bold markers (the partiality is proven legacy-inline debt), `[markers-partial]` when any bold marker is present (new-grammar authoring that must land the complete pair — this variant always gates, exempt path or not; Codex P2, PR #214 round 2). Classified by the line-anchored `classifyPhaseMarkers` (a bullet-head or `;`/`(` field position), NOT the dispatch gate's bare-substring `countCites`, so a prose mention of "Spec coverage" never trips it.
- `[legacy-unbold-marker]` — a phase carrying inline/unbold field markers (the Plan-008 `- **T-…** (…; Verifies invariant: …; Spec coverage: …)` style) that `extractCiteAnchors` — bold-only — silently skips, so their anchors are never verified: `countCites` reads > 0 and the extractor still parses nothing (the false-green class).
- `[inline-anchor-not-found]` / `[inline-doc-missing]` / `[inline-cite-violation]` / `[legacy-inline-descriptor-tail]` — the **inline anchor-existence floor** (Codex P2, PR #214 rounds 3-8). The PRIMARY pass runs the REAL Gate-4 grammar (`parseCitePayload`) over each unbold inline payload after two purely-cosmetic idiom normalizations (backtick strip; `docs/architecture/**/<name>.md` → basename), then verifies every anchor that parses with the REAL verifier at full fidelity — sections, ACs, line / line-range subanchors, subjects, hints. There is deliberately no floor-private grammar in this pass: rounds 3-5 each found a claim type a hand-rolled walker under-covered (§ sections, ACn, line/lines), so the real grammar is the only complete enumeration of Gate-4 claim types. A depth-0 `;` in the payload terminates it ONLY at a `; <Field>:` intro — the grammar's own `;` segment separator stays inside the payload, so trailing segments are parsed rather than truncated (round 6). Verify failures route by reason: document-resolution reasons (missing / ambiguous / unreadable file) → `[inline-doc-missing]`; a `section-not-found` whose cite-side longest-prefix resolves uniquely to a real heading (trailing parenthetical on the heading side stripped when exact match fails — unique-match guarded, so salvage can never over-accept) re-verifies the anchor's PRIMARY claim under the salvaged heading, then classifies: zero dropped words → clean, dropped words remaining → `[legacy-inline-descriptor-tail]` (the anchor RESOLVES; only the tail is legacy formatting — the one floor kind in `LEGACY_INLINE_EXEMPT_KINDS`, divertable-but-printed on exempt paths, gating everywhere else); every other failure → `[inline-anchor-not-found]` (fail-closed: an unrecognized verifier reason still gates, under the anchor-level kind). Parse failures split by semantic class (round 8): shape-class kinds (`INLINE_SHAPE_PARSE_KINDS` — the text simply did not match the strict grammar) are NOT floor findings AS SHAPES — malformation without a checkable claim is exactly the formatting debt `[legacy-unbold-marker]` already counts (and that kind gates by itself on non-exempt paths) — while every OTHER error-severity parse kind (the parse-time defect classes `namespace-violation` / `plan-local-id-as-spec-anchor` / `compound-range-multi-subject`, and any future kind, fail-closed; warn-severity kinds never gate, mirroring Gate 4 proper) routes to `[inline-cite-violation]` and gates on every path — a denied `Plan-NNN:LLL` line cite existence-checks as a clean Plan label, so no existence sweep can represent it. And the CLAIMS inside unparsed text do not escape: a SECONDARY existence sweep (rounds 6-8) walks the full normalized payload — descriptors, unparsed fragments, post-`;` segments — existence-checking every `Spec-NNN` / `ADR-NNN` / `Plan-NNN` / `<name>.md` label (`Plan-NNN` has no Gate-4 namespace, so its check lives only here) plus §Heading / ACn / line-N / row-id tokens under the nearest preceding Spec binding (walker-style; Plan / ADR / .md / `cross-plan-deps` labels reset the binding — their §/row refs are documentary in the bold grammar). Row claims (`Spec-027 rows 4 + 10`, `row 7a`; digit-led ids, `+`/`/`/`,` lists — prose "rows" never tokenizes) verify against the bound spec's markdown-table first-column ids (round 7). Sweep findings are DEDUPED against the primary pass via coverage sets — a claim the grammar parsed is never re-reported, and §/AC/line tokens under a spec whose label already failed are folded into that one doc-missing finding — and residue § tokens share the same salvage/tail classification, so both layers agree on what a tail is. Every salvage-dropped tail — primary or residue — is itself re-scanned by the sweep before it is classified as formatting debt (round 8), so a checkable claim can never hide in dropped words. The sweep is existence-level by design; full fidelity (subjects, hints, ranges under sections) is the primary pass's job, because unparseable text cannot express those couplings. `[inline-anchor-not-found]`, `[inline-doc-missing]`, and `[inline-cite-violation]` **always gate** (never in `LEGACY_INLINE_EXEMPT_KINDS`); the floor is fail-closed (its own thrown error surfaces as `[cite-check-threw]`) and runs on every phase, exempt or not.

**Exit contract.** Plain `--survey` prints `citeAnomalies` loudly but keeps exit `0` (the two-sided `anomalies` alone gate it — including the `[survey-uncovered]` rows the coverage line describes, which is why an unsurveyable plan blocks in both modes), so an author running the survey locally is never blocked by cite findings. `--survey --enforce-cites` folds `citeAnomalies` into the nonzero exit; this is the mode the `docs-corpus.yml` CI step runs, so a new or edited plan carrying a malformed Gate-4 cite fails the gate (real-corpus armed guard in `preflight-survey.test.mjs`). Mixed invocations (`--survey` with a plan file, phase, or any other flag) exit `2`; `--enforce-cites` is the sole flag `--survey` accepts. The dispatch gate itself (`gateTasksBlockCites` on the selected phase during a real preflight) is unchanged — this screen is survey-only. (Invariant-reference resolution is NOT: it runs on both paths — see Gate 4 §Invariant-reference resolution.)

**Deliberately stricter than dispatch (Codex P2, PR #214 round 3).** The survey consumes `gateTasksBlockCites`'s `findings` array, which always carries the full parse+verify set — the Size-Classed Ceremony demotions (grammar kinds → warnings for S/M phases) affect only the dispatch halt/warnings routing, never `findings`. The armed CI gate is therefore stricter than dispatch for S/M phases **by design**: merge time is where grammar debt is cheapest to fix and where letting it land would re-accumulate the corpus debt the gate holds at zero, while dispatch keeps its S/M demotions so execution is never blocked on a nit that predates the policy. The asymmetry runs one way only — everything that lands is dispatchable; a shape dispatch merely warns on does not land anew.

**Legacy-inline exemption.** Two compact-inline plans encode each task's cites on one bullet line (`- **T-…** (…; Verifies invariant: …; Spec coverage: …) — prose`), a shape `extractCiteAnchors` cannot parse — bolding in place runs the marker payload to end-of-line through the task prose. Until each is re-authored into the expanded one-marker-per-line form, `LEGACY_INLINE_CITE_EXEMPT` (in `preflight.mjs`) diverts their **legacy-formatting** anomalies — the `LEGACY_INLINE_EXEMPT_KINDS` classes, `[legacy-unbold-marker]` + `[legacy-markers-partial]` + `[legacy-inline-descriptor-tail]` — to a separate `exemptCiteAnomalies` channel: PRINTED every run under a `cite-exempt (legacy-inline, …)` group (visible debt, never a silent skip) but never folded into the `--enforce-cites` exit. The divert is **kind-scoped**: verifier findings on parsed cites (`[section-not-found]`, `[unparseable-cite]`) and hard failures (`[cite-check-threw]`) always gate, exempt path or not — the exemption hides legacy formatting debt, never a broken or unverifiable Spec anchor (Codex P1, PR #214; the fixture-tested gating control lives beside the divert control in `preflight-survey.test.mjs`). Every divertable kind carries its legacy proof in the kind itself: `[legacy-markers-partial]` exists only for partial phases with zero bold markers, so a half-finished new-grammar restructure of an exempt plan emits the always-gating `[markers-partial]` instead of shipping silently (Codex P2, PR #214 round 2), and `[legacy-inline-descriptor-tail]` exists only for an anchor whose heading RESOLVED — the divertable residue is the trailing words, never the anchor (Codex P2, round 5). And the divert hides only formatting, not the anchors inside it: the inline anchor-existence floor (`[inline-anchor-not-found]` / `[inline-doc-missing]` / `[inline-cite-violation]` above) verifies every anchor an inline payload parses to, existence-checks the claims in text it cannot parse — including salvage-dropped descriptor tails — and gates the parse-time defect classes the grammar itself detects, so editing an exempt plan's inline cite to a phantom document, section, line, AC, table row, or a denied cross-namespace line cite fails the armed survey even though the formatting classes still divert (Codex P2, PR #214 rounds 3-8). The list itself is the tracking — no backlog item. Removal owner per file:

- `008-control-plane-relay-and-session-join.md` — its Tier-5-remainder readiness audit.
- `023-desktop-shell-and-renderer.md` — its Tier-8 readiness audit.

`007-local-ipc-and-daemon-control.md` and `025-self-hostable-node-relay.md` were re-authored into the expanded bold form and their entries removed from the code constant; this prose lagged behind that removal and named four plans until 2026-07-27. **The code constant is authoritative** — the real-corpus guard asserts `survey.exemptFiles.length === LEGACY_INLINE_CITE_EXEMPT.length`, i.e. output against the constant, so drift between this paragraph and the list is structurally invisible to it. One consequence used to reverse the intuition: re-authoring a plan out of the inline shape moved its cites from the inline floor's reach (which spans a whole survey unit) into Gate 4's then-phase-section-only scope, so a marker sitting outside a `### Phase N` section went from visible-but-diverted debt to not screened at all. Plan-025 was exactly that case. **The complement screen closes it** — Gate 4's scope is now the phase sections plus their complement, which together partition the plan, so re-authoring no longer moves any marker out of reach. See §Survey mode, intra-plan coverage.

**Stale-exemption ratchet.** An exempt plan present in the corpus that emits zero anomalies of the DIVERTED classes has been re-authored out of the legacy shape (any remaining verifier findings gate on their own), so the survey pushes a gated `[stale-exemption]` finding — the exemption then fails `--enforce-cites` until its `LEGACY_INLINE_CITE_EXEMPT` entry is deleted. Re-authoring a plan and removing its entry are forced to land together; a fixture-named clean plan at an exempt path proves it (`preflight-survey.test.mjs`). A path that no longer resolves to a plan file is caught by the real-corpus guard, which pins `exemptFiles.length` to the list length.
